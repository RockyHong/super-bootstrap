## Design — 2026-08-03 · settled with user — phase-drainability + scoped-brief session

Lore-audited (canon + Tier 1) before settling; `dispatch-brief-shape`'s wide-author stall applies to single-turn subagents, not full `claude -p` sessions — the brief below is anchor + breadcrumb, never payload.

1. **Drainable is a phase attribute, not a ticket attribute.** Every phase on an item's chain classifies `drainable | wall(user) | wall(shape)`. User walls: design settling / taste, user smoke, real external cost, harness surface. Shape walls: device-bound runners, capabilities unverified (GAP-052). Venue map's "modality fields govern only the phase they gate" becomes the base-layer rule, not a scale-module extra.
2. **Admission = next phase drainable; run = drain-till-wall.** An item enters when its next phase is drainable — no whole-chain projection. The subprocess runs phase-to-phase until the first wall, halts with the wall's type. Front-walled items (Discuss) enter later when the wall resolves and thread state changes; tail-walled items drain their front and halt before the wall.
3. **Machine reduces to scoped-brief sessions.** One `claude -p` session per item consumes one scoped brief — anchor (problem-aim) + breadcrumb (card thread path, verdict, boundary + halt conditions) rendered from card files (cold-restart re-renders). The per-phase command dispatch dissolves; the worktree session runs the envelope itself. Hard condition kept from `pipeline-design`: artifacts land as blocks/commits before the next segment — state = file presence; `.drain-status` moves to milestone grain.
4. **Thread law: cut by aim, not by phase.** Same aim → same thread, blocks append and take over the lead (reframe = Amendment/Verdict supersession). Changed aim (the problem itself superseded) → resolve the card with the counter-diagnosis, open a successor citing the predecessor ID. Per-concern card splitting stays out (adjacent to the closed satellite-files fork, decisions.md).
