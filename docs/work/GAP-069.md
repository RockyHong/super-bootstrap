# GAP-069 — doc-sync scan container unmeasured: cold dispatch vs warm gateway-inline

**Logged:** 2026-08-28 · **Source:** user observation, log session
**Problem:** The commit door's doc-sync scan dispatches the cold `doc-sync-scan` agent whenever the mechanical gate hits, and that container choice has never been read out against the warm-inline alternative. Inline is warm: the gateway already holds the diff, the change intent, and the docs it read this session, so it can walk the touched line's SSOT links straight to the affected docs at near-zero marginal cost — but it reads with authoring confidence and can miss surfaces it never opened. Dispatch pays a full cold restart per commit — the agent re-derives its whole picture from the prompt-supplied read-set, which is slow rework — and its claimed payoff is catching the unexpected, which is not the same claim as catching more accurately. No cost/recall evidence exists for either arm, so the dispatch default sits unearned.
**Area:** `plugins/super-bootstrap/skills/commit/SKILL.md` §3; `plugins/super-bootstrap/agents/doc-sync-scan.md`; `CLAUDE.md` § Doc Sync + § Dispatch
**Stochastic:** llm
**Blast:** repo
**Prior:** The cold-eyes rationale (an omitter cannot see its own omission) may be carrying credit that the mechanical enumeration actually earns; the untested middle is a hybrid — warm inline over link-reachable docs, dispatch reserved for gate hits outside the session's read-set.

## Amendment — 2026-08-28 · doc-links strip-list work, GH #57–#60 follow-on

First recall evidence on the cold arm, from two dispatches in one session against the same target line — [`docs/techstack.md`](../techstack.md#coding-patterns)'s fork-free-inner-loops entry — over successive revisions of one change:

- **Run A** judged the entry `clean` against a revision whose new helper forked once **per slug-table entry**, inside a loop reached from the per-item walk. Its stated reason: the entry's cost prose is about the success path, so the miss-path forks fall outside it.
- **Run B** judged the same entry `stale-docs` against the next revision, which added an early return that fires on any all-ASCII slug table — **strictly fewer forks**. Its stated reason: the entry's claim is literal and absolute, so any subprocess in a per-item loop contradicts it.

The verdicts invert against the direction of the change: the stricter reading landed on the less-violating code. Both runs were the same agent at the same tier over the same scope doc, differing only in the diff. The gateway resolved it by taking Run B and both changing the code and recording the residual exception — but that pick was the gateway's judgment, not something either return established.

Bearing on this card's question: the cold arm's failure mode here is not the missed surface the dispatch default is priced against — the doc was found both times. It is verdict variance on a found surface, which neither arm's stated tradeoff addresses, and which a recall metric counting surfaces-reached would score as two clean hits. Any read-out this card runs needs a verdict-stability axis, not only a coverage one.

Sample size is one line over two runs, and the diffs were not identical — a controlled repeat would hold the diff fixed and vary only the container.

### Decision needed

- **Warm-arm construction — how is gateway warmth produced?**
  - **(a) Prompt reconstruction, transcript-sourced** — arm prompt = the fixed diff + the change intent + the session-read doc list, lifted from the recorded dispatch context; scan runs inline in the arm's own top-level turn, no subagent.
  - **(b) Authoring replay** — the arm is given the change's intent, makes the edits itself, then runs the scan inline in the same context. Genuine authoring confidence; but the arm's authored diff will not be byte-identical to the fixture's, which trades away the card's own held constant.
  - recommendation: **(a)**. The Design block fixes the diff as the constant and already names prompt reconstruction; the session store makes the reconstruction observed rather than invented, which is stronger than the Design block assumed. Record the unmodeled component (authoring confidence) as a declared bound on the read-out rather than buying it with the constant. If (a) shows no separation, (b) becomes the escalation with its own protocol, not a substitute.
  - settles by: measurable proxy the gateway can run — score (a) against the cold arm first; separation ⇒ the axis is real without (b); null result ⇒ (b) is the only remaining discriminator and its diff-variance cost is then justified. Not settleable from static read in this lane.

- **Fixture allocation + N per arm.**
  - The two candidates are not interchangeable: `d3161f3` carries a recovered answer key and is the only one that can score the **coverage** axis; the techstack case has no independent key (Run A vs Run B is exactly the disputed verdict, settled by the gateway, not by either return) and can therefore score only the **stability** axis — same fixed diff, N repeats, agreement rate.
  - recommendation: `d3161f3` → coverage; techstack **record 2** (Run B's revision, the one whose verdict the gateway adopted) → stability, repeated N times against itself rather than run as the 1→2→3 sequence. N=3 per arm — every prior round in this repo used 3, keeping the new numbers comparable to the 1/15 and 3/3 figures already on record, at ~70–80k tokens per arm.
  - settles by: the operator's P-venue cost ceiling — 2 fixtures × 2 arms × 3 = 12 arms ≈ 0.8–1.0M subagent tokens, plus 3 more if the Opus control runs. Budget authority, not a code fact.

- **Does the Opus control arm run at all?**
  - decisions.md row 34 already priced Opus out for the per-commit door, so the arm buys a comparison baseline (is the warm-cold gap smaller or larger than the known tier gap?) and nothing shippable.
  - recommendation: **run it, on the coverage fixture only** — it is the cheapest way to give the warm/cold delta a scale, and row 34 stays closed because the arm is a control, not a proposal. Skip it if the cost ceiling above bites.
  - settles by: the same budget call; the doctrinal side is already settled by row 34 and needs no user input.
