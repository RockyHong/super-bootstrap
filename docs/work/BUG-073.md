# BUG-073 — README's triage description overstates tier floor and toolset

**Logged:** 2026-09-24 · **Source:** `/claude-api prompt-audit` model-pin notes over `plugins/super-bootstrap/**`; unverified at capture
**Problem:** `agents/triage.md` pins `model: inherit`; `triage/SKILL.md:3,9` and `plugins/super-bootstrap/README.md:14,68` gloss it as "the session owner's model is the top tier" — true only when the session runs the top tier. A Sonnet-session user gets a Sonnet triage, contradicting README:68's "top-tier floor … never a lower fixed alias". README:68 also calls triage's toolset read-only while frontmatter grants `Read, Grep, Glob, Bash, Edit` (Edit for the verdict append; the body polices read-only-ness).
**Area:** `plugins/super-bootstrap/README.md:14,68`, `plugins/super-bootstrap/skills/triage/SKILL.md:3,9`, `plugins/super-bootstrap/agents/triage.md`
**Prior:** Wording fix (state the inherit assumption plainly; describe the toolset as read-only-except-verdict-append) unless a real floor is wanted, which would be a pin decision.

## Amendment — 2026-09-24 · `bench/triage-grep-first` (12 Opus runs, both arms)
The body's Bash floor ("read-only: `git status/diff/log`, `ls`") is not observed behavior: 9/12 runs tried to append the verdict via a Bash `cat >> card <<EOF` heredoc (rejected by the harness parser, fell back to Edit), one run read files with `cat`/`sed`/`find`, one tried to run python (denied). Arm-independent — the README's "read-only toolset" and the body's Bash floor both overstate what the grant enforces.

## Verdict — surface · 2026-09-24

### Findings

- root cause — the card carries two claims; they ground differently:
  - **Tier half: falsified.** "Top tier" is a defined term, not a claim about Opus. `.claude/guidelines/work-discipline/model-tiering.md:21-26` defines it: `Top (inherit)` = "the model the session owner runs the gateway on and simultaneously the cap — no dispatch runs above it, the session model being the owner's own cost decision". So README:14, README:68 ("top-tier floor: the model the session owner runs, never a lower fixed alias"), `triage/SKILL.md:3,9`, and `docs/overview.md:58` all match that doctrine. When a Sonnet-session user gets a Sonnet triage, the floor and cap are working as defined, not contradicting README:68. "Never a lower fixed alias" rules out a sub-session pin such as `model: sonnet`. It does not promise Opus. The Prior's alternative, a real fixed floor such as `model: opus`, would break the cap the same doctrine sets. It is a closed direction, not an open pin decision.
  - **Toolset half: confirmed.** `agents/triage.md:4` grants `tools: Read, Grep, Glob, Bash, Edit`. README:68 says "read-only toolset + clean context enforce the phase identity", but the grant enforces nothing read-only. Edit is granted for the verdict append. Bash is granted with no pattern restriction. Read-only-ness is only prose in the body's floor (`agents/triage.md` § Phase identity: "Bash stays read-only (`git status/diff/log`, `ls`)").
  - **Amendment (Bash floor):** direct evidence is `bench/triage-grep-first/FINDINGS.md:85-90`. That bench allow-listed Bash to `git status/diff/log` + `ls` (`bench/triage-grep-first/README.md` § Protocol), so the rejections came from the bench harness. In production nothing enforces the floor. Most observed breaches stayed inside the phase's intent: `cat`/`sed`/`find` reads are read-only, and the `cat >> card <<EOF` heredocs target the one allowed write. Only the python attempt went beyond it. The prose floor is a literal command list that the model does not follow, and the grant does not back it. Unverified hypothesis on the heredoc habit: this dispatch's own runtime context carries an auto-mode reminder saying subagents may "make small, mechanical file changes with sed, heredocs". If the bench runs carried the same reminder, that would explain the 9/12 heredoc rate. Not checked against the bench transcripts.
- scope reach: wording half is `plugins/super-bootstrap/README.md:68` only. README:14 and `triage/SKILL.md:3,9` say "read-only grounding phase", a phase-identity claim that stays accurate. The tier text needs no edit. `docs/overview.md:58` was read and confirmed unchanged. The Bash-floor half would change `plugins/super-bootstrap/agents/triage.md` § Phase identity (an ambient-loaded shipped agent body, cluster 7) and possibly `plugins/super-bootstrap/hooks/hooks.json` if enforced mechanically. Provenance: every touched path is this repo's own plugin source, not a served copy.

### Decision needed

- Does the Bash-floor half (from the amendment) ride this card, or split into its own card?
  - A: **Split.** This card lands the wording fix only (mechanical, docs, no test surface). README:68's "read-only toolset" becomes something like "read-only phase, policed by the body. The grant is `Read, Grep, Glob, Bash, Edit`, with Edit for the verdict append". The tier text stays as it is. The Bash-floor gap goes to a new DEBT card through `/super-bootstrap:log`: prompt or enforcement for `agents/triage.md` § Phase identity.
  - B: **Widen.** This card also takes the Bash floor. It becomes cluster 7, prompt-shape work that needs a behavior probe first. Options there: restate the floor as an intent rule ("no writes except the verdict append; Edit is the append tool") instead of a command list; or enforce it with a triage-scoped PreToolUse Bash gate. Whether a subagent `tools:` field can pattern-restrict Bash is unverified and needs a docs lookup.
  - C: **Wording only, drop the Bash half.** Treat the observed breaches as harmless, because the reads and append stay inside the phase intent, and record that in `docs/decisions.md` as a closed direction.
- recommendation: A. The card's own aim, README overstating the toolset, is auto-fix-grade now. The Bash floor is a different fix-shape (`prompt`) whose shape depends on a probe. Holding a one-line docs fix behind a bench build conflates two change units.
