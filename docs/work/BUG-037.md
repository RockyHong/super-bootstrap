### Root cause (verified)

Not two different classification passes — one classified set, two different **filters**, plus a disclosure line scoped to the wrong modes.

`plugins/super-bootstrap/skills/todo/assets/render-board.py:444-447` —

```python
body_rows = [r for r in rows if not r.hard_blocked]
counts = {k: sum(1 for r in rows if r.intent == k) for k in ("Discuss", "Cloud", "Device", "Harness")}
total = sum(counts.values())
```

`counts`/`total` (the macro header, emitted at `:513`) run over **`rows`** — hard-blocked included. The sub-verb table at `:511` runs over **`body_rows`** — hard-blocked excluded (`kept = sort_rows([r for r in body_rows if r.intent == intent], …)`). Every hard-blocked row of the current intent therefore inflates the header by 1 against the table. `hard_blocked` is set in `couple()` (`:376-382`) on an explicit `blocked by|depends on|after {ID}` naming a still-open card — reachable for `Discuss` rows (a `Decide` / `Approve design` card that names a prerequisite).

The script is a faithful encoding, not a slip — the spec mandates the same divergence, so **both lanes carry it**:

- `plugins/super-bootstrap/agents/todo.md:157-159` (§5 Cross-mode counts) — counts come from §1, i.e. all rows classified *before* §2 filtering and before the §4 coupling gate.
- `agents/todo.md:127` (§4) — hard-blocked rows are "held out of the board body; it surfaces only in the footer `pending unblock` count."
- `agents/todo.md:184` — "**Pending-unblock line** (Full mode only)". Sub-verb boards get no such line, so nothing on a `discuss` board reconciles header to rows.
- `skills/todo/assets/scaffolds.md:5` + the four sub-verb scaffolds (`:85`, `:124`, `:163`, `:202`, empty-state `:105/144/183/232`) carry the macro line and **no** `pending unblock` slot; only the needme (`:56`) and full (`:272`) scaffolds have it.

Self-contradiction inside the same agent doc pins which side is wrong: `agents/todo.md:207` (Rules) states globally that "every open card and test-queue entry is accounted for — runnable rows get a board row; hard-blocked rows surface as the footer `pending unblock` count." `:184` scopes that footer to Full mode alone. Sub-verb boards thus satisfy neither clause — the held row is neither a body row nor a disclosed count, which is exactly the silent under-report the card's origin block flags.

Fix shape (settled by the aim `header count == rendered row count on every board, in both lanes`, plus the two ratified clauses above): scope the four macro counts and `Full T` to `body_rows`, and extend the `pending unblock: {n}` footer to the sub-verb modes so held rows still surface.
