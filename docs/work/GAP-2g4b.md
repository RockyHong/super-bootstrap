# GAP-2g4b — session-close owns push policy; push timing belongs to the user's preference layer

**Logged:** 2026-10-29 · **Source:** user ruling after GAP-0asv shipped (`ea3e4b1`): "superbootstrap有多個consumer，有些user可能會希望agent自動push，但我本人希望session close push。所以不是把session-close當SSOT gate。應該是不管push這件事，由使用者的pref自己設定，而我這台裝置就是給CCM管"
**Problem:** GAP-0asv removed the per-commit push ask from the commit and merge doors but moved push into `session-close` as a detected move it runs itself (step 2 push move, step 4 push line + execution order `… merge → push → prune`). That still makes super-bootstrap the SSOT of when a push happens — it encodes one user's preference (push at session close) for every consumer. Push timing is a user preference: some consumers want the agent to push on its own, the author wants it at session close, and on the author's device that preference is owned by the claude-config-manager device layer (`~/.claude/CLAUDE.md` § Ask Threshold: "Ask whether to push only at session closeout …"). super-bootstrap should not decide or run push at all.
**Area:** `plugins/super-bootstrap/skills/session-close/SKILL.md` (description, step 2, step 4, Rules), `commit/SKILL.md` §6 handoff line ("push, card resolve, carry"), `merge/SKILL.md`, plugin `README.md`, `docs/overview.md`, `docs/test-queue.md`, `bench/commit-push`, `bench/merge-push`
**Prior:** drop the push move from session-close; no door asks or runs push; at most report the branch's ahead-of-upstream count as a tree-state fact in the close output, leaving the push decision to the user's own preference layer.
