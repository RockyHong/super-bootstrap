# GAP-101 — card IDs collide across devices and sessions that log before syncing

**Logged:** 2026-10-10 · **Source:** device note from magnetized-remake, 2026-10-08 (`20261008T190941Z-card-id-collision-across-devices.md`); incident: two devices both took `GAP-149`
**Problem:** `log` step 4 takes "max+1 from the README high-water line, bumped in the same change" — correct in one checkout, but across clones a distributed counter with no reservation. Two devices (or a cloud session beside a local one) logging from the same high-water take the same ID; nothing detects it until rebase (README high-water conflict, a commit message "Resolves GAP-149" naming a different card), and a card logged and resolved within one session never conflicts at all — only the duplicate ID in commit history shows it. The consumer recovered by hand: renumbered the never-pushed card, amended the commit message, merged the high-water line, rebased.
**Area:** `plugins/super-bootstrap/skills/log/SKILL.md` step 4; `plugins/super-bootstrap/skills/commit/SKILL.md` (push); `session-close` push move; `docs/work/README.md` high-water convention (skeleton + dogfood)
**Prior:** candidate directions from the note — (1) fetch-check at log time, max(local, upstream)+1 — narrows the window, does not close it; (2) commit-door pre-push collision check against upstream `docs/work/` + README, renumbering unpushed IDs; (3) collision-free IDs (device/session suffix or date-based) at the cost of readable sequence.

## Verdict — surface · 2026-10-10

### Findings

- premise age: clean. No commit touched the Area paths since 2026-10-08.
- root cause (gap confirmed): the ID allocator reads only the local checkout, and no step checks upstream. `plugins/super-bootstrap/skills/log/SKILL.md:30` (step 4) takes max+1 from the local README high-water line and does no fetch. The push steps run no ID check: `commit/SKILL.md:45` (§6), which `session-close` also reaches through its commit move (`session-close/SKILL.md:39,84`), and `merge/SKILL.md:107-114` (§8, a second push surface that the card's Area does not name). `docs/work/README.md:23` and `harness-bootstrap/assets/work-readme-skeleton.md:23` define the counter as local-only. No `docs/decisions.md` row closes this fork. No open card overlaps it: BUG-084 and BUG-085 are about other surfaces.
- detector weakness (sharpens the card's "never conflicts" claim): the README high-water line is not a reliable detector either. When both sides bump one category to the same value (both take only `GAP-149`), git merges the identical line change cleanly, and the collision is silent. The incident conflicted only because the other device took three IDs. A card that is deleted at resolve leaves no file to diff against, so a check against upstream `docs/work/` *files* (Prior direction 2 as worded) misses the logged-and-resolved case. A three-point comparison of the high-water line catches it: merge-base, upstream, and local, per category. If both (base, local] and (base, upstream] are non-empty, the ranges overlap and the local IDs collide. This uses only the line every log already bumps.
- family sweep: the same defect applies to `OUT-###` (`docs/outward/README.md:23`, `scale/outward-readme-skeleton.md:23`) and `PARK-###` (`docs/parked.md:9`, `scale/parked-skeleton.md:9`). Both use the same local max+1 high-water allocation. Seeded cards (`setup/SKILL.md:43`) and the high-water re-plant (`harness-bootstrap/SKILL.md:486`) also allocate from the same line. Any fix covers all four counters, or it states why one counter is out of scope.
- scope reach: the shipped skills `log`, `commit`, `merge`, and maybe `session-close`. The shipped skeletons `work-readme-skeleton.md`, `work-template-skeleton.md:1`, `scale/outward-readme-skeleton.md`, and `scale/parked-skeleton.md`, each with its dogfood mirror (`docs/work/README.md`, `docs/work/TEMPLATE.md`, `docs/outward/README.md`, `docs/parked.md`) under repo-boundary's prose lane. Direction 3 also reaches `harness-bootstrap/SKILL.md:169`'s high-water shape check, `check-docs-consistency/assets/tracker-annotation.md`, and the `{BUG,DEBT,GAP}-###` pattern narrated in `CLAUDE.md:166` and `claude-md-skeleton.md:159`. All the shipped-skill edits shape behavior, so `skill-authoring` requires a RED first.
- attempted: static read of every allocation site and push surface. I stopped at the direction choice, because the directions trade off things that this lane cannot settle.

### Decision needed

- Which mechanism closes cross-clone ID collision for every high-water counter (BUG/DEBT/GAP, OUT, PARK)?
- (A) Detect at push and renumber: before the push in commit §6 and merge §8, fetch, then compare the high-water line at merge-base, upstream, and local, per category. Overlap → stop and surface a renumber of the local range above upstream's line, and on confirm rewrite the unpushed commits (card files, cross-references, commit messages). This closes the window for every unpushed ID, including logged-and-resolved cards. Cost: one fetch per push, and a history rewrite of unpushed commits, which the commit door currently allows only on request ("amend only if asked").
- (B) Narrow at log time only: `git fetch` in log step 4, and take max(local, upstream)+1. This is cheap and touches only the log skill, but a race window remains between log and push, so it cannot close the gap alone.
- (C) Make IDs collision-free by construction: add a device or session suffix, or use date-based IDs. This removes allocation coordination but loses the readable sequence. The ID pattern changes in every consumer repo, together with the shape checks and greps that key on `{BUG,DEBT,GAP}-###`.
- recommendation: (A), with (B) as an optional cheap first layer. (A) is the only option that closes the window and keeps the ID convention. The three-point high-water comparison is mechanical and also catches the deleted-card case. The rewrite stays safe for the reason the card states: the IDs have never left the clone.
- settles by: user preference/risk on two points: (1) the readable sequence against a collision-free scheme (A/B vs C), and (2) whether the push door may propose a history rewrite of unpushed commits behind a confirm. If (A) is chosen, the detector's coverage of the incident shapes (identical single bump, a 1-vs-3 bump, logged-and-resolved within one session) is checked by a `dispatched probe` on a two-clone fixture repo. The skill wording then needs its `skill-authoring` RED.

## Design — 2026-10-10

User ruling: **C — collision-free IDs by construction.** Readable max+1 sequence is given up; no reservation, fetch, or push-time renumber machinery. ## Progress — 2026-10-10

Parked on user direction: the ID-scheme design runs next session, starting from the gateway proposal below (a proposal, not a settled Design — open it with the user).

**Gateway proposal (C, concrete):**
- **Shape:** category prefix + 4-char random base36 suffix — `BUG-k7f3`, `GAP-x2m9`, `OUT-…`, `PARK-…`. No coordination, short enough to type and grep; 36^4 ≈ 1.7M per category, collision negligible at solo-repo volume.
- **Local guard, not a counter:** at assignment `log` regenerates on a hit against live card files + `git log --grep=<ID>` (covers resolved/deleted cards). Cross-clone collision stays possible only at random-draw odds — that is the trade C accepts.
- **High-water lines retire** from `docs/work/README.md`, `docs/parked.md`, `docs/outward/README.md` (skeletons + dogfood): no counter, nothing to bump, nothing to conflict on rebase.
- **Migration:** existing numeric IDs stay valid forever (history greps keep working); the ID pattern becomes `{CAT}-(\d{3}|[a-z0-9]{4})`. No renaming of live cards. `harness-bootstrap` sync drops the high-water line on re-run.
- **Chronology:** given up in the ID; the origin block's `Logged:` date and `git log` carry order.
- **Alternatives to weigh next session:** date-based (`GAP-261010a` — sortable, but still collides same-day across devices without a suffix); device-scoped suffix (`GAP-149a` — needs a per-device letter registry, the coordination C is meant to avoid).
- **Reach to sweep:** every reader/writer of ID patterns or high-water lines — `log`, `setup` seeding, `harness-bootstrap` (re-plant `:169`, sync), `check-docs-consistency/assets/tracker-annotation.md`, `needs-me`, `autorun`, `session-close`, `CLAUDE.md:166`, `claude-md-skeleton.md:159`, the four container skeletons + dogfood mirrors.
