# DEBT-065 — shipped skeleton (and dogfood CLAUDE.md) carries a dispatch exception whose antecedent consumers cannot satisfy and this repo has never attested

**Logged:** 2026-08-12 · **Source:** GitHub issue [#40](https://github.com/RockyHong/super-bootstrap/issues/40) (RockyHong), pulled via `/pull-issue`
**Problem:** § Dispatch's "Writer run mode keys on path overlap" bullet ends with: "Narrow exception: under a paired `PreToolUse(Write)` context-injector hook, a backgrounded subagent's new-file Write can stall before writing (platform defect) — with such a hook wired, new-file writers dispatch foreground." The shipped skeleton and the dogfood `CLAUDE.md` both carry it. `harness-bootstrap` wires no `PreToolUse(Write)` hook, so a repo bootstrapped from this skeleton inherits an exception whose antecedent it has no way to satisfy unless its author separately writes such a hook — which the skeleton neither ships nor mentions. Cost is not zero: read literally, the exception tells every consumer to give up background dispatch on every file-creating writer, permanently, to defend a condition that never holds for them. The antecedent is also unattested — scanning this repo's session transcripts for the failure signature (a `Write` tool call with no tool result) returns nothing; the "Tool result missing due to internal error" string appears only on `Read` calls, a generic internal error rather than a Write-stall marker. Reporter's suggested direction: drop the sentence from both surfaces — the path-overlap criterion stands on its own and is the part the consumer can act on — and re-add only against an observed occurrence in a repo that actually wires such a hook. Verify: `jq -r '.hooks.PreToolUse[]? | .matcher' .claude/settings.json` shows no `Write` matcher; `grep -rl "PreToolUse" plugins/super-bootstrap/skills/harness-bootstrap/assets/` shows the skeleton ships no `Write`-matcher hook; scan `~/.claude/projects/<repo>/**/*.jsonl` for `Write` tool_use ids with no matching `tool_result`.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/claude-md-skeleton.md` § Dispatch (writer-run-mode bullet); root [`CLAUDE.md`](../../CLAUDE.md) § Dispatch (same sentence)
**Prior:** Confirmed by this session at capture — this repo's configured `PreToolUse` matchers are `Bash,Read,Workflow,Agent` (no `Write`), and shipped hook assets carry only the Bash-matcher commit-channel guard; [`docs/decisions.md`](../decisions.md) separately retired the `harness-grounding` `PreToolUse(Edit|Write)` hook as out of scope for consumer repos, so no bootstrapped repo receives one. Counter-argument left for triage: the clause is conditional, so an unwired consumer never triggers it.
