# GAP-063 — check-docs-consistency: add an index-row ↔ entry-file claim axis

**Logged:** 2026-08-21 · **Source:** GitHub issue [#47](https://github.com/RockyHong/super-bootstrap/issues/47) via `/pull-issue`
**Problem:** A doc-catalog shape the current P0–P3 axes miss: an `index.md` whose rows carry a *substantive summary* of each entry file rather than a bare "what exists" pointer. The row is the retrieval surface — a reader cut-tests the row's summary to decide whether to open the file — so a row that drifts from its entry stops the reader arriving, and nothing holds row against file. Two failure shapes, observed in a hand sweep of 51 rows across three such catalogs: (1) **Contradiction** (1 found) — a row instructed one procedure; the entry file's corresponding section states the opposite; the row dated from file creation and was never touched while the body was rewritten; a dedicated row-sync pass ran in between and missed it. (2) **Whole-section omission** (8 found) — a row summarizing everything except one of its file's named sections; several of those sections are cited *by name* from other docs, so the row was the one place a reader would learn the section exists. Omission outranked contradiction 8:1 and fails worse (a contradiction misleads a reader who arrived; an omission stops the reader arriving). Why an axis and not a cheap per-commit script — measured, not assumed: a deterministic version (row text vs entry file `##`/`###` headings, zero-overlap only, no threshold) caught 3 of 8 omissions and 0 of the contradiction (structural: a contradiction *names* the thing it contradicts, so coverage passes it), and needs a per-corpus exclusion list for rhetorical-role headings (`## The fact`, `## Boundary`, `## Failure modes` — without one it fired 32 times, 30 role labels). The cheap tier is worth keeping where the corpus is authored; the claim pass is the only tier reaching contradiction + most omissions, and its cost (one full read of catalog + entry files) is exactly this skill's cadence. **Not suggested:** any row-format convention making coverage machine-checkable — summary density is load-bearing for the cut-test; thinning rows to bare pointers trades this drift risk for a worse one.
**Area:** `plugins/super-bootstrap/skills/check-docs-consistency/SKILL.md` Step 2 (P0–P3 tables)
**Prior:** A P0/P1 pair in Step 2, gated on a catalog predicate (a doc whose rows each link one sibling file and carry prose beyond the link): P0 — a row asserts something its entry file states the negation of; P1 — a row omits a whole named section of its entry file. Detection is per-row, per-file (no whole-corpus load), so it fits the single-pass read and the workflow fan-out equally.
