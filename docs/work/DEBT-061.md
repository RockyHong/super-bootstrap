# DEBT-061 — `docs/decisions.md` contradicts its own append-only contract

**Logged:** 2026-08-10 · **Source:** a cold harness auditor cited the file's in-place annotations as license to edit an existing row; the finding was rejected on the header's wording
**Problem:** The scope header declares the file append-only — "entries are added, never edited to 'now'" — while three of its rows carry in-place `**Reopened + answered:**` prefixes that overturn the verdict the row originally recorded (the mattpocock core-pin row, the code-review-layer row, the todo macro-picker row). A reader holding the header reads those rows as violations; a reader holding the rows reads the header as advisory. This session's `audit-harness-edits` probe took the second reading — it argued the append-only constraint "is not absolute here" and proposed editing an existing row in place — and the finding was rejected on the header. The artifact teaches the opposite of what its own contract says, so the same misread recurs at every cold read.
**Area:** `docs/decisions.md` scope header; the three rows carrying `Reopened + answered` prefixes
**Prior:** One side gives — either the header names the reopen-annotation as a sanctioned in-place form and says where the line sits, or the annotated rows restate as new rows citing the ones they supersede.
