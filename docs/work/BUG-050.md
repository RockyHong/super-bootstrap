# BUG-050 — `doc-links.sh terms` emits pipeline-seeded skeleton stems, so the commit door's scope ceiling trips on path-mention noise

**Logged:** 2026-08-27 · **Source:** v2.42.2 pilot sync in `Games/Magnetized Remake`, its commit-door run (consumer report)
**Problem:** The pilot's sync commit (7 files; every content change in doc-sync prose) printed terms `overview` / `super-bootstrap-runway` / `techstack` / `worktree-settings.local`; `hits` returned 8 docs, plus 1 link-target = 9 > the ceiling of 8, so the ceiling surfaced. None of the 9 narrates doc-sync behavior — `docs/specs/ui-guidelines-mobile.md` and `docs/specs/original-c2-project-provenance.md` hit only because they mention `techstack.md` / `overview.md` in backticks as paths. The cold scan read all 9 and returned clean (45k tokens / 89s). `term_generic()` in [`doc-links.sh`](../../plugins/super-bootstrap/skills/commit/assets/doc-links.sh) exempts slot-names (skill / claude / readme / template / backlog / marketplace / plugin / gitignore / index / settings / run / main / test / tests / spec / config) but not the stems harness-bootstrap seeds into every repo and whose `CLAUDE.md` § Planning tells every doc to reference (overview, techstack, decisions, super-bootstrap-runway) — editing any of them near-certainly fans out repo-wide, so the ceiling fires on "touched a skeleton file" rather than on a real hub fan-out.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` `term_generic()` + `terms`; `plugins/super-bootstrap/skills/commit/SKILL.md` §3 scope ceiling
**Prior:** Pipeline-owned skeleton stems as their own class — count toward the ceiling but demand narrative context (not a bare path mention) before joining scan scope, or drop from `terms` outright; the grep lane itself stays (closed fork: [`docs/decisions.md`](../decisions.md) grep-vs-link error directions).
**Test-feel:** unit
**Blast:** local

## Verdict — surface · 2026-08-27

### Findings

- root cause: confirmed, and it is **two stacked mechanisms**, not one.
  1. `derive_term()` ([`doc-links.sh:433-450`](../../plugins/super-bootstrap/skills/commit/assets/doc-links.sh)) maps every non-exempt changed path to its basename stem, and `term_generic():424` exempts slot-names only. Replayed verbatim on the pilot's four paths: `terms docs/overview.md docs/techstack.md .claude/super-bootstrap-runway.json .claude/templates/worktree-settings.local.json` → `overview` / `super-bootstrap-runway` / `techstack` / `worktree-settings.local`. Two of those stems name **machine artifacts with no narrative subject at all** (a coverage receipt, a settings template); `path_exempt():395-416` covers bench/tests/fixtures/ledgers/binary assets but not `.claude/**` state files.
  2. `do_hits()`'s `pathin($0, term)` (`:500-515`) matches the stem in **any** path shape on the raw line — so a markdown link target `](../techstack.md)` and a backticked path `` `docs/techstack.md` `` both hit. The repo's own `ssot-doc-link` rule mandates exactly those mentions surface-wide, so for a hub stem the grep lane saturates: measured here, `hits overview techstack super-bootstrap-runway worktree-settings.local` → 9 of a 17-file doc surface (53%). Per-file cause matches the pilot's report — `docs/agents/triage-labels.md:19` hits on `](../overview.md#data-flow)` alone, `docs/specs/mattpocock-coexistence.md:5` on `](../techstack.md#key-dependencies)` alone.
- **the grep lane is near-fully redundant with the citer lane for a changed *doc* path** — the sharpest form of the defect. `refs docs/overview.md` ∪ `refs docs/techstack.md` = `README.md`, `docs/agents/domain.md`, `docs/agents/triage-labels.md`, `docs/specs/harness-architecture.md`, `docs/specs/mattpocock-coexistence.md` (+ the two changed files). The grep lane returns that same set plus exactly one grep-only file (`plugins/super-bootstrap/README.md:79`, which names the paths in backticks without linking them). So 5 of 6 grep hits were already citers — and the grep lane arrives **unanchored**, discarding the narrowing `anchors`→`refs <path>#<slug>` exists to provide. The ceiling is fed mostly by a wider restatement of a lane already counted.
- scope reach: `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` (`path_exempt` / `term_generic` / `derive_term` / `do_hits`), `plugins/super-bootstrap/skills/commit/SKILL.md` §3 (terms-line + scope-ceiling prose), goldens `bench/doc-links/run.sh` + `bench/doc-links/expected/terms-*.txt` / `hits-*.txt`, construct lock `tests/doc-links.test.sh`. All this repo's own artifacts — no imported copy, no `/contribute` route. Consumers pick the fix up through the plugin release + harness sync.
- adjacent defect found, **not** part of this card's claim: `do_hits()` filters only `is_history_doc`, so `docs/work/**` card threads join the scan scope as hit files (`docs/work/BUG-050.md` appears in every hit run above), while `do_terms` exempts them via `path_exempt`. SKILL.md §3's frozen-provenance rationale ("card threads are self-contained") applies to both sides but is implemented on the changed-path side only. Log separately.
- attempted: replayed `terms`/`hits`/`refs` against the live repo surface for each of the four stems and per-file attribution; read `doc-links.sh` whole, SKILL.md §3/§3b/§4, the `decisions.md` grep-vs-link row, the harness-bootstrap seeding lines for both `.claude/**` artifacts. Probed one candidate match-shape rule empirically (below). Stopped at the design fork — no probes table in [`docs/techstack.md`](../techstack.md), so nothing else to fire.

### Decision needed

- **Which lane carries the cut — `terms` (path class), `hits` (match shape), or the §3 ceiling (counting rule)?** Every option below moves the grep lane's false-positive end, which is the end [`docs/decisions.md`](../decisions.md) row 41 deliberately keeps loose; the row forbids *replacing* grep with link-lookup and none of these do, but the size of the narrowing is a user call.
  - **(A) `terms` — machine-artifact class.** Extend `path_exempt` to non-narrative `.claude/**` state (`super-bootstrap-runway.json`, `templates/worktree-settings.local.json`). Coverage loss ≈ 0 (these files have no narrative subject), but it cuts only 2 of the pilot's 4 stems — measured here those two contribute 2 hits against `overview`+`techstack`'s 8, so the ceiling still trips. Insufficient alone.
  - **(B) `terms` — drop hub stems outright.** Harness-seeded SSOT stems (`overview`, `techstack`, `decisions`, `super-bootstrap-runway`, `worktree-settings.local`) yield no term. Kills the noise entirely; the changed-hub-doc case then rides the citer lane only, which covers 5 of the 6 measured hits but drops the grep-only residue (`plugins/super-bootstrap/README.md` — a doc that names the seeded paths without linking them). That residue is exactly the false-positive-leaning coverage row 41 protects.
  - **(C) `hits` — bare-token match shape for the class.** Keep every stem in `terms`; for the seeded/hub class require a bare-token mention (`` `techstack` ``) and reject path forms (`docs/techstack.md`, `](../techstack.md)`). Measured proxy on this surface: 9 hits → 2 (`docs/specs/harness-architecture.md`, which genuinely narrates the seeded artifacts by name, survives; the pure path-citers drop). Stems stay counted, so a genuine hub fan-out still fires the ceiling. Cost: a doc narrating the hub doc *only* through a linked path mention (`docs/agents/domain.md:10-12`) leaves the grep lane — but it is a citer, so the anchored citer lane still reaches it whenever the hub doc itself changed.
  - **(D) ceiling only.** Leave both lanes, retune §3's number or its counting rule. Evidence against: the scan scope is already a union (citers ∪ hits ∪ targets), so a de-duplication rule changes nothing — only raising the number would, and that disarms the protection for every commit rather than for this noise class.
  - recommendation: **(C), with (A) riding along on independent grounds.** (C) is the only option that removes "cited its path" from the hit set while keeping "talked about the artifact", so the ceiling goes back to measuring real fan-out instead of skeleton-file contact; (A) is not a competing lane choice but a missing `path_exempt` row — a `.json` receipt narrates nothing under any match shape. Reject (B): its coverage loss lands precisely on the non-linking mention the closed fork keeps grep around for.
- **Second question the pick opens — who defines class membership?** A hardcoded stem list beside `term_generic()` (drifts from the seeded set silently) vs derived from the harness-bootstrap asset inventory (`skills/harness-bootstrap/SKILL.md` §2c placement rows). Recommendation: hardcoded list with a comment naming the seeding SSOT — the asset inventory is prose, not machine-readable, and the seeded set changes at release cadence, not per commit.
