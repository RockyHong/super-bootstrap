# BUG-057 — triage `surface` verdict's `settles by:` names the gateway as executor with no sizing; framing + route gate fires only at pickup

**Logged:** 2026-09-05 · **Source:** GitHub issue [#64](https://github.com/RockyHong/super-bootstrap/issues/64) (RockyHong, via `/send-issue`); evidence session `3bb16f14`, bench arm dropped unshipped per `d323cb3`
**Problem:** A `surface` verdict's `settles by:` line can name an instrument and hand it to the gateway with no container or size — e.g. *"the RED itself — a no-guidance control run … Gateway-runnable; this read-only lane cannot dispatch it."* The gateway then executes it literally in the main thread: fixture trees, a CLI shim, smoke scripts, nested `claude -p` runs — a multi-file build carried inline, turn by turn, with no card, no plan block, no dispatch, until the user aborted. "Gateway orchestrates; it does not build" was present in three layers (one verbatim in `CLAUDE.md` § Dispatch) and did not fire. Two surfaces produced the miss: (1) `agents/triage.md`'s `surface` template — `settles by:` names *what* settles the fork and *who*, never *in what container or at what size*; the sibling `auto-fix` verdict already carries an explicit `Execution:` axis (inline / phased / full), the `surface` instrument has no equivalent, so "gateway-runnable" reads as "gateway runs it inline". (2) `claude-md-skeleton.md` § Framing + Route — state, don't gate is scoped "before routing"; when an absorbed verdict changes the route mid-flight (from "settle a carrier fork" to "build a headless A/B bench"), nothing asks for the aim to be restated or the new route sized — the user's mid-build interrupt asking for a self-coherent problem statement is the direct evidence.
**Area:** `plugins/super-bootstrap/agents/triage.md` (`surface` verdict template, `settles by:`); `plugins/super-bootstrap/skills/harness-bootstrap/assets/claude-md-skeleton.md` § Framing + Route; dogfood mirror root `CLAUDE.md` § Framing + Route
**Prior:** (a) `settles by:` gains executor + container + size, the same shape the `auto-fix` verdict's `Execution:` axis fixes (inline read / dispatched probe / phased build), never a bare "gateway-runnable"; (b) § Framing + Route gains one clause — the framing + route line re-fires whenever an absorbed verdict changes the route, not only at pickup. Verify: re-triage a card whose settle needs an experiment → `settles by:` names the container and the gateway's next move is a dispatch or plan block, not a main-thread fixture write; a mid-flight re-route is followed by a restated aim + route line before any build step.
**Test-feel:** `manual` · **Stochastic:** `llm`
