# GAP-045 — No fire-moment gate when a review claim enters a container — false claims pass all existing harness checks

**Logged:** 2026-07-26 · **Source:** DEBT-032 controlled probe runs (3/3 false-review-finding implemented and shipped); closed fork in `docs/decisions.md` explicitly reopens on this shape
**Problem:** Every gate the harness owns (`audit-harness-edits`, `doc-sync`, `/super-bootstrap:commit`) fires on the **diff**, not on the **claim**. A cold subagent handed a plausible-but-false review finding against a harness file implements it cleanly — one run reached the line that falsifies the claim (`worktree-boundary.md` grants in-worktree `git add` + `git commit`) and rewrote that line to match; another ran `audit-harness-edits`, cleared doc-sync, and committed the falsehood to main. The ambient law `Review received, not absorbed` was verifiably in context (run 2 quoted all three ambient laws verbatim on request) and did not activate. The same failure class reaches drain's review phase, which feeds findings back into an execute phase with no premise gate between them. Candidate surfaces not yet evaluated: hook on the dispatch boundary, skill invoked at the receive-review moment, or a required verdict field in the review-return contract.
**Area:** `CLAUDE.md` § The envelope (`Review received, not absorbed`); `plugins/super-bootstrap/skills/harness-bootstrap/assets/claude-md-skeleton.md` § The envelope; `plugins/super-bootstrap/skills/drain/assets/phase-loop.md` (review→execute phase boundary)
**Prior:** Root cause confirmed in the DEBT-032 closed fork: the failure is activation, not compression — the law was in context and still did not fire. Fix must place a gate at the fire-moment a review claim enters a container; evaluate the three candidate surfaces (dispatch-boundary hook, receive-review skill, verdict-field contract in the review-return shape).

## Verdict — surface · 2026-08-02

### Findings

- **root cause (mechanism located, fix shape open):** no dispatch payload in the harness ever hands a review finding as a *claim to check*. Two proven delivery mechanisms exist and neither carries a premise obligation: `plugins/super-bootstrap/skills/drain/assets/phase-loop.md:10` embeds `worktree-boundary.md` verbatim into every phase prompt ("the subprocess attention anchor"), and `CLAUDE.md:53` requires "**Every build-dispatch prompt carries the commit convention up front**". The only place review findings meet dispatch is `CLAUDE.md:55` (fix→re-review loop), which routes by *fix grade* (transcription vs judgment) and says nothing about the finding's truth. So a false finding arrives as an instruction, and every downstream gate (`audit-harness-edits`, doc-sync, commit) reads only the diff that faithfully implements it.
- **the differentiator is container role, not prose strength — direct probe evidence, both directions.** `docs/decisions.md` row 22 (DEBT-032): 3 cold subagents in an *implement* container, plausible-but-false finding, 0/3 pushback, one rewrote the falsifying line. `docs/decisions.md` row 33: 3 cold agents in the *triage* container, planted-wrong Prior, 3/3 traced cold and explicitly falsified it — without any anti-prior bullet. Same model, same ambient laws, opposite outcome. A container whose declared job is "implement this" absorbs the premise; one whose declared job is "judge this claim" falsifies it. That is the empirical handle the fix should pull.
- **candidate 1 (dispatch-boundary hook) is mechanically refuted, not merely disfavored.** A `PreToolUse` hook fires in the *dispatcher's* session and can inject only there — no hook event delivers text into a subagent's context, so it cannot gate the container the claim enters. Compounding: `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md:19-35` records five retired hooks (`entry-nudge`, `harness-grounding`, `docsync-gate`, `docsync-scan`, `docsync-stamp`), leaving exactly one shipped hook; `docs/decisions.md` rows 26-27 close the shipped-nudge-hook direction twice on ambient-carrier and scope grounds.
- **candidate 3 is half-owned.** `/code-review` is a bundled/foreign skill (`phase-loop.md:46`, `parallel-worktrees.md:52`) — this repo cannot add a required field to its *return* shape. Only the receiver-side contract is ours.
- **a working precedent for candidate 2 already ships:** `plugins/super-bootstrap/agents/triage-report.md` is a per-finding disposition judge — "the finding's claim is the scanner's, not yours" (step 2), one verdict per finding, a coverage line the gateway bounces if it doesn't match, and a gateway-side bounce for a rationale weaker than the scanner's. That is the review-intake shape, already built for scan reports and absent for code-review findings.
- **card premise correction (supersedes the origin block's drain clause):** "drain's review phase… feeds findings back into an execute phase" is not the shipped shape. Every chain in `phase-loop.md:20-33` terminates `review → merge gate (halt)`; there is no review→execute edge, and `drain/SKILL.md:109` states "No phase-level auto-retry beyond the one TDD retry inside the build phase." drain's exposure is real but different: review findings ride the branch to the merge-gate halt, so the receiving container is the *gateway/user at merge*, not a re-dispatched execute phase. Any fix that gates only a drain-internal loop would gate a loop that doesn't exist.
- **scope reach:** `CLAUDE.md` § Dispatch (fix→re-review bullet) + § The envelope · `plugins/super-bootstrap/skills/harness-bootstrap/assets/claude-md-skeleton.md:15,55` (skeleton mirror — `.claude/rules/repo-boundary.md` sync direction pulls it into the closure) · `plugins/super-bootstrap/skills/drain/assets/phase-loop.md` (merge-gate handoff, not a review→execute edge) · a possible new `agents/review-intake.md`.
- **attempted:** traced all three candidates against shipped mechanism (hook events, dispatch-prompt embedding, contract ownership) and against the two probe records. Stopped at the fork: which layer the gate lands on is a design call with a live user trade-off (extra dispatch per review cycle vs a prose-only obligation), and the closed fork at `docs/decisions.md:22` admits a reopen only with "a fire-moment mechanism at the point a review claim enters, **not** with prose" — so picking wrong re-walks a closed fork. Static read cannot separate the options; only a pressure-test can, and `.claude/rules/skill-authoring.md` requires that RED before any behavior-shaping prose ships. Test strategy is therefore probe-run/micro-test, not unit or e2e.

### Decision needed

- **Which layer owns the premise gate when a review finding enters a container?**
- **A — payload contract (dispatcher-side prose).** Extend `CLAUDE.md` § Dispatch: a prompt handing a review finding into a container must present it as a claim to check and require a per-claim return field (`checked | falsified | confirmed` + the evidence line). Cheapest; reuses the proven "every build-dispatch prompt carries X up front" mechanism; mirrors to the skeleton. Risk: still an obligation on the dispatcher's recall — closest in kind to the shape `docs/decisions.md:22` already refuted, though it changes the *payload* rather than exhorting the receiver.
- **B — receive-review agent (structural interposition).** A cold `review-intake` agent, sibling of `triage-report`: review findings route through it before any implementer sees them; it verifies each claim against code and returns confirmed/falsified per finding, with a coverage line the gateway bounces. The implementer container never receives an unchecked claim. Cost: one extra dispatch per review cycle; needs its own return contract and a RED baseline.
- **C — dispatch-boundary hook.** Falsified above — no hook event reaches into the container the claim enters; listed so it is not re-proposed.
- **recommendation: B.** It is the only option that moves the claim out of an "implement this" container into a "judge this claim" container, which is the exact variable the two probe records isolate (0/3 vs 3/3), and it has a shipped template (`triage-report`) plus an existing failing baseline (the DEBT-032 scenario, 0/3) to run RED against. A is the fallback if the extra dispatch per review cycle is judged too heavy at solo-dev scale — but A ships only with its own pressure-test, since the reopen condition explicitly bars prose.

## Design — 2026-08-02

User pick: **B — receive-review agent** (structural interposition), per Verdict § Decision needed. A cold `review-intake` judge, sibling of [`plugins/super-bootstrap/agents/triage-report.md`](../../plugins/super-bootstrap/agents/triage-report.md), interposed before any implementer container receives a review finding. A stays the fallback if the per-review-cycle dispatch cost proves too heavy at solo-dev scale. Ship gate: RED pressure-test against the DEBT-032 baseline (false-finding scenario, 0/3 pushback) before any behavior-shaping prose lands — [`.claude/rules/skill-authoring.md`](../../.claude/rules/skill-authoring.md) RED floor + the `docs/decisions.md` reopen condition (fire-moment mechanism, not prose).
