# GAP-073 — harness-bootstrap: § Coding Principles + `CODING_STANDARDS.md` scaffold unconditionally, even on a no-code repo

**Logged:** 2026-09-10 · **Source:** GitHub issue [#66](https://github.com/RockyHong/super-bootstrap/issues/66) via `/pull-issue`
**Problem:** On a docs-only repo — where Phase 1's "no manifests + no source files" detection already fires — harness-bootstrap still scaffolds `CLAUDE.md` § Coding Principles (an ambient line firing "before writing, reviewing, or refactoring code" in a repo that never writes code) and `CODING_STANDARDS.md` (four headings that stay empty for the life of the repo). Both are pipeline-owned, so every re-sync drift-checks them and the runway receipt lists them as covered — a slot in an always-loaded file with no decision it can sharpen there. Decide once at skeleton level rather than leaving every non-code consumer to carry the pair. Shape A — drop when no code: gate both on the same no-manifest-AND-no-source detection, treated like the existing tier conditionals (monorepo block, scale module) — section absent on a no-code repo, receipt `covered` omits them, a later re-run that finds a manifest raises both as `⊕ new`. Shape B — keep everywhere: state in the skeleton comment / SKILL.md that the empty pair is the intended "unsolved" state, so it reads as deliberate rather than as drift. Verify if dropped: (1) bootstrap a repo with only `docs/*.md` → no § Coding Principles, no root `CODING_STANDARDS.md`, receipt `covered` lists neither; (2) add a `package.json` and re-run → both surface as `⊕ new`, insert on approval; (3) existing code repos → sync output unchanged.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` (Phase 1 greenfield detection; "`CODING_STANDARDS.md` is **always** scaffolded" + asset table row); `plugins/super-bootstrap/skills/harness-bootstrap/assets/claude-md-skeleton.md` § Coding Principles; `plugins/super-bootstrap/skills/harness-bootstrap/assets/coding-standards-skeleton.md`
**Prior:** The pair is scaffolded on an "always" rule that predates the greenfield detection; the detection that already gates `overview.md` / `techstack.md` fill is the natural gate for both.
**Test-feel:** manual · **Blast:** pkg

## Design — 2026-09-10

Shape A — drop the code-touch pair when no code is present. Grounds: the ambient line fails the cut test on a repo that never writes code (harness-md-discipline); the tier-conditional mechanism already exists (monorepo block, scale module) so the walk skips a non-applicable section and the receipt's `covered` omits it; the "empty skeleton is intentional" precedent (overview/techstack) does not transfer — those empties are a signal `/super-bootstrap` reads, an empty `CODING_STANDARDS.md` has no reader. The issue's optional "keep everywhere, document as deliberate" shape is closed by the same cut test. Detection reuses Phase 1's "no manifest + no source file" (scripts count as source — this repo stays a code repo). No removal path for a pair an earlier bootstrap already placed on a docs-only repo (spec § Migration table: dropped sections orphan); stated in Phase 1 § Code presence.
