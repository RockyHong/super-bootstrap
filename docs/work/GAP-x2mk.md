# GAP-x2mk — session-close can close while work this session started is still running

**Logged:** 2026-10-29 · **Source:** handoff note from `rockyhong__magnetized-remake` (D:/Git/Games/Magnetized Remake), 2026-10-29, read via `/read-notes`
**Problem:** `/super-bootstrap:session-close` has no detect step for in-flight work. A background subagent (Agent `run_in_background`), a backgrounded shell, a Monitor, an armed cron/wakeup, or a spawned `claude -p` / foreign executor (`codex exec`) can still be running when the skill routes to the confirm-pick and closes; that work then writes after the commit — left uncommitted, or racing the commit door's readback. Seen in Magnetized Remake on 2026-10-29: the user asked for `/super-bootstrap:session-close park close` while a build subagent was mid-round; the gateway chose to wait for the report, verify, then pick — the skill text never asked for it. Author's ruling: session-close is the session's last step; it must not close while anything this session started is still running.
**Area:** `plugins/super-bootstrap/skills/session-close/SKILL.md` (detect steps, Rules); possibly `plugins/super-bootstrap/skills/session-continue/SKILL.md` (pickup check for leftovers a close accepted as in flight)
**Prior:** sender's shape — a first detect step "in-flight work" listing everything this session launched that has not reported back; any running → no pick, surface the list with three options (wait then re-detect / stop via TaskStop then inspect partial writes / explicit user accept, carry records them in flight); Rules bullet "Last step. Nothing this session started is still running when the close commits."
