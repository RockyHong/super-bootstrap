# DEBT-058 — doc-sync may not catch a new doc that supersedes an existing doc's claim

**Logged:** 2026-08-09 · **Source:** the mattpocock posture drift — two specs asserted opposite postures across two commits before anyone noticed
**Problem:** The commit door's scan is keyed on the diff: it looks for prose elsewhere describing behavior the diff changed. A commit that adds a **new** doc stating a posture which contradicts an **existing** doc changes no text in the older one, so there is nothing in the diff to key on — the older claim keeps reading as current. That is what happened when `docs/specs/mattpocock-coexistence.md` shipped as a new file declaring one posture while `harness-architecture.md` §4/§6 and `docs/decisions.md` row 21 went on declaring the one it replaced; a reader entering through the spec got the superseded answer for two commits. Whether the gate fired and the scan judged it clean, or the gate never fired, is unknown — the session that landed it is not available, so the failure point is unlocated.
**Area:** `plugins/super-bootstrap/skills/commit/SKILL.md` §3 grep-gate + §4 scan dispatch; `plugins/super-bootstrap/agents/doc-sync-scan.md` (what the cold scan is asked to look for); [`.claude/guidelines/work-discipline/doc-impact-mirror.md`](../../.claude/guidelines/work-discipline/doc-impact-mirror.md) scan predicate
**Prior:** Locate the failure point before proposing anything — a controlled run (new doc asserting a posture an existing doc contradicts, against the current gate + agent) tells whether this class is already covered, and a fix authored without that test is the unearned-prose shape `.claude/rules/skill-authoring.md` gates.
