# BUG-048 — `placed` is recorded only after a copy, so a sha-equal frozen file never earns an entry and its next asset bump lands as fork

**Logged:** 2026-08-27 · **Source:** consumer pilot sync 2.40.0 → 2.41.1 — producer findings 1 + 2 (same root cause)
**Problem:** [`hooks-ensure-infra.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md) § Idempotency ("After copying a script, record `placed[…]`") and [`drain/assets/ensure-infra.md`](../../plugins/super-bootstrap/skills/drain/assets/ensure-infra.md) § Idempotency ("After copying the template, record `placed[…]`") write the hash on the copy branch only. A consumer whose installed copies are already byte-equal to the asset — placed before the `placed` field existed, or verified-current on every sync since — never enters that branch, so no entry is ever written; [`harness-bootstrap/SKILL.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md) § 2c only carries the on-disk map forward whole, so the map stays absent forever. On the next asset bump `scriptUntouched()` / `templateUntouched()` find no entry → the fork prompt fires for a copy this pipeline did place. The pilot hand-seeded `placed` for its four verified-current files (deviation, flagged) to get past it.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md` § Idempotency · `plugins/super-bootstrap/skills/drain/assets/ensure-infra.md` § Idempotency · `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § 2c receipt write
**Prior:** record `placed` on the verified-current branch too (sha-equal → write the same hash, same guarded read-modify-write), so the map converges without a copy; § 2c stays a carry-forward. The pilot's hand-seeded entries are exactly what the fix would have written — keep them. Unblocks [DEBT-099](DEBT-099.md): after one clean sync every consumer carries a `placed` hash for the template.
