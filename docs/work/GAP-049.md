# GAP-049 — doc-sync gate has no wikilink detection — missing links uninserted, broken links unchecked

**Logged:** 2026-08-02 · **Source:** user capture via /super-bootstrap:log
**Problem:** The doc-sync gate (commit door grep-gate + `doc-sync-scan` agent) has no wikilink awareness. Two sub-problems ride the same gap: (1) docs that were authored without following the `ssot-doc-link.md` born-linked discipline (concepts used substantively with no link to their SSOT home) pass doc-sync undetected — missing links are never inserted retroactively by the pipeline; (2) existing markdown links are never validated against their targets — a renamed file, a moved section, or a wrong anchor silently survives every commit. The adjacent `ssot-doc-link.md` rule fires at authoring time (on doc reads) but has no pipeline-level enforcement or repair pass, so the born-linked discipline is aspirational for already-committed docs and unverified for new ones beyond the authoring moment.
**Area:** `plugins/super-bootstrap/agents/doc-sync-scan.md` (scan predicate); `plugins/super-bootstrap/skills/commit/SKILL.md` §3 (grep-gate); `.claude/rules/ssot-doc-link.md` (adjacent authoring-time discipline)
**Prior:** Evaluate separately: (1) missing-link insertion — requires semantic detection of substantive concept uses against a known-SSOT map, likely a scan-agent addition or a dedicated lint pass; (2) broken-link validation — a mechanical check (target path/anchor exists) that could sit in the grep-gate pre-filter or as a cheap pre-scan step. Decide whether both sub-problems share one mechanism or warrant separate gates.
