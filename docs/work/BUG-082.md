# BUG-082 — the commit-channel deny fires on a commit targeting a repo outside this one, and routes it to a door that cannot serve it

**Logged:** 2026-10-07 · **Source:** harness-bootstrap fixture walks (three cold executors, plugin v5.1.1, scratch repos under the session scratchpad)
**Problem:** `.claude/hooks/commit-channel.sh` resolves its gate from the `agent_type` stdin field alone — `case "$agent" in main) exit 0 ;; esac` — with no read of the commit's target repository. A dispatched subagent committing to a throwaway fixture repo outside this tree is therefore denied, and the deny text instructs it to "let the gateway fire `/super-bootstrap:commit`" — a door that commits *this* repo, never the fixture. The guidance is unfollowable for that case, so the worker either abandons the commit or works around the hook. Three of three cold executors hit the deny verbatim on fixture commits; one abandoned, and its run lost every git-history-gated lane (the § 2b rot scan is gated on a bootstrap-shaped commit existing, so it never ran).
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.sh` (SSOT, asset-ahead lane) + the placed dogfood copy `.claude/hooks/commit-channel.sh`; `assets/hooks/commit-channel.hook.json`; `tests/commit-channel.test.sh`
**Blast:** repo — plus any dispatched build container that must commit inside a scratch tree
**Prior:** The gate reads the *actor* and never the *target*; a target-repo predicate (commit's repo root vs `CLAUDE_PROJECT_DIR`) is the missing term. Distinct from [`docs/decisions.md`](../decisions.md) row 62, which closed the *widening* axis (more commit verbs, more tool paths) and affirmed the hook as a routing guard — this is the opposite axis, the guard firing where it has no door to route to.

### Decision needed

- How does the gate acquire its target-repo term, given the term is not generally computable at PreToolUse — and does the shipped guard grow a documented pass form?
- **A — explicit-flag escape.** The script captures the target from the git global flag it already walks (`-C <abs path>`, `--git-dir=`) and exits 0 when that path resolves outside `CLAUDE_PROJECT_DIR`; every other form keeps denying, and the deny text gains the re-issue instruction naming the flag form. Cost: a new pass form every installed repo inherits; `tests/commit-channel.test.sh:80` flips; residual — a quoted path with spaces breaks the walker's `[^[:space:];&|]+` token, and a `cd`-then-commit payload denies once before the worker re-issues.
- **B — keep the gate, fix the guidance.** No predicate change; the deny text gains an outside-repo branch routing the commit back to the dispatcher, and the fixture-walk harness stops needing a worker-landed commit (the dispatcher commits the fixture, or the re-run signal is seeded without one). Keeps the actor-only gate and adds no pass form; leaves the aim's "fires only where a door serves" unmet by design, and moves the obligation into the harness layer outside the hook.
- **C — actor-class exemption.** The gate passes a declared out-of-repo worker class (an `agent_type` allowlist, or a brief-set sentinel). Cheapest predicate, but it keys on the actor — the term this card identifies as the wrong one — and any worker can present the class.
- recommendation: **A.** It is the only option whose predicate reads the target, it lands inside the flag walker the script already runs, and row 62's ratified reading ("a routing guard to the door, not a containment boundary", with a worker's script-indirection commits into a throwaway repo recorded as accepted residual) means the pass form gives away no containment this hook ever had. A's deny-text change makes the guidance followable even for the payload forms its predicate cannot resolve, which is the harm the card records.
- settles by: the containment half is settled — cite [`docs/decisions.md`](../decisions.md) row 62. What remains is the author's call on growing the shipped guard a pass form (risk / accountability root: the contract ships to every installed repo). One measurement refines A's first-attempt hit rate without changing the A/B/C pick — the verbatim command text of the three deny events, sized `inline read`: grep the fixture-walk session transcripts (`~/.claude/projects/D--Git-super-bootstrap/*.jsonl`) for the deny reason string and read the `tool_input.command` beside each.

## Amendment — 2026-10-08 · container, not guard — the premise's scenario is a methodology breach (user, in-session)

**The guard is not the defect; the walk's container is.** The user challenged the premise at the fork: a session's subagent should not be committing into a repo that is not that session's own. Checking it against this repo's own bench methodology confirms the challenge and voids all three fork options.

[`bench/commit-guard/README.md`](../../bench/commit-guard/README.md) § Protocol already states the settled form, lines 23–25: "Arms run headless (`claude -p`) with the fixture as cwd — a project-level `commit-channel` hook routes a subagent's raw `git commit` back to the gateway, **so an in-session subagent cannot be the arm.**"

In that form nothing is denied and nothing needs changing: the fixture is its own project, so this repo's hook is not wired into that session at all; and once the fixture's own bootstrap has run, the fixture carries its **own** `commit-channel` hook, whose deny routes to `/super-bootstrap:commit` — a door that, in that session, commits the fixture. The door serves. The guard's behavior is correct end to end.

The three cold executors hit the deny because they ran as **in-session subagents of a session rooted in this repo**, not as headless runs rooted at the fixture. Corroborating surface: `tests/commit-channel.test.sh:61` models the payload as `Set-Location $FIXTURE` — a navigate-in command shape that is only needed when the shell's cwd is not the fixture, i.e. when the session root is elsewhere.

**Consequence for this card's `Area:`** — `assets/hooks/commit-channel.sh` and its placed dogfood copy owe no change, so the frozen-asset cost chain the Verdict priced (marker v7 → v8, the row-62 propagation across five narrator surfaces, the runway-receipt sha re-stamp, the `CLAUDE_PROJECT_DIR` term in the test harness) is not owed either. Options A (flag-based pass form), B (deny-text-only), and C (actor-class exemption) are all withdrawn: A and B modify a guard that is behaving correctly, and C was already ruled out on the card's own term.

**Where the real remainder lives.** The defect is that the fixture walks were launched in a container the repo's own protocol forbids for exactly this reason, and the protocol's assertion sits in one bench README rather than anywhere a walk author reads at launch time. The `§ 2b` coverage loss the card records (an abandoned fixture commit leaves the next pass reading as a fresh install, so the git-history-gated lanes never fire) is real and stands as the harm — it is a harm of the wrong container, not of the guard.

**Note on the Verdict above.** Its grounding reached this surface — scope item 3 names `bench/commit-guard/README.md` § Protocol — but held the assertion as collateral a fix would partly falsify, rather than as the governing protocol that makes a fix unnecessary. The premise-verify and the row-62 reading in that block stay valid; its fork does not.
