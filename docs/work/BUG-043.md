# BUG-043 — doc-links.sh fence toggle is blind to fence nesting

**Logged:** 2026-08-25 · **Source:** BUG-042 triage — the agent's first verdict draft embedded a fixture as a fenced block inside a fenced block and `doc-links.sh check` reported a link inside it as broken
**Problem:** `extract_links` flips `in_fence` on *any* line opening with three backticks or tildes, so a fence opened with a longer run (```` ```` ````) that wraps an inner ``` ``` ``` block closes at the inner opener: the inner block's body and everything after the outer closer are read with the fence state inverted, and path-like literals in prose that should be code report as broken links (or real links inside code go unchecked). CommonMark closes a fence only on the same character with a run at least as long as the opener; the toggle carries neither the character nor the length.
**Area:** [`plugins/super-bootstrap/skills/commit/assets/doc-links.sh`](../../plugins/super-bootstrap/skills/commit/assets/doc-links.sh) — `extract_links`, the fence line inside the second `awk` program
**Prior:** Track the opener — its fence character and run length — and close only on a line whose run is the same character and at least as long; the portable-awk floor in [`docs/techstack.md` § Coding Patterns](../techstack.md#coding-patterns) rules out interval expressions for the length check, so count the run with a loop or `match` + `RLENGTH`. Seen once, on a card that has since been rewritten around it; no doc on the surface currently nests fences.
