# GAP-drwb — commit doc-sync reports a same-change harness co-edit as "route to owner", so the gateway asks the user one item at a time

**Logged:** 2026-11-09 · **Source:** device note from a jowagoko session, 2026-11-09. The user's words, verbatim: 「很煩欸，有偵測到為什麼不一次改完，改一處又問這裡也改嗎」
**Problem:** The user changed a criterion-type policy (the YouTube Shopping product-tagging standard). The session edited `docs/overview.md` and `docs/know-how/platform/monetization.md`, then ran `/super-bootstrap:commit`. The scope was over 8 docs, so the cold `doc-sync-scan` ran. It returned clean, plus one "out-of-scope drift, report only" item: `.claude/skills/ep-prep/SKILL.md` still narrates the old standard. The session turned that item into a question to the user. After that fix it found `workspace/` docs and an already-sent cohost message on the old standard too, and asked again.
Mechanism the note names: the doc-sync lanes enumerate only the doc surface. Harness is read-only in this step (CLAUDE.md § Doc Sync, Write boundary: "flag the drift and route the fix to its owner"). So harness co-changes surface only after the commit, and come back shaped as a separate matter. When the session itself owns that harness, "route to owner" means back to itself, but the output shape makes the gateway treat it as a new decision point. `workspace/` and sent outward messages sit in no lane.
**Area:** `plugins/super-bootstrap/skills/commit/SKILL.md` (doc-sync step), `plugins/super-bootstrap/agents/doc-sync-scan.md` (output contract), `plugins/super-bootstrap/skills/harness-bootstrap/assets/claude-md-skeleton.md` § Doc Sync Write boundary
**Prior:** The note offers two directions. (i) For a criterion or policy SSOT change, enumerate the closure before implement: grep the old criterion's keywords across docs, harness, workspace and outward messages, and do the whole list in one pass, so doc-sync verifies instead of discovers. (ii) When doc-sync reports harness drift that is a co-change of the same edit and the gateway owns that harness, report it as "a harness edit to do this round, through its own audit", not as a pending route-to-owner item. The global CLAUDE.md half (the closure rule is not bound to its trigger moment) went to claude-config-manager in a separate note.
