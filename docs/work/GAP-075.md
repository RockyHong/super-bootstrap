# GAP-075 — commit-channel: a subagent's `git commit` in a non-project repo (fixture, scratch) is denied like a project commit

**Logged:** 2026-09-10 · **Source:** GAP-073 verify run — a dispatched executor committing inside a scratch fixture under the session scratchpad was denied by this repo's `commit-channel` hook
**Problem:** `assets/hooks/commit-channel.sh` routes every subagent `git commit` back to the gateway on the `agent_type` field alone; it never asks which repo the commit targets. A worker whose task is legitimately to commit elsewhere — a bench fixture, a scratch clone, a worktree the drain path owns — hits the same deny as a project commit, and the deny text ("let the gateway fire /super-bootstrap:commit") is wrong for that repo. The single-channel property is about *this* project's history; decide whether the guard should resolve the commit's target (`git -C <dir>`, a leading `cd`, else cwd → `git rev-parse --show-toplevel`) and pass when it differs from `CLAUDE_PROJECT_DIR`, or state that a subagent never commits anywhere and the fixture-commit shape is the dispatcher's to run.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.sh` (frozen v5); `.claude/hooks/commit-channel.sh` (dogfood copy, byte-identical); `assets/hooks-ensure-infra.md`; root README `.claude/hooks/` row
**Prior:** The guard predates any dispatched task that owns a second repo; the drain worktree path sidesteps it by running workers as separate processes (`agent_type` absent → main).
**Test-feel:** unit · **Blast:** pkg
