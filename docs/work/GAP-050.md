## Amendment — 2026-08-02 · judges-unification scope + DEBT-044 residue transfer (intake discussion, user-led)

Scope extension: the per-slot audit also decides the **cold-judge taxonomy**. Three agents hold one epistemic function — cold, priors-skeptical claim-vs-evidence judging — keyed by entry door: `triage` (card pickup, Opus, root-cause depth), `triage-report` (`.review/` scan reports, Sonnet, per-finding disposition), `review-intake` (mid-flow review findings, Sonnet, per-claim falsify). Decide: one grounding function parameterized by door (tier / depth / batch), or door-native slots. Facts settled in discussion:

- **Value density is internal-vs-external.** Internal reviews (same session, same granularity) carry low FP rates — premise-check marginal catch is small; external mass scans (scope/granularity mismatch) carry high FP — the check pays there. `triage-report` already owns the external-scan lane, so `review-intake`'s residual lane is mid-flow findings — mostly internal in a solo-dev repo. Its strongest surviving case: externally-produced reviews arriving mid-flow (pasted PR comments, cloud review output).
- **Framing counter-fact (against "second look = same dice"):** DEBT-032 run 2 — the same model family reaches the falsifying line; framing (falsify-this vs implement-this) decides what it does with it. Adversarial framing adds real signal even same-family.
- **Function is not bleed; container is the question.** `review-intake` is repo-native in provenance (DEBT-032 experiment, spec §5 deliberate authorship, skeleton ships it) and gate-the-input-stream matches the pipeline's own thesis (commit door, doc-sync gate, triage). Open question is only whether the thesis needs a dedicated agent per door.
- **DEBT-044 residue transfers here:** the README § Inline vs Dispatch unowned-agent row for `review-intake` (its option A shape sits in DEBT-044's Verdict, git-archived). Judges unify → the row is never written; intake stays standalone → land that row shape then.

## Design — 2026-08-03 · settled with user — context-engineering reframe (charter-first)

**Thesis (settled):** brainstorm→spec→plan→impl 是 de-routed pipeline 的殘留,多數關卡 ceremonial — 模型世代已解掉 attention-dilution / anchor-drift(`docs/specs/harness-architecture.md` §1 的 model-generation-bound 組),staging ceremony 對的正是那兩個。價值收斂到永久組:doc-sync + cold docs + cards + grounding + link graph — **context engineering(wiring + retrieval)> pipeline engineering**。開發中的 temporal artifact 不是 spec,是 **context scope**:前因後果 context + blast area + 任務邊界,確保執行範圍後讓 agent 專心做事。`docs/specs/`(product truth,state dimension)不受影響 — 兩個維度,temporal 件不再稱 spec。

**Evidence anchors:** spec §1 load-bearing split(前兩 failure modes "largely has dissolved");probe 記錄 implement 0/3 pushback vs triage 3/3 falsification(`docs/decisions.md` DEBT-032 row;GAP-045 RED/GREEN 重現);`agents/triage.md` verdict block 結構(Root cause / Files / Doc Impact / Execution sizing)已是 context scope 的形狀;兩週多 repo 裸跑(未裝 super-bootstrap)夠用、牆 = no-doc-sync scope cap + session-ledger cap(倖存者偏差註記:裸跑的 context engineering 在作者腦中 — 結論是價值收斂到永久組,非 harness 不需要)。Ledger cap 的解:context scope 落卡(durable),ledger 只留 pointer — Session Carry contract 既有分工,零新機制。

**Deliverables (re-cut):**
