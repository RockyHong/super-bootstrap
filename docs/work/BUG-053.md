# BUG-053 — commit-door link check strips CJK from heading slugs; every non-ASCII anchor reports broken

**Logged:** 2026-08-27 · **Source:** GitHub issue [#55](https://github.com/RockyHong/super-bootstrap/issues/55) via `/pull-issue`; reproduced in-session on a scratch file
**Problem:** [`skills/commit/assets/doc-links.sh`](../../plugins/super-bootstrap/skills/commit/assets/doc-links.sh) `check` (2.42.2) slugs `## 3. 後台數據` as `3-` (`anchors` subcommand reproduces: `3-` / `hello-world`), so a link `[x](doc.md#3-後台數據)` is reported `anchor not found in target` on every commit while GitHub renders that anchor fine. A repo with CJK docs can only fall back to file-grain links or acknowledge the false broken each commit. Expected: GitHub-rule slugs — lowercase, strip punctuation, spaces→`-`, **keep unicode letters** (`3-後台數據`); ASCII headings unchanged. Verify: an md with a CJK heading plus one `#<cjk-slug>` link → `check` reports zero broken; English-heading behavior identical.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` `SLUG_AWK` (~L105–116; shared by `check` / `refs` / `anchors`, so one fix site)
**Prior:** `gsub(/[^a-z0-9 _-]/, "", s)` is an ASCII-only class — it deletes every unicode letter. Fix shape: strip punctuation/symbols rather than "non a-z" (awk `[[:punct:]]` under a UTF-8 locale, or an explicit ASCII-punctuation class), leaving multibyte letters intact; mind mawk vs gawk byte-vs-char semantics.
**Test-feel:** unit
**Blast:** local
