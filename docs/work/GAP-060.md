# GAP-060 — triage's card location is fixed to `docs/work/{ID}.md`, so a repo on another card substrate has no door into the grounding phase

**Logged:** 2026-08-12 · **Source:** GitHub issue [#41](https://github.com/RockyHong/super-bootstrap/issues/41) (RockyHong), pulled via `/pull-issue`
**Problem:** `/super-bootstrap:triage` is documented as every card's pickup — the read-only grounding phase that premise-verifies, aim-validates and blast-collects before implementation runs — but its card location is fixed: the skill takes a bare ID and the `triage` subagent appends its verdict to `docs/work/{ID}.md`. A repo tracking open items elsewhere (a single queue file with one row per item, say) has no way in: there is no argument for the card's path and the subagent's contract names the location directly. The grounding *work* is substrate-independent; only the read/write target is coupled. Cost: grounding is the phase that catches a card whose premise was never checked against real data — with no door, pickup goes straight from card text to implementation and a wrong premise surfaces after the change ships. It also cuts against the project-agnostic rule the harness applies to its own skills (read the host's convention from ambient rather than hardcoding repo layout). Shapes named by the reporter, in rising blast: accept a path or `file#anchor` alongside a bare ID with `docs/work/{ID}.md` as default resolution · resolve the card home from the consumer's CLAUDE.md the way other phases read host conventions · at minimum degrade explicitly, reporting the substrate as unsupported rather than failing on a missing file. The verdict-append step needs the same treatment — appending a block to a row inside a shared queue file is a different write from appending to a dedicated card file, and the skill should either handle it or say it cannot. Verify: in a repo whose open items live in one queue file, invoke triage on an item and confirm it grounds the item and lands its verdict where that repo keeps it.
**Area:** `plugins/super-bootstrap/skills/triage/SKILL.md` (step 1 card resolution + description); `plugins/super-bootstrap/agents/triage.md` (write floor, § Aim `docs/work/` grep, verdict-append target)
**Prior:** Scope call first — whether sb's grounding phase serves foreign card substrates at all, or the harness prescribes `docs/work/` and the skill only owes an explicit unsupported-substrate degrade (current behavior stops at "no card {ID}", which reads as a missing card rather than an unsupported substrate); cf. the scope-boundary reasoning in [`docs/decisions.md`](../decisions.md).

## Verdict — surface · 2026-08-12

### Findings

- root cause: **the mechanical leg is confirmed, the rule leg is falsified.** Confirmed — `skills/triage/SKILL.md:20` resolves the card as `docs/work/{ID}.md` with no argument and degrades as `Missing → report "no card {ID}", stop`; `agents/triage.md` names the same path four times (frontmatter `description`, § Phase identity write floor L19, § Aim `grep docs/work/` L34, § Output formats L58). Falsified — the card's second cost leg ("cuts against the project-agnostic rule the harness applies to its own skills") has no referent: no such rule exists in the plugin, `.claude/rules/`, or root `CLAUDE.md`. The three nearest analogues are all *optional enrichment layered on a fixed substrate*, never substrate relocation — `drain/assets/merge-probe.md:10` parameterizes the **stack** from consumer techstack; `harness-bootstrap/SKILL.md:492` derives the **plugin's own artifact map** at runtime; `work-discipline/path-portability.md` bans **absolute machine paths**. Triage itself already carries the genuine ambient-read pattern (§ Probes reads the consumer's `docs/techstack.md § Probes` table, absent → skip), which is exactly this class: optional config on top of a fixed card home.
- scope reach: the fixed path is **the house pattern, not a triage outlier** — 89 literal `docs/work` references across 22 plugin files. Two facts make it structural rather than incidental: (1) `skills/resolve-plugins/SKILL.md:175` declares `docs/work/` the **harness-active marker** — "`docs/work/` directory exists in the repo. Detect with one Glob" — and L181 branches the core-pin lock on it, so the directory *is* the plugin's installed-signal; (2) [`docs/specs/harness-architecture.md`](../specs/harness-architecture.md) §2 assigns the "Standing work state" slot to super-bootstrap as **`docs/work/` cards** — an owned slot, not a host convention deferred to. Sibling doors state the same boundary explicitly: `skills/drain/SKILL.md:12` — "**Consumer contract:** assumes the super-bootstrap harness shape — `docs/work/{BUG,DEBT,GAP}-###.md` card files … Not portable below that line." The interop direction sb actually ships runs **outward**, not inward: `harness-bootstrap/assets/mattpocock-tracker-recipe.md` declares sb's card contract *to* foreign tooling rather than reading a foreign tracker's.
- attempted: swept all 24 `docs/work`-referencing plugin files for an existing parameterized or ambient-resolved card home — one near-miss and no hit. Near-miss: `check-docs-consistency/assets/tracker-annotation.md` frames generically ("*a* backlog, an issue list… e.g. `docs/work/` card set") but its operative § The contract line still hardcodes `Read open cards at docs/work/{BUG,DEBT,GAP}-###.md` — generic at the description level, fixed at the executable level. Also swept for the **degrade** precedent the card's third shape names, and it exists twice: `skills/log/SKILL.md:24` — README absent → "write nothing; route: *run `/super-bootstrap:harness-bootstrap` to (re-)plant the work substrate*"; `skills/todo/SKILL.md:33` — `docs/work/` absent → "**No runway installed. Run `/super-bootstrap` to set up the pipeline.**"; plus `agents/todo.md:77`'s stale-scaffold row. **Triage is the only card door with no substrate-absent branch** — that is the live, contained residual. Stopped at the scope fork: the card's own `Prior:` asks for the scope call first, and criterion 4 (no user judgment) fails on a product-boundary decision — decisions.md shows this class settled by owner call (the mattpocock-pairing row) rather than by evidence alone.
- aim: live, no duplicate — GAP-060 is the only open card; no closed fork in [`docs/decisions.md`](../decisions.md) covers card-substrate portability (the nearest, the retired `harness-grounding` hook row, closes a *different* scope question with the same shape: "Reopen only if super-bootstrap's scope expands to own consumer authoring discipline").

### Decision needed

- **What does super-bootstrap owe a repo whose open items are not `docs/work/` cards?** The three options below are the card's own named shapes, re-scoped against the evidence.
- **A — Nothing; close as a scope boundary (wontfix).** `docs/work/` is sb's owned slot and its harness-active marker; a repo on another substrate is outside the consumer contract `drain` already declares. Card deletes, row lands in `docs/decisions.md` with the reopen condition ("sb's scope expands to serve foreign card substrates"). Leaves triage's misleading "no card {ID}" in place.
- **B — An accurate diagnosis, nothing more (the card's third shape).** Boundary holds as in A, but `skills/triage/SKILL.md` step 1 gains the substrate-absent branch its two sibling doors already carry: `docs/work/` missing entirely → route to `/super-bootstrap:harness-bootstrap` / `/super-bootstrap` (matching `log:24` / `todo:33` wording), reserving "no card {ID}" for a missing card *within* a live substrate. Fix surface is one skill step; `agents/triage.md` needs no change (its BLOCKED row already covers "named files don't exist"). Blast: behavior-shaping skill prose → `.claude/rules/skill-authoring.md` RED applies (micro-test vs no-guidance control before the edit). No shipped-skeleton counterpart exists for this section, so no mirror propagation.
- **C — A resolvable card home (the card's shapes 1 and 2).** Accept a path/`file#anchor` argument, or read the card home from the consumer's CLAUDE.md. **Not triage-scopable:** parameterizing triage alone yields an incoherent pipeline — `/super-bootstrap:log` cannot mint the ID (`log:24` reads the high-water line from `docs/work/README.md`), `/super-bootstrap:todo` cannot board it (`todo:33` skip-gate + `shared/classify-actionable.md:71` glob), `drain` cannot admit it (`drain/SKILL.md:36`, `assets/phase-loop.md:53` maps the ground phase to a `## Verdict` block at `docs/work/{ID}.md`), `commit`'s card-lifecycle exemption (`commit/SKILL.md:19`) would not cover the write, and `resolve-plugins:175`'s harness-active marker would go dark. Real cost is a pipeline-wide substrate abstraction across ~22 files plus the append-only thread contract (`docs/work/README.md`) — appending a `## Verdict` block to *a row inside a shared queue file*, as the card notes, is a different write primitive entirely.
- recommendation-note: the option the user settled on is recorded in the Design block below.
- recommendation: **B.** The scope boundary is evidence-backed on three independent surfaces (owned slot, harness-active marker, declared non-portable consumer contract), so C buys a pipeline-wide abstraction for a substrate sb deliberately does not serve; but A leaves a real inconsistency standing — triage is the sole card door lacking the substrate-absent degrade its two siblings ship, and the card's diagnosis of that gap ("reads as a missing card rather than an unsupported substrate") is exact. B closes the verifiable defect, records the boundary in `docs/decisions.md` as A would, and leaves C's reopen condition intact.

## Design — 2026-08-12

`docs/work/` stays sb's owned slot: it is the harness-active marker `resolve-plugins` globs for, the "Standing work state" slot the architecture spec assigns to sb, and the consumer contract `drain` already declares non-portable below. Option C buys a pipeline-wide substrate abstraction for a layout sb deliberately does not serve; option A leaves the one verifiable inconsistency standing.
