# GAP-060 — triage's card location is fixed to `docs/work/{ID}.md`, so a repo on another card substrate has no door into the grounding phase

**Logged:** 2026-08-12 · **Source:** GitHub issue [#41](https://github.com/RockyHong/super-bootstrap/issues/41) (RockyHong), pulled via `/pull-issue`
**Problem:** `/super-bootstrap:triage` is documented as every card's pickup — the read-only grounding phase that premise-verifies, aim-validates and blast-collects before implementation runs — but its card location is fixed: the skill takes a bare ID and the `triage` subagent appends its verdict to `docs/work/{ID}.md`. A repo tracking open items elsewhere (a single queue file with one row per item, say) has no way in: there is no argument for the card's path and the subagent's contract names the location directly. The grounding *work* is substrate-independent; only the read/write target is coupled. Cost: grounding is the phase that catches a card whose premise was never checked against real data — with no door, pickup goes straight from card text to implementation and a wrong premise surfaces after the change ships. It also cuts against the project-agnostic rule the harness applies to its own skills (read the host's convention from ambient rather than hardcoding repo layout). Shapes named by the reporter, in rising blast: accept a path or `file#anchor` alongside a bare ID with `docs/work/{ID}.md` as default resolution · resolve the card home from the consumer's CLAUDE.md the way other phases read host conventions · at minimum degrade explicitly, reporting the substrate as unsupported rather than failing on a missing file. The verdict-append step needs the same treatment — appending a block to a row inside a shared queue file is a different write from appending to a dedicated card file, and the skill should either handle it or say it cannot. Verify: in a repo whose open items live in one queue file, invoke triage on an item and confirm it grounds the item and lands its verdict where that repo keeps it.
**Area:** `plugins/super-bootstrap/skills/triage/SKILL.md` (step 1 card resolution + description); `plugins/super-bootstrap/agents/triage.md` (write floor, § Aim `docs/work/` grep, verdict-append target)
**Prior:** Scope call first — whether sb's grounding phase serves foreign card substrates at all, or the harness prescribes `docs/work/` and the skill only owes an explicit unsupported-substrate degrade (current behavior stops at "no card {ID}", which reads as a missing card rather than an unsupported substrate); cf. the scope-boundary reasoning in [`docs/decisions.md`](../decisions.md).
