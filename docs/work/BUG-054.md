# BUG-054 — `do_refs()` admits `docs/work/**` card threads as citers; the frozen-provenance exemption stops at `terms` and `hits`

**Logged:** 2026-08-27 · **Source:** BUG-051 fix, cold audit probe finding (adjacent, outside that card's claim)
**Problem:** [`doc-links.sh`](../../plugins/super-bootstrap/skills/commit/assets/doc-links.sh) `do_refs()` filters citers through `is_history_doc` only, so an open card thread linking a doc section (a card's `Area:` or `Problem:` line citing `overview.md#…`) joins the citer read-set when that section changes. `terms` (via `path_exempt`) and `hits` (via `is_frozen_provenance_path`) already leave card threads and `docs/outward.md` out; the citer lane does not. Whether it should is a judgment the other two lanes did not need: a card citing a section is a declared reader of that truth, yet threads are append-only — a stale origin block is never "updated", at most amended.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` `do_refs()`; `plugins/super-bootstrap/skills/commit/SKILL.md` §3 citer lane; `bench/doc-links/` (`refs-*` goldens)
**Prior:** Either extend `is_frozen_provenance_path` to `do_refs()` (symmetry with `hits`, one bench case `refs-card`) or state in §3 why a card citer stays in scope — decide at triage; if excluded, the header line "`refs` and `check` still cover them" flips to `check` alone.
