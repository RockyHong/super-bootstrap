**Logged:** 2026-08-26 · **Source:** `GAP-064` Verdict arm (ii), split out on the user's ruling (GAP-064 § Design, Stage 0)
**Problem:** `plugins/super-bootstrap/shared/classify-actionable.md` § Wait override sets `intent: Discuss` on a card whose latest block names an awaited party, keeping the stage its thread state gives. The venue-wired lane split in `plugins/super-bootstrap/agents/todo.md` keys lane on venue alone (only `intent: Harness` declared to win over venue), and `plugins/super-bootstrap/skills/drain/assets/eligibility.md` § isEligible's venue branch reads `nextPhaseVenue(item)` without consulting `intent` — so a `raw` external-wait card lands **lane: drainable** and drain admits it, while the no-venue-map fallback (`if item.intent != "Cloud": return false`) defers the identical card. The plugin's own golden asserts the deferred behavior — `bench/todo-board/fixture-extwait/` + `expected/needme-extwait.md` (`Drainable: 0` + a `Decide:` row) — and passes only because `plugins/super-bootstrap/skills/todo/assets/render-board.py` exits 3 on a `.claude/rules/venue-map.md` hit, so the wired lane is never rendered by tested code. Installing the scale module inverts the golden's asserted behavior. Repro: the extwait fixture plus a venue map → board shows the card drainable; `/super-bootstrap:drain` claims a worktree and runs `/super-bootstrap:triage` on it before its first user wall fires (`drain/assets/phase-loop.md` § Walls).
