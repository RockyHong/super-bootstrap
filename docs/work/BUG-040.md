# BUG-040 — doc-links.sh anchor check false-negatives on BSD sed (macOS)

**Logged:** 2026-08-25 · **Source:** GitHub issue #49 (RockyHong) — https://github.com/RockyHong/super-bootstrap/issues/49
**Problem:** On macOS, `doc-links.sh check` reports essentially every markdown link carrying an `#anchor` as `anchor not found in target`, even when the heading plainly exists. One repo reported 100+ broken links; the true count was zero. Because the noise is total rather than partial, the commit door's link-integrity step reads as "this repo's links are a mess" rather than "this checker is broken" — the gate gets ignored, and a genuinely broken link would be invisible inside the false ones.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` (`anchor_exists()`, line 41)
**Prior:** `sed 's/^#\+ *//'` uses `\+`, a GNU BRE extension; BSD sed reads it as a literal `+`, so no heading prefix is stripped and `## Tests` slugifies to `-tests`. Reporter's fix: `sed -E 's/^#+ *//'` or plain-BRE `sed 's/^#* *//'` — both accepted by GNU sed too. Reporter states this is the file's only GNU-only construct (line 29's `sed` is portable BRE, `grep -qxF` is POSIX). Gateway confirmed line 41 reads as quoted.
