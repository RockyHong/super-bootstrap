# GAP-064 — `docs/work/` has no container for author-moved cards; business / external-wait / taste cards read as drainable T

**Logged:** 2026-08-26 · **Source:** GitHub issue [#50](https://github.com/RockyHong/super-bootstrap/issues/50), filed from a consumer repo at publish phase (pilot available, private); carry `SESSION-STATE/author-moved-cards-0472d25f.md` holds read-first pointers
**Problem:** The work-space carries one axis — defect category BUG / DEBT / GAP — and assumes the repo is the subject; it has no card-level **actor** axis (repo / author / external). Venue is derived per phase, so a card whose every phase is user-walled is indistinguishable from a repo card until triage has already run. Consumer census: 8 open cards, 1 cleanly drainable, 3 pure business / external-wait, 3 author-taste / author-review walled, 1 mixed (code behind an external wall). Three consequences: (1) **board noise** — `todo` lists them beside repo cards, nothing at glob level tells them apart; (2) **drain trap** — the venue-map's `raw → Triage → T` is unconditional, so `drain` admits a business card with no Verdict, crawls its external paperwork, and writes a Verdict nobody can act on in-repo; (3) **forced taxonomy** — an unanswered licence reply lands as DEBT, a pitch as GAP, restating state its `docs/business/` doc already holds, and the thread contract (triage → Verdict → Design → Plan) is the wrong shape for "author sends a thing, repo waits for the answer". Existing containers cover two of three handoff shapes: `parked` = actionable, waits on a named trigger, nobody moves it; `test-queue` = a repo card's **verify phase** handed to the author (phase-level); missing = the **whole item** is the author's move and the repo owns only a result tail (card-level). Option space from the issue (its lean = 2): 1. optional `Actor:` card field feeding venue derivation, drain excludes author / external; 2. separate container with its own glob (`docs/work/outward/` or a flat queue file) that `todo` renders as its own group and `drain` never reads, row shape parked-like (*next author move* + *repo tail: fires on*); 3. fourth prefix `OUT-###` in the same directory. Whichever lands is a scale-module opt-in like parked / test-queue. Verify: `todo` renders author items as their own group and the drainable count excludes them; `drain` never admits one; `log` routes an author-actor observation into the new container instead of forcing BUG / DEBT / GAP; `harness-bootstrap` adopt mode keeps a consumer's existing container.
**Area:** `plugins/super-bootstrap/skills/todo/assets/render-board.py` + `agents/todo.md` (stage → drainable count) · `skills/drain/SKILL.md` admission gate · `skills/log/SKILL.md` card-shape gate (card / parked / drop route) · `skills/harness-bootstrap/SKILL.md` scale module + adopt mode, `assets/scale/card-fact-fields.md`, `assets/scale/rules-venue-map-skeleton.md` · `shared/classify-actionable.md` · `skills/commit/SKILL.md` card-lifecycle exemption path list · `skills/check-docs-consistency` glob · `docs/work/README.md` card glob line
**Prior:** Two sub-shapes hide under "author-moved" and may want different treatment — (a) outward (external party / business move) → new container; (b) user-walled repo card (taste round, author review) → still a repo card, still yields a diff, but every phase is U → carries an actor signal so drain skips. If so, options 1 and 2 are complementary, not a pick. Fix belongs at the venue map's input or above it (a glob it never sees), not at drain's gate alone. Settle the (a)/(b) fork with the user after triage.

## Verdict — surface · 2026-08-26

### Findings

- **root cause — three arms, all confirmed by direct read of the shipped mechanism.**

  **(i) The venue map has a per-phase downgrade vocabulary and no actor vocabulary.** `assets/scale/rules-venue-map-skeleton.md` § Derivation maps `raw | Triage | T` with no derive arm, and § Modality overrides opens "Downgrade an otherwise-**T** phase when the row carries the signal" — every listed signal gates a post-ground phase (`Test-feel: manual` → *verify*, visual-taste → *acting*, `Test-feel: e2e` → *verify*). The one signal reaching a `raw` card's next phase, `Stochastic: llm`, routes triage to **P**, not **U**. So no field a card can carry walls its *triage* phase, and none walls *every* phase. The skeleton is byte-identical to the pilot consumer's `.claude/rules/venue-map.md` (`diff` clean) — the producer is this repo; the fix routes here, never to the consumer copy.

  **(ii) The venue lane discards the shared spec's wait override.** `shared/classify-actionable.md` § Wait override sets `intent: Discuss` while "keeping the **stage** its thread state gives". `agents/todo.md` § Lane split's venue-wired table keys lane on venue alone, declaring only `intent: Harness` as winning over venue — so a `Discuss` row at stage `raw` lands **lane: drainable**. `skills/drain/assets/eligibility.md` § isEligible does the same: its venue branch reads `nextPhaseVenue(item)` and never consults `intent`, while its no-venue-map fallback (`if item.intent != "Cloud": return false`) *does* defer the identical card. Installing the scale module therefore inverts behavior the plugin already ships a golden for: `bench/todo-board/fixture-extwait/` + `expected/needme-extwait.md` assert `Drainable: 0` plus a `Decide:` row for an external-wait card — and that golden holds only because the fixture carries no venue map (`render-board.py` `die(3, …)` on `.claude/rules/venue-map.md` presence, so the script never renders the wired case at all). This arm is a self-contained regression, separable from the container question — see § Decision needed, split note.

  **(iii) Cost is spent before the wall fires.** `skills/drain/assets/phase-loop.md` § Stage entry gives `raw` the chain `ground → [wall check] → plan → …`; § Phase → artifact routes `ground` to `/super-bootstrap:triage`, landing a `## Verdict` block on the card; § Walls fires its first user wall "after ground, before plan". So an admitted business card costs a worktree claim, a full triage crawl over its business paperwork, and an appended Verdict block — *then* halts. The card's consequence (2) is exact.

  **Consequence (3) confirmed at the capture door.** `skills/log/SKILL.md` step 2 offers exactly three routes — card / `docs/parked.md` `PARK-###` / drop. Parked is the wrong container by its own header (`assets/scale/parked-skeleton.md`: actionable-but-waits-on-a-named-trigger, nobody moves it), and its consumer note says `/super-bootstrap:todo` never lists parked entries — parking an author-move *hides* it. No fourth route exists, so an author-move is forced into BUG/DEBT/GAP.

Six classify `raw` (origin-only or Amendments-only) → venue **T** → drainable, and all six are author-moved. Two of the six carry `Test-feel: manual` and are still **T**, exactly per arm (i). One author-taste card *is* correctly walled **U** — it carries a `## Design` block, so the visual-taste modality reaches its acting phase. That single correct row localizes the hole precisely: **pre-Verdict cards, plus any card whose wall is not attributable to one named phase.**

### Decision needed

- **What shape carries the actor axis — a card field, a container, or both?** The (a)/(b) split the card's `Prior:` proposes is real and now evidenced: (a) outward items whose repo surface is a business doc yield no diff at all; (b) user-walled repo cards do yield a diff (a spec edit, a locale column) but have no phase a machine can take. Arm (i) shows a container alone cannot reach (b); consequence (3) shows a field alone cannot reach the taxonomy complaint. The options are not interchangeable coverage of one problem.

- **Options**
  1. **Container only** (the issue's lean) — a new scale-module container with its own glob, its own `todo` group, and no `drain` read; row shape *next author move* + *repo tail: fires on*. Closes (1)(2)(3) for sub-shape (a). Leaves sub-shape (b) exactly where it is — those cards stay in `docs/work/`, still read `raw`, still count drainable.
  2. **Card field only** — an optional `Actor: repo | author | external` fact field, one arm in the venue map downgrading **every** phase to **U** when set, one lane guard in `eligibility.md`. Closes (1)(2) for both sub-shapes at the smallest blast, no new glob. Leaves (3): an outward item still files as BUG/DEBT/GAP under a thread contract shaped for triage → Verdict → Design → Plan.
  3. **Both, staged** — field first (mechanical, closes the live harm for (a) and (b) alike), container second (closes the taxonomy harm for (a), and lets the field's `external` value retire into it). Largest total blast, but each stage ships and verifies alone.
  4. **Fourth prefix `OUT-###` in `docs/work/`** — one taxonomy change, no new glob, but it touches all 21 taxonomy sites and hands the new kind the same thread contract the card says is the wrong shape. The issue already leans away from this.

- **recommendation: 3 (both, staged), field first.** Arm (ii) is a shipped regression — installing the scale module makes drainable an external-wait card that the plugin's own `fixture-extwait` golden asserts is not — and only the field reaches it at every stage; the container is the right home for the taxonomy complaint but cannot land first without leaving sub-shape (b) broken. Staging also keeps each phase inside one surface, which neither the combined change nor option 1 does.

- **split note (gateway's call, not mine).** Arm (ii) — the venue-wired lane and `eligibility.md` both dropping the shared spec's `intent: Discuss` wait override, against a golden asserting the opposite in the unwired lane — is a self-contained defect with a repro the existing bench can carry. It can land as its own BUG ahead of whichever option wins, or ride stage 1 of option 3. It should not be silently folded into a container design.

## Amendment — 2026-08-26 · user, mid-session

Reframe of the aim, not a new option: this is not only drain's venue problem — it is an **attention-offload** problem with two actors whose attention focuses differ, and the design (or designs) must serve each actor's root concern, not one on behalf of both.

Stage 2 (the outward container's row shape: next author move · waiting on · repo tail) serves this concern; a field alone leaves the author reading BUG/DEBT/GAP threads to find their own queue.

Check every stage's verify line against the concern it claims to serve: a stage that fixes the drainable count but leaves the author's queue unreadable has served one actor only.
