Reproduced in this repo (20 files under `docs/` + `README.md`, 155 link occurrences, 49 anchored index entries), Git-Bash/msys on Windows:

- `time bash plugins/super-bootstrap/skills/commit/assets/doc-links.sh check` → **real 49.3 s** (user 24.1 s, sys 26.6 s), exit 0
- `time … refs docs/techstack.md` → real 9.9 s · `time … index` → real 15.7 s

In every run `sys` ≈ `user` — the signature of process-spawn cost, not computation.

### Root cause (verified)

Two fork-count mechanisms in the shared helper layer. The card premise holds and localises:

1. **Dominant — `anchor_exists` re-derives the target file heading-slug table on every anchored link, at 4 processes per heading.** `anchor_exists` (`doc-links.sh:40-46`) holds no cache, so each anchored link recomputes its target slug list from scratch, and `slugify` (`:28-33`) is a 4-process pipeline (`printf | tr | sed | tr`) invoked **once per heading**. Cost = sum over anchored links of 4 × (headings in target). Measured in isolation: one `anchor_exists CLAUDE.md …` call = **1.17 s** (23 heading lines, ~50 ms each); this repo holds 13 links to `CLAUDE.md#…`, so that single target costs **15.4 s** of the run.
2. **Floor — ~6 forks per link in the resolve path, shared by all three subcommands.** `resolve_target` (`:112-136`) returns via stdout, so every call is a command substitution (fork) that internally forks `dirname` (`:129`) and the `normalize_path` awk (`:50-62`, itself a second command substitution at `:135`); `do_check` then forks `cut` twice to split the result (`:154-155`). `do_refs` (`:183-186`) and `do_index` (`:198-201`) carry the identical pattern — which is why `refs` costs 9.9 s here while doing no anchor work at all. This is the family-sweep result: one helper-level defect serves all three subcommands, so the fix covers the family. It also multiplies through the other mechanical lane of SKILL.md §3, which runs `refs <path>` **once per changed doc path** (`SKILL.md:23`) — a 5-doc commit pays ~50 s there on top of `check`.

`check` = mechanism 1 + mechanism 2; `refs` / `index` = mechanism 2 only. That is precisely the asymmetry the card observed.

Scaling: the downstream report is 49 files under `docs/`, ~2.5× this surface, projecting ~125 s — crossing the 120 s Bash default. The mechanism predicts the reported symptom with no extra assumption.

**Fix shape — prototype-verified.** A patched copy (scratchpad, not landed) making three changes:

- `slug_lines()` — one awk pass per file emitting every heading slug (`sub(/^#*/,""); sub(/^ */,""); tolower; gsub(/[^a-z0-9 _-]/,""); gsub(/ /,"-")`), replacing the per-heading `printf|tr|sed|tr`;
- `anchor_exists` memoizes the slug list per file (bash-3.2-safe eval key, `SLUGCACHE_${file//[^a-zA-Z0-9]/_}`) and matches via `case` on the newline-delimited list rather than forking `grep -qxF`;
- `normalize_path` / `resolve_target` become fork-free, returning through globals (`NORM`, `R_KIND` / `R_PATH` / `R_ANCHOR`); `do_check` / `do_refs` / `do_index` read those globals instead of forking `cut`.

Measured on this repo: `check` **49.3 s → 0.585 s** (84×), `refs` **9.9 s → 0.37 s**. Output parity confirmed three ways: (a) `index` and `refs` byte-identical against the live repo; (b) a purpose-built broken-link fixture (missing path, missing target anchor, missing intradoc anchor, `./` + `..` normalization, a CJK/diacritic heading slug) yields byte-identical findings and the same exit 1; (c) the existing `tests/doc-links.test.sh` passes 7/7 against the prototype unmodified — including the BUG-040 sed-BRE construct lock and the BUG-042 no-interval lock, both of which the replacement awk satisfies.

**Prior option B is closed by evidence, not by preference.** Option A ("build the link index once per run"), in its fork-elimination form, already lands 84× with byte-identical semantics. Option B (default-scope `check` to changed files + citers, `--all` for the whole surface) would trade away the contracted whole-surface coverage of the §3 link-integrity layer to buy a speedup that is no longer needed. No coverage trade-off is required, which is also why this stays auto-fix rather than a user-judgment fork.

**Caveat on platform generality.** Both the 49.3 s baseline and the 0.585 s result were measured under msys/Git-Bash on Windows, where `fork` costs ~10-20 ms. On a Linux runner the same surface is already several times faster pre-fix, so the absolute point at which 120 s is crossed is platform-dependent — the mechanism (fork count, growing as anchored-links × target-headings) is not. This does not change the fix; it does mean the regression lock should assert fork-shape, or a generous wall-clock ceiling, never a tight absolute number.

### Files (fix surface)

- `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:28-33` — `slugify`: replace the per-heading 4-process pipeline with a one-pass `slug_lines` awk program. Must stay inside the [portable-awk asset dialect](../techstack.md#coding-patterns) — no interval expressions, no GNU-only sed BRE escapes; this is the exact surface that produced BUG-040 / 042 / 043.
- `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:40-46` — `anchor_exists`: memoize the slug list per target file. The `pipefail` / EPIPE guarantee documented at `:36-39` (slugs buffered into a variable before matching) must survive — the one-pass form preserves it by construction.
- `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:49-63` — `normalize_path`: pure-bash segment walk returning through a global; drop the awk fork. Semantics to preserve exactly — skip empty and `.` segments, pop on `..` only when the accumulator is non-empty.
- `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:112-136` — `resolve_target`: return through globals; drop the `dirname` fork in favour of a `case`-based parent-dir strip.
- `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:138-170, 172-192, 194-206` — `do_check` / `do_refs` / `do_index`: read those globals, drop both per-link `cut` forks. All three convert together; they share the helper contract.
- `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:2-15, 36-39` — header and rationale comments: the rewrite subsumes the constructs those notes explain; restate them, never delete silently.
- `tests/doc-links.test.sh` — regression lock, RED first. Recommended shape: a fixture-parity case covering the four finding classes (missing path, missing target anchor, missing intradoc anchor, `.` / `..` normalization) plus a construct assertion that no per-link command substitution or `cut -f` survives inside the three `do_*` loops. A wall-clock assertion, if added, needs a generous ceiling — see the platform caveat.
