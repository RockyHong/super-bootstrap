# BUG-q2jy — commit door's grep lane takes a changed code file's basename as its term, so any edit to a consumer hub code file crosses the scope ceiling

**Logged:** 2026-11-13 · **Source:** device note `20261112T165758Z-commit-gate-file-term-overscope` from `magnetized-remake` (plugin v5.10.4); author: "太扯了，為什麼這樣小改動會有24份文件?"
**Problem:** `doc-links.sh terms` derives one term per changed path — the basename — whatever the diff changed inside the file. A consumer's hub code file (`scripts/game.gd`, `main.gd`, `player.gd`) is mentioned in code shape by nearly every doc, so every edit to it, a one-value change included, puts nearly the whole doc surface in scope and sends it to the cold `doc-sync-scan`. Observed: a two-line diff (`PLAY_TS_BY_VIEW["LV58"]` value in `scripts/game.gd` + the matching pin under `tests/`) → `terms` prints only `game` → `hits` returns 24 docs → over the 8-doc ceiling → cold scan, about 48k tokens and 48 s, returns clean: no doc narrates the changed fact. `HUB_STEMS` bounds the same effect only for the doc stems `harness-bootstrap` seeds; a consumer's own hub code files have no bound. Repro in a consumer repo: change one const value in a script most docs mention, then `git diff --name-only HEAD | doc-links.sh terms - | doc-links.sh hits -`.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` (`do_terms`, `derive_term`, `do_hits`, `HUB_STEMS`); `plugins/super-bootstrap/skills/commit/SKILL.md` §3; `tests/doc-links.test.sh`; `bench/scope-replay/`
**Prior:** Sender's candidates — (1) terms for a code file come from the diff hunk's symbols, basename only on add / delete / rename; (2) a basename term that hits more than N% of the doc surface is demoted like a hub stem; (3) `hits --by-term` flags a high-count term at the gate instead of sending the whole scope cold. Sender also notes its repo's `CLAUDE.md` carries a knob-value-tweak carve-out the door cannot see. Adjacent closed fork: `docs/decisions.md` § Closed Forks, the `DEBT-94g6` row (ceiling / unit / lanes) — its measurement did not attribute crossings to code-origin basename terms.

### Decision needed

- Which rule replaces "a changed code file's basename is its grep term", so that scope follows what the diff changed inside the file?
- Options:
  - A — hunk-derived terms. For a modified code file, terms are the identifiers on the diff's changed lines and its hunk-header context; the basename stays for an added, deleted or renamed file. `terms` gains a diff-reading input. Risk: a doc that narrates the file's behavior without naming an identifier is no longer reached.
  - B — fan-in demotion. The basename stays, but a term that hits more than a set share of the doc surface is treated as a hub stem. Bounds the worst case only; a mid-fan-in file keeps its false scope, and the threshold is a new number to defend.
  - C — gate-side flag. Terms and hits stay; above the ceiling the door reads `hits --by-term` and drops or asks about a dominant term instead of sending the scope cold. Puts a judgment into a gate that §3 states as mechanical.
- recommendation: A. It is the only option that removes the class instead of capping it, it matches the origin-shaped rules the script already has for hub stems and Godot assets, and on the observed diff it selects the 3 docs that name the changed constant. Its risk is the one thing unmeasured.
- settles by: a replay measurement, `phased build`. `replay.sh` needs (1) a per-origin split of the `hits` lane into code-origin and doc-origin terms, (2) an arm for each option beside `head`, (3) a fixture that reaches `3891bf41` — the pinned `mr` fixture is `c70a5c43`, 246 commits behind — and (4) for each doc an arm drops, the pair judgment the README already defines (pointer-only / restating / stale). Pass for A: the crossing rate on code-touching commits falls, and no dropped doc is stale against the commit's changed text. A stale drop found → B or C is weighed against it with that number in hand.


## Design — 2026-11-13

Settled by the replay measurement the Verdict's `settles by:` names — `bench/scope-replay/arms.sh`, results in `bench/scope-replay/results/arms-{commits,dropped,terms,summary,judged}.tsv` — not by a ruling. The measurement picks the `AB` arm over the Verdict's recommended A.

**Rule.** A changed path off the doc surface keeps its basename term. When that term alone hits more docs than the door's scope ceiling (8), the term is demoted to hub-stem matching — a bare token in a code span only, its path mentions no longer counting — and, where the path is a modified file, the symbol-shaped identifiers on its changed lines join the term list. Doc-origin terms, the ceiling, its unit and the other lanes are untouched.

- Demotion test: the term's own `hits --by-term` count, changed files included, is over 8. Only a term from a path off the doc surface can be demoted; a Godot asset term (`X.tscn`) never is.
- Added identifiers, for a demoted term's path with git status M only: maximal runs of `[A-Za-z0-9_]` starting with a letter or `_`, on the diff's `-` and `+` lines and on each hunk header's trailing context; length 4 or more; not in `term_generic`; symbol-shaped — holds `_`, a digit, or an uppercase letter after its first character. An added, deleted or renamed path adds none.
- The extraction stays mechanical: a fixed token shape, no judgment about which identifiers matter.

**Measured** (MR pinned `3891bf41`, this repo pinned `d25164e`, 30 commits each that change a term-yielding path off the doc surface):

- MR commits changing no doc (9): crossings 4 → 0 under `AB`, mean scope 8.6 → 3.4. MR commits that also change a doc (21): 21 → 21 crossings in every arm — their scope comes from the doc-origin lanes this card leaves closed.
- This repo: no term is demoted in 30 commits; `AB` equals `head` on every row.
- `AB` never widens a scope (0 of 60 commits). `A-all` widens 53 of 60; `A-shaped` widens 9 and drops the most docs (87 in MR, 58 here), which is why A alone is not taken.
- The observed commit `3891bf41`: 24 docs → 8, the three that name the changed constant among them.
- Staleness of what `AB` drops: 68 (commit, doc) pairs over 12 MR commits, all judged — 63 pointer-only, 5 restating an unchanged neighbouring fact, 0 stale.

**Limits.** One reader (Sonnet) judged the 68 pairs, with a gateway spot-check of the two nearest misses. Every demotion in the sample comes from one consumer repo and three terms (`game`, `ui-strings`, `audio`). A doc that narrates a hub file's changed behavior in prose, naming neither a changed identifier nor the bare stem, is no longer reached; `/super-bootstrap:check-docs-consistency` is the backstop.

**Steps.** (1) `doc-links.sh` + `tests/doc-links.test.sh`: the rule as one mode the door pipes the changed list through, test-first, with a parity run against the `AB` arm. (2) `commit/SKILL.md` §3 pipe, ceiling readout and the "Grep-gate is mechanical" rule line; `docs/decisions.md` rows `DEBT-94g6` and `BUG-et1c`; `bench/scope-replay/README.md` findings.
