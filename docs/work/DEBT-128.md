# DEBT-128 — § 2c's effect-keyed commit predicate names no baseline, and compares the receipt by bytes where it means recorded content

**Logged:** 2026-10-08 · **Source:** third cold `audit-harness-edits` pass on the `BUG-083` fix (verdict: sound as written, two minor findings + one open question)
**Problem:** § 2c's commit predicate now reads "If this run changed no bytes in any path of the stage list below — the receipt included, compared against its prior content — report no changes and skip the commit." Two residues. (1) **No baseline is named for the non-receipt stage-list paths.** The receipt has one — Phase 1 snapshots it, and § 2c's `placed` paragraph refers to "the Phase 1 snapshot" — but the other paths do not, so an executor checking "changed no bytes" falls back on either its own memory of what it wrote this run, or `git status`, which also reports pre-run dirt. Pre-run dirt is the exact case the predicate's own last sentence excludes, so the check and the exclusion lean on different grounds. (2) **The receipt compare is byte-level where the intent is recorded content.** The receipt is written as JSON by the executing agent and nothing in the file pins key order, whitespace, or array order, so a cosmetically re-serialized receipt over an otherwise identical sync reads as changed bytes and commits — a junk `chore: sync harness pipeline` on a no-op re-run.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § 2c (the predicate at the commit-decision line, and the receipt-write paragraph it compares against)
**Blast:** repo — plus every consumer repo's re-run, since the predicate decides whether the commit door is entered at all
**Prior:** The two residues may share one fix: naming the baseline per path class — what this run wrote or deleted for the placed paths, the Phase 1 snapshot for the receipt — would also be the place to say the receipt is compared by its recorded fields rather than its formatting. Held as a hypothesis; the audit prescribed them as separate fixes.

### Decision needed

- **Residue 1: what names the before-state for the non-receipt stage-list paths?**
  - (A) A run-start snapshot. Phase 1 records `git status --porcelain` plus a sha256 of each dirty stage-list path. At § 2c, the run's effect is the set of paths whose state differs from that snapshot. This is closed and mechanical, and pre-run dirt is excluded by construction. Cost: a new Phase 1 output, and an executor step on every run.
  - (B) The run's own write record, named explicitly: the stage-list paths this run's own write or delete calls touched, compared against their content before each call. Cost: zero new steps. The baseline is the executor's in-session action history, which an interrupted run loses (`533685c` already accepted that edge as noise-only).
  - Not offered: keying on sync-report resolution words (`updated` / `seeded` / …). The Scenario F v3 record explains why the byte key was chosen: it makes that vocabulary not load-bearing, and it avoids the closed-list omission GAP-084 measured.
  - recommendation: (B). It states the exact ground that arm v3's state block supplied, with no new machinery, and its failure mode (interrupted run) is already accepted. Move to (A) only if a bench arm without the baseline handed in fails under (B).
- **Residue 2: how does the receipt stay out of a formatting-only commit?**
  - (i) Pin a canonical serialization (key order, 2-space indent, `covered` in report-row order). The byte compare then stays valid. This reopens the closed `covered`-ordering row, so it requires the additive annotation the decisions header allows.
  - (ii) Compare by recorded content and write only on difference. § 2c compares `version`, `covered` and `declined` as sets and `placed` as a map against the pre-run receipt, which Phase 1 must then read whole. § 2c rewrites the file only when these differ, which replaces :579's "overwrites whole … even when every row is `✓ current`". The receipt then has no order-sensitive reader, so the closed row's ground holds again. Compare-without-conditional-write is not offered: on a field-equal skip it leaves a re-serialized receipt dirty in the tree, and that becomes the next run's pre-run dirt.
  - (iii) Change no prose for residue 2. Write a decisions row: cosmetic re-serialization is unobserved (0 of 8 whole-file rewrites), the same "unobserved gap" cut that rows 28/96 made. Annotate row 96: its ground died, but the verdict stands.
  - recommendation: (ii). It is the only option that is correct whatever the serializer does, and it removes the order-sensitive reader instead of governing it. It also answers residue 1's receipt half, because "pre-run receipt = the Phase 1 whole-file read" becomes the named baseline. Choose (iii) only if the gateway judges the incidence evidence enough to cut, as rows 28/96 did.
- settles by: `phased build` (a plan block, then dispatch). Extend `bench/rot-row-contract` with a Scenario G, pre-registered: the state block gives the executor tool-call history and a `git status` that includes pre-run dirt, but does NOT assert "no file was written by this run". ## Design — 2026-10-08 · both forks settled from the record, no user ruling needed

**Residue 2 — the receipt's byte compare → option (iii), cut as unobserved.** Settled by [`docs/decisions.md`](../decisions.md) rows 28 and 96, which are this repo's standing call on receipt-formatting risk: a hazard the receipt history does not show is not built against, and a conservative failure ceiling weighs the same way. The Verdict's own read supplies the evidence those rows ask for — the last 8 dogfood receipt commits each rewrote the whole file, and every diff is a content change, none a reorder or reformat. The ceiling is conservative in row 28's sense: the worst case is a visible `chore: sync harness pipeline` commit on a no-op re-run, not a silent miss. Option (ii) is the robust fix and stays on file as the route if the hazard appears; it changes the receipt-write behavior every lane leans on, which is the cost rows 28 and 96 each declined for an unobserved risk.

Row 96 owes an additive annotation, not a reopen: its ground — `covered`'s only readers are set operations — died when § 2c started comparing the receipt's bytes. Its verdict stands on the second ground this card supplies (unobserved, conservative ceiling), and its reopen condition narrows to the event that would show the hazard is real.

**Stated plainly, because it narrows the aim this card was grounded against:** the gateway-aligned aim included "a no-op re-run never commits on formatting alone". Option (iii) leaves that half unmet by design. The climb order puts closed forks above a gateway-aligned aim, and the aim was never user-confirmed, so the record wins; the user is told, not asked.

**Residue 1 — the missing baseline for non-receipt paths → settled by a RED, not by argument.** Scenario G in `bench/rot-row-contract/`, pre-registered before it runs. The state block gives the run's tool-call history and the pre-run dirt, and does **not** state the baseline as a fact — the gap the Verdict found in Scenario F, whose state block handed the executor "No file in the repo was written or modified by this run". Control red → land option (B), the run's own write and delete calls named as the record, against an arm on the same state. Control green → close residue 1 the way `DEBT-127` closed, with the read-out.
