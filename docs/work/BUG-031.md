# BUG-031 — doc-links.sh check treats link-shaped literals inside fenced code blocks as real links

**Logged:** 2026-08-08 · **Source:** GitHub issue #37 via `/pull-issue` (reported against 2.29.7 from a consuming repo)
**Problem:** `extract_links` (awk) scans every line for `[...](...)` with no fenced-code-block or inline-code-span exclusion, so a doc embedding markdown-link-shaped literals in a code fence (e.g. a re-runnable measurement snippet) produces a permanent false positive — every commit reports `N broken link(s)`, training the operator to ignore the check and burying real breaks. Confirmed by code read at HEAD: `doc-links.sh` carries no fence state.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` `extract_links`; frozen-asset contract — fix propagates via `/release`
**Prior:** Track fence state (``` toggle) in `extract_links`, skip lines inside fences and inline code spans. Verify: a fenced block containing a `[x](docs/missing.md)`-shaped literal passes `check`; a genuine broken link outside a fence still fails.
