### Root cause (verified)

`render-board.py:379-387` (`couple()`, hard-block pass) increments `target.fanout` once **per regex match** rather than once per (blocker, blocked) pair:

```python
for m in re.finditer(r"(?:blocked by|depends on|after)\s+((?:BUG|DEBT|GAP)-\d+)(?:\s+lands)?",
                     r.card.text, re.I):
    target = by_id.get(m.group(1).upper())
    if target and target is not r:
        r.hard_blocked = True
        target.fanout += 1          # ← per match, not per distinct target
```

`Card.text` (`render-board.py:129`) is the **whole card file**, so every restatement anywhere on the thread — origin block, Design, Plan, Progress, Verdict — feeds the same loop. The three alternations (`blocked by` / `depends on` / `after`) are exactly the multi-phrasing surface the card's repro exercises, and an append-only thread that re-states its blocker in a later block inflates by one per restatement. `r.hard_blocked = True` is idempotent, so the `pending unblock` footer count is correct; only `fanout` inflates.

Symptom follows: `fanout` is rendered verbatim as the `unblocks` column (`render-board.py:480`) and as the `(unblocks N)` suffix in `context_cell` (`:446` — discuss table + the macro-priors cells of empty sub-verb modes), and it is rank key 0 wherever the column renders (`sort_rows`, `:418-419`), so an inflated count also mis-orders the need-me groups.

**Not a lane-parity contract gap — script-only slip.** The spec SSOT is unambiguous and already says relationships: `agents/todo.md:130-136` — "`fanout(X)` = the count of **other open rows** that X unblocks", "**+1 per hard-blocked row that names X**". Per row, not per mention. The agent lane needs no change; the script diverges from a rule already codified.

**Family sweep — scopes to this one site.** The other `fanout` increment (`:404`, soft-coupling pass) already counts distinct rows: it iterates `for b in rows` and adds at most 1 per `b`. Cross-lane double-count is also impossible — the soft pass `continue`s on any `b.hard_blocked`, so a pair counted hard is never counted soft. `hard_blocked` (bool) and `held` (`sum(1 for r in rows if r.hard_blocked)`) are set-shaped already.
