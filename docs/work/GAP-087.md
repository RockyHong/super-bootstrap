# GAP-087 — Greenfield runway: mechanize the empty-repo path into a bundled script

**Logged:** 2026-09-23 · **Source:** GitHub issue #74 (via `/pull-issue`)
**Problem:** On a truly empty repo (no files, no manifest, no source), `/super-bootstrap` still runs the full model-driven runway: the model reads the harness-bootstrap SKILL.md plus ~40KB of skeleton assets, renders CLAUDE.md's conditional blocks by hand (drops Coding Principles / monorepo / scale / example-rule blocks), hand-assembles the sync report with every row `⊕ new`, builds the runway receipt + `placed` hashes, routes the commit through `/super-bootstrap:commit` (doc-sync judgment over freshly-copied skeletons), and seeds the three fixed GAP cards through `/super-bootstrap:log`. Every step on this path is deterministic — no drift, no legacy content, no user-owned sections, and the opt-in gates (drain infra, scale module) resolve to skip on an empty repo. Many tokens and turns reproduce a fixed output, and hand-rendering the templates (ad-hoc regex over `{…}` blocks) is the step most likely to drift from the skeleton. Verify: `/super-bootstrap` in an empty dir yields an output tree + receipt byte-identical to the current model-driven run in one script call; a re-run afterwards takes the normal sync path and reports all `✓ current`.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/` (Phase 1 detection, assets), `plugins/super-bootstrap/skills/super-bootstrap/`
**Prior:** Bundled script (e.g. `skills/harness-bootstrap/assets/scaffold-greenfield.py`) fired when Phase 1 detects empty/docs-only tree + no harness files + no receipt — copies verbatim assets, renders CLAUDE.md / techstack.md with docs-only + single-package + no-scale branches, writes `.claude/settings.json` (core pin + three hook snippets), copies hook scripts, appends `.gitignore`, writes the receipt (`version`, `covered`, `placed` sha256s) and cleanup-only `.claude/bootstrap.md`, seeds GAP-001..003 with the high-water bump, makes the two commits; the model path keeps everything with judgment (re-sync, legacy migration, code-present repos, forks).

## Verdict — surface · 2026-09-23

### Findings

- root cause: the premise holds in part and fails in part. The empty-repo path is mostly mechanical, but it is not deterministic end to end. Four things in it are not fixed output today:
  1. **Drain opt-in asks on every run.** `harness-bootstrap/SKILL.md:284-287` § 2a-drain says "Ask once: … Install now? (y / skip)" with no earn gate. Only the scale module is earn-gated (`:295-302`: ≥10 cards, drain infra, or a user ask). So on an empty repo the scale module skips silently but the drain prompt still fires. The card's "opt-in gates (drain infra, scale module) resolve to skip on an empty repo" is wrong for drain.
  2. **Two CLAUDE.md fields have no empty-repo rule.** `claude-md-skeleton.md:137` (`{detected one-line summary…}`, § Tech Stack) and `:149` (`{detected from scripts/Makefile/Cargo — only what exists right now}`, § Commands) have no docs-only rendering rule anywhere in SKILL.md (`:179`, `:531` cover fill-from-facts only). For `techstack.md`, `:355` says a docs-only repo keeps "the template's placeholder body", and `super-bootstrap/SKILL.md:30` relies on that placeholder text for its substantive check. CLAUDE.md has no such rule, so each model run improvises here.
  3. **Seeded card bodies are written by the model.** `super-bootstrap/SKILL.md:40-46` passes three fixed *observations* to `/super-bootstrap:log`. `log/SKILL.md:31` then has the model write H1 + `Problem:` + `Area:` ("capture the claim faithfully"). The H1 text is not fixed, yet the greenfield idempotency guard matches on it (`super-bootstrap/SKILL.md:38`). The log door's Mover gate (`log/SKILL.md:26`, "ask once") also sits on this path. The model can settle it here (the repo moves), but it is still a model step.
  4. **The "two commits" have no spec source.** § 2c makes one commit (`chore: scaffold harness pipeline`, `:650`). The greenfield branch (`super-bootstrap/SKILL.md:34-54`) seeds cards and stops, with no commit step, and § Disclosure's list of committing steps (`:70`) leaves out log seeding. The card's Prior ("makes the two commits") adds new behavior; it does not reproduce current behavior.
  Result: "byte-identical to the current model-driven run" has no stable target. The model run varies at items 2 and 3, so the check needs a golden fixture defined by spec, not a recorded run.
- Deterministic and scriptable today: git-init; the fixed-macro folders + `.gitkeep`s; verbatim copies (`decisions`, `work-readme`, `work-template`, `agents-md`, `rules-index` skeletons); `overview.md` (placeholders + `external-tools: [github]` harness-meta); `techstack.md` minus the § Packages block; CLAUDE.md block stripping for docs-only + single-package + no-scale + no-seeded-rules (the `{…}` removals `:533-536` spell out); `.claude/settings.json` fresh write (core pin `:245-258` + three `.hook.json` snippets); hook script copies + `.gitignore` `.claude/.consult-catalog`; `placed` sha256s (`hooks-ensure-infra.md:141-146`); the receipt's `covered` (a fixed list for this tier) and `declined: []`; the cleanup-only `.claude/bootstrap.md` (`:543-549`, `{project name}` / `{date}`); the high-water bump on seeded cards. `log/SKILL.md:11` sanctions a script writing the cards: "Hand-copying `docs/work/TEMPLATE.md` with the same high-water bump is the same door, by hand."
- Commit-door bypass is a policy question, not a technical one. `commit-channel` only fires on a bare `Bash(git *)` / `PowerShell(git *)` from a worker subagent (`:276`), so `python3 scaffold.py` calling git is not intercepted. But the § 2c commit route (`/super-bootstrap:commit`: doc-sync judgment + `doc-links.sh` link check) is where much of the token cost the card targets sits. Skipping it loses the link check unless the script runs `commit/assets/doc-links.sh` itself.
- Dialect / precedent: this work is JSON merge + sha256 + block rendering + tree write, a mechanical half that outgrew shell. `.claude/rules/asset-dialects.md` § Python mechanical-extraction therefore puts it in Python 3 via `python3 "${CLAUDE_PLUGIN_ROOT}/…"`, stdout = product, with a declared degrade path. Here the degrade path is simply the current model path, which stays. Precedent in this same skill: `assets/scale/split-outward.py` (deterministic, called from `SKILL.md:307`). Also `todo/assets/render-board.py` and `help/assets/render-menu.py` (the latter locked by `tests/render-menu.test.sh`). `hooks/runway-version.sh` is a plugin-owned hook, not a render precedent. No bash-only route: no jq guarantee (`runway-version.sh` header).
- Maintenance cost: the real risk is having two renderers. The script renders the greenfield tier while SKILL.md prose still makes the model render the same skeletons for code-present / monorepo / scale tiers. A skeleton edit then has to land correctly in both, and nothing enforces agreement. The cost is limited to the conditional-block mechanics (verbatim copies can't drift, since they read the asset live). It can be locked by a test that renders from the live skeletons and asserts against spec-derived expectations, not a frozen golden tree that goes stale on every skeleton edit.
- Aim: no overlapping open card (only `GAP-088`, an entry rename; a script would carry the entry name in seeded-card text and the handoff, a minor coupling). No closed fork in `docs/decisions.md` blocks this. Row 78 (a version-driven update/merge engine) rejects a re-sync engine, and a greenfield-only scaffold leaves re-sync to the § 2b drift walk, so row 78 doesn't apply.
- scope reach: `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` (Phase 1 greenfield detection + a script-fire branch, § 2a-drain gate, § 2b placeholder rule for CLAUDE.md Tech Stack / Commands on docs-only, § 2c commit); `plugins/super-bootstrap/skills/super-bootstrap/SKILL.md` (greenfield branch: seeded-card source + commit; idempotency guard's H1 match); new `harness-bootstrap/assets/scaffold-greenfield.py` + likely a pinned seed-card asset (three card bodies); new `tests/scaffold-greenfield.test.sh`; `docs/overview.md` Module Index / `plugins/super-bootstrap/README.md` if they list bundled assets; `docs/techstack.md` if it lists script assets. Shipped-skill edits are behavior-shaping, so `.claude/rules/skill-authoring.md` requires a RED first. No imported / served paths (all plugin-source).
- attempted: static read of both SKILL.md files, `log/SKILL.md` procedure, `hooks-ensure-infra.md` idempotency/placed mechanics, skeleton placeholders, `asset-dialects.md`, `decisions.md`. Stopped at surface: the premise has spec gaps (items 2-4) that need design settling before a byte-identity target exists, plus scope and commit-route forks.

### Decision needed

- Feasibility: **feasible, bounded.** About 80% of the empty-repo output is already byte-determinable from assets + spec. The rest needs three spec settlements, and the script must not become a second renderer that drifts. The question is its scope and its seams.
- Options (scope of the script):
  - **A. Greenfield-only scaffold script.** Fires on empty tree + no harness files + no receipt, owns the whole tier; the model path stays the only renderer for every other tier. Cheapest to build, but leaves two renderers of the same `{…}` blocks, guarded only by a test.
  - **B. Shared mechanical renderer + greenfield driver.** `scaffold.py render --code-present=0 --monorepo=0 --scale=0 --rules=…` strips and keeps conditional blocks from the live skeletons for *every* tier; the model path calls it for block mechanics and keeps fact-filling and all judgment; a `greenfield` subcommand chains render + place + settings + hooks + receipt + seed cards. One renderer, less drift; bigger build, and it touches the code-present path.
  - **C. Don't build.** Instead pin the three spec gaps in prose (drain earn-gate or explicit greenfield answer, CLAUDE.md docs-only placeholder rule, fixed seed-card bodies) so the model run is at least spec-deterministic. Removes the drift risk the card names, but not the token cost.
- Sub-forks, whichever option:
  - (i) Drain on an empty repo: add a greenfield earn gate (skip silently, like the scale module; drain self-installs on first use per `:291`), or keep asking model-side and pass `--drain y|skip`. Lean: earn-gate it, since `:286`'s own prompt text says docs repos skip.
  - (ii) CLAUDE.md § Tech Stack / § Commands on docs-only: keep the skeleton placeholder (matches `techstack.md` `:355`) or a fixed "none yet" line. Lean: keep the placeholder, one rule for both docs.
  - (iii) Seeded cards: pin their bodies as an asset (H1 = the idempotency-guard key) written by the script with the high-water bump, or keep dispatching `/super-bootstrap:log`. Lean: pin (it fixes guard fragility too).
  - (iv) Commit: script commits directly after running `doc-links.sh check`, or script stages and the model fires `/super-bootstrap:commit`. Also: seed cards join the scaffold commit, get their own, or stay uncommitted (today's unspecified state).
- recommendation: **B**, with (i) earn-gate, (ii) placeholder, (iii) pin, (iv) script commits after `doc-links.sh` in two commits (scaffold, then seed cards). B is the only option that removes the drift risk the card names rather than moving it. Settling (i)-(iii) first also makes today's model path deterministic, so C's benefit comes free on the way. If B's reach into the code-present path is unwanted now, A plus a render test against the live skeletons is the fallback.
- settles by: (i)/(ii)/(iii) are harness-internal settlements the spec can decide: `harness-bootstrap/SKILL.md` § 2a-drain / § Placeholders and `super-bootstrap/SKILL.md` § Greenfield branch, author's pick. (iv) and A-vs-B are harness design calls: preference (the author's taste on the commit-route single-door principle vs token cost, and on build scope). The token/turn saving that justifies the build is measurable as a **dispatched probe**: one cold model-driven `/super-bootstrap` in an empty temp dir, turns + tokens read from its transcript, against a projected 2-3 turns for the script path. Once picked, the build is **phased build**: a `## Design` + `## Plan` block on this card, a RED on the SKILL.md prose edits, then dispatch; test via a new `tests/scaffold-greenfield.test.sh` rendering into a temp dir (unit-testable, e2e for the "re-run reads all ✓ current" leg).

## Design — 2026-09-23

User pick: phased **C → measure → B**. Phase C makes the model-driven greenfield path spec-deterministic (the precondition any script needs); a measured cold run then decides whether B (shared renderer + greenfield driver) earns its build. Sub-fork (iv) — commit route and seed-card commit — defers to the B decision.

- (i) § 2a-drain earn-gate: on a docs-only repo (Phase 1 code presence = none) the drain prompt skips silently, the way the scale module does; drain self-installs on first use.
- (ii) § 2b placeholder rule extends to CLAUDE.md: on a docs-only repo, § Tech Stack's one-liner and § Commands keep the skeleton placeholder body verbatim — one rule shared with `techstack.md`.
- (iii) Seed cards pinned as an asset in the entry skill: the three card bodies fixed (H1 = the idempotency-guard key, `Problem:` / `Area:` / `Prior:` split fixed), `{ID}` / `{date}` the only fills; written by the sanctioned hand-copy path with the high-water bump, not re-phrased through `/super-bootstrap:log`.
