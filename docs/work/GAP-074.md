# GAP-074 — harness-bootstrap: a re-run after code arrives on a docs-only repo never refreshes manifest-derived facts

**Logged:** 2026-09-10 · **Source:** GAP-073 verify run (cold executor on a docs-only fixture, then `package.json` added and re-run)
**Problem:** On the re-run, the code-touch pair rose as `⊕ new` (GAP-073's contract), but the manifest-derived facts stayed at their docs-only values: CLAUDE.md's Tech Stack one-liner is § Project-owned ("never touched, even on drift") while § 2b Placeholders says manifest facts fill it — so the executor left it reading "Docs-only repository — no runtime or build stack" with a manifest present, and doc-sync's write boundary excludes CLAUDE.md, so no other door refreshes it. `docs/techstack.md` § Runtime / Key Dependencies / Build & Distribution likewise have no stated re-derive path — "drift" means template-shape mismatch, not stale detected facts; the executor re-detected and presented them as drift by inference. Decide: a fact-refresh lane on re-run when Phase 1 detection changes (docs-only → code present, or a new manifest), or an explicit "hand-refresh" statement.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § Pipeline-owned / § Project-owned (Tech Stack one-liner), § 2b Placeholders, § 2b per-doc handling (drift = template shape)
**Prior:** Ownership split assumes detection facts are stable across runs; the code-presence transition is the first case where they legitimately change.
**Test-feel:** manual · **Blast:** pkg

## Verdict — surface · 2026-09-10

### Findings

- root cause: two distinct mechanisms, both confirmed by direct read of `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md`.
  1. **CLAUDE.md Tech Stack one-liner — never visited on a re-run.** The § Pipeline-owned CLAUDE.md section list (line 147) names Development Workflow, Dispatch, Doc Sync, Coding Principles, Edit Discipline, Context Hygiene, Finding Triage, Rules, Git Notes, Planning, Monorepo — **Tech Stack is absent**. Line 161 puts it under § Project-owned ("never touched, even on drift"). So the 2b drift walk emits no row for it, the § 2c gate (line 537, a set-difference against § Pipeline-owned) never demands one, and the receipt's `covered` never lists it. The only write path is the § 2b Placeholders bullet (line 485, "Manifest detection facts … fill into CLAUDE.md Tech Stack one-liner"), which fires solely on the per-doc `Missing → fill placeholders, write` branch (line 330) — a branch a re-run against an existing CLAUDE.md cannot take. Not a contradiction between the two clauses as the origin block frames it: they compose to **fill-once-then-frozen**. The defect is the missing re-fill trigger, not a conflict.
  2. **`docs/techstack.md` § Runtime / Framework / Key Dependencies / Build & Distribution — drift-checked against the wrong referent.** These four *are* pipeline-owned (line 148) and do earn rows, but line 331 fixes the comparison as "diff that section vs template" — the template being `assets/techstack-skeleton.md`, whose bodies are placeholders (`{detected from primary manifest — …}`). On a docs-only first run those sections are written **as the unfilled skeleton** (line 325: "On greenfield (no manifest, no source files), `overview.md` / `techstack.md` write as unfilled skeletons — manifest-derived facts fill only when code is present"), so the re-run's section-vs-template diff returns `✓ matches` and the placeholder is preserved, not filled. Zero occurrences of `re-detect` / `re-derive` / `refresh` applied to detection facts anywhere in the skill tree — the freshness comparison the card asks for has no referent in the walk.
- scope reach (larger than the card states): mechanism 2 is not confined to the docs-only→code transition. On **any** code repo, once these four sections carry detected facts they permanently differ from the placeholder template, so a literal read of line 331 makes each re-run emit `⚠ drifted` whose only defined resolution is writing the placeholder back. `assets/techstack-skeleton.md` line 3 calls them "seeded at scaffold from detected facts; Edit Discipline, fixed prose" — a seed-once vs fixed-prose distinction the SKILL's own ownership lists and drift rule never carry. Whatever shape settles this card should settle that classification too, or explicitly scope itself to the transition.
- adjacent constraint, not a supersession: [`docs/decisions.md`](../decisions.md) row "A version-driven update/merge engine for the bootstrapped runway" closed that direction on the ground that "`harness-bootstrap` re-run already re-syncs — the Phase 2b per-section drift check preserves user edits", shipping "the earned residual instead: a version stamp + a stale-stamp guard". This card does **not** re-walk it (its trigger is a detection delta, not version-keyed migrations) — but that row's ground is exactly what mechanism 2 falsifies for detected facts, and it bounds the option set: any fix must stay stamp-and-check-shaped, not grow an engine.
- detection signal already exists, free: the receipt `.claude/super-bootstrap-runway.json` `covered` list omits § Coding Principles + `CODING_STANDARDS.md` on a docs-only run (Phase 1 § Code presence, line 32). Last-run-saw-docs-only vs this-run-sees-code is therefore readable at Phase 1 with no new state, from the artifact Phase 1 already reads.
- partial hand route already shipped: `/super-bootstrap`'s greenfield branch seeds a `decide techstack` GAP card whose text already says "manifest facts auto-filled where a manifest exists". It covers the transition only while that card is still open — once the consumer resolves and deletes it, the entry's substantive-check reads the docs-only prose as substantive and routes to tier-2 curation, never re-detecting.
- attempted: full read of SKILL.md § Phase 1 (code presence, greenfield, version-staleness), § per-artifact rule, § Pipeline-owned / § Project-owned, § 2b per-doc handling + Placeholders, § 2c gate + receipt write; `techstack-skeleton.md`, `claude-md-skeleton.md` § Tech Stack; grep of the whole plugin for `Tech Stack one-lin` (2 hits, both in SKILL.md), for refresh/re-derive vocabulary (0 relevant hits), and of `docs/decisions.md` for the adjacent closed forks. Duplicate check: `DEBT-112` is a different precedence question (2a-scale marker guard vs drift), `GAP-072` / `BUG-059` / `BUG-060` unrelated — no open card overlaps. Provenance: every touched path is this repo's own plugin source, no served/imported copy in the fix surface. Stopped at the fork because the answer changes the runway's ownership contract.

### Decision needed

- May the runway ever **write** manifest-derived facts into a repo on re-run — and if so, does that write reach CLAUDE.md § Tech Stack, a section § Project-owned currently declares untouchable?
- Options:
  - **A — refresh lane (pipeline writes).** Phase 1 computes a detection delta (receipt `covered` vs current code-presence / root manifests); non-empty → 2b re-derives the four `techstack.md` skeleton sections and the CLAUDE.md one-liner, emitting `⚠ stale facts` rows through the normal Block 2 per-section approval. Requires carving the Tech Stack one-liner out of § Project-owned as a named exception and giving the four techstack sections a stated seed-once-plus-refresh semantic distinct from template-shape drift.
  - **B — advisory lane (pipeline detects, consumer writes).** Same Phase 1 delta, no write: SKILL.md states detected facts are seed-once, and Phase 3 handoff prints a stale-facts advisory naming the exact sections plus the hand route. § Project-owned stays intact; the four techstack sections get the seed-once classification so their drift row reads shape-only, closing the broader scope-reach finding as well.
  - **C — documentation only.** No detection, no advisory: state the seed-once semantics in SKILL.md and the skeleton comment, and lean on the existing `/super-bootstrap` `decide techstack` card lane as the refresh route. Cheapest; leaves the resolved-and-deleted-card case silently stale.
- recommendation: **B** — it supplies the one thing actually missing (a signal that the facts went stale) without granting the runway a write into project-owned CLAUDE.md content, and it is the same stamp-and-forced-check residual shape the decisions row above already blessed, where A drifts toward the engine that row rejected. B also has room to carry the seed-once classification that fixes the broader family, which C leaves open.
- settles by: the repo author's design call — no decisions row or spec settles whether § Project-owned admits an exception, and `docs/specs/harness-architecture.md` § 8 records only the migration shapes, not fact freshness. Not measurable in this lane; the closest empirical input is a `dispatched probe` re-running the GAP-073 docs-only fixture to observe what a cold executor does at the re-run with each shape stated, which prices the ambiguity but does not decide the ownership question. Verify for whichever shape lands is manual (fixture bootstrap, then manifest + re-run) — the GAP-073 run showed headless `claude -p --plugin-dir` produces no output for this skill.

## Design — 2026-09-10

Ruling: **B — advisory lane.** Phase 1 reads the receipt's `covered` list beside this run's code-presence / root-manifest detection and computes a detection delta; a non-empty delta surfaces at Phase 3 as a stale-facts advisory naming the exact sections (CLAUDE.md § Tech Stack one-liner; `docs/techstack.md` § Runtime / Framework / Key Dependencies / Build & Distribution) and the hand route. The runway writes none of them: § Project-owned keeps the Tech Stack one-liner; the four techstack sections take a stated seed-once classification — seeded from detected facts at first fill, drift-checked for shape only thereafter — which also closes the verdict's scope-reach finding (a filled section is not `⚠ drifted` against the placeholder template). A refresh lane that writes (A) was rejected as the engine shape [`docs/decisions.md`](../decisions.md) row "A version-driven update/merge engine" closed; documentation-only (C) leaves the deleted-card case silently stale. Verify is manual on the GAP-073 docs-only fixture.
