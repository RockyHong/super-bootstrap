# BUG-042 — doc-links.sh fence detection may not survive macOS awk

**Logged:** 2026-08-25 · **Source:** BUG-040's triage parked the interval half as unverifiable from this box; claude-config-manager's BUG-038 then measured the sibling construct
**Problem:** `extract_links`' fence guard tests `` /^[[:space:]]*(`{3,}|~{3,})/ `` — one regex carrying both a POSIX character class and interval expressions. claude-config-manager records, from its own macOS work, that "older one-true-awk builds carry no POSIX classes" and rewrote a parser to `[ \t]` on that ground; interval support in the same builds is the other half BUG-040's triage could not check. If either construct fails, the fence toggle never fires and every path-like literal inside a fenced code block reports as a broken link again — the exact defect GitHub issue #37 closed, back on macOS only. That would land on top of a checker whose anchor half was just fixed, so the noise would read as a fresh regression rather than an untouched second cause.
**Area:** [`plugins/super-bootstrap/skills/commit/assets/doc-links.sh`](../../plugins/super-bootstrap/skills/commit/assets/doc-links.sh) — `extract_links`, the fence-toggle line inside the second `awk` program
**Prior:** Premise is unverified here: no BSD/one-true-awk available, and GNU awk accepts both constructs, so no local run can separate them. Verification needs either a macOS run or a build whose awk matches. If confirmed, the shape mirrors upstream's fix — drop the POSIX class for an explicit `[ \t]` set, and replace the intervals with a spelled-out three-character prefix match. Cheap either way; the cost is the evidence, not the edit.
