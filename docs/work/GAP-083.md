# GAP-083 — a declined rot row leaves no trace the next sync reads

**Logged:** 2026-09-21 · **Source:** residual surfaced by the cold triage of `DEBT-116`, which recommended a separate card rather than folding it into that fix
**Problem:** [`harness-bootstrap`](../../plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md) § 2c sources the runway receipt's `declined` from per-section drift rows and the missing-on-mature advisory only; rot rows are never enumerated there, and the `previously declined:` line renders only when the prior receipt's `declined` carries the row's own section. So a rot row the consumer declines leaves nothing the next sync can read — the 2.51.0 → 2.51.1 decline survives only in commit `9493622`'s message. The sibling card `DEBT-116` removes the recurring frozen-provenance rows, so that symptom clears, but the memory gap survives for every rot row a consumer legitimately declines on non-frozen grounds — the referent-ambiguity case [`rename-map.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/assets/rename-map.md) § Scan guidance already names, where the `old` literal belongs to another plugin's command. That consumer re-decides the same row every re-run with no signal that they already ruled on it.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § 2c receipt (`declined` sourcing) + § 2b rot-row acceptance
**Prior:** Suspected shape (not settled) — rot rows need a receipt identity to be remembered by, and a rot row is keyed by `{file, old literal}` rather than by a section, so the receipt's section-keyed `declined` shape may not hold them as-is.
**Test-feel:** doc-only
**Blast:** pkg

## Verdict — surface · 2026-09-21

### Findings

- **root cause — confirmed, one level deeper than the card frames it.** The rot lane never joined the sync-report row-resolution contract § 2b / § 2c apply to every other row class. The memory gap is the third of three holes, all downstream of that one omission:
  - `SKILL.md:468` — acceptance is `y / n / per-row`, no reason capture. The section lane's rule (`n — {reason}`, bare `n` re-prompts, `SKILL.md:455`) has no rot counterpart, so a rot decline produces no reason to remember.
  - `SKILL.md:568` (2c gate) — the resolution requirement enumerates `⚠ drifted`, `⊕ new`, `⊘ missing` only. A rot row is specified with no resolution column at all (`SKILL.md:461–468` defines it as `{file}:{line} — stale literal … Reason: {map entry reason}` — the map's reason, not the decline's), so the gate does not halt on an unresolved rot row and 2c can commit over one.
  - `SKILL.md:583` (receipt write) — the `declined` sources are enumerated exhaustively: "a drift kept or an insert declined at Block 2, a re-seed skipped at the missing-on-mature advisory … For those two the report is the receipt's sole source." Rot rows fall outside that enumeration, so no rot decline reaches the receipt; `SKILL.md:455`'s render then omits `previously declined:` for want of an entry. The card's premise holds verbatim on both clauses.
- **exemplar refuted.** The card's named instance — referent ambiguity — is answered upstream, not here. [`assets/rename-map.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/assets/rename-map.md) § Scan guidance: *"Read the hit's line: propose migration when the surrounding prose means the bundled skill, and leave the line when it means the other tool."* Spec intent is that **no row is raised** for that case — the consumer never re-decides it; what re-derives silently per run is the scan's own referent judgment. With `fd9623e` (DEBT-116) removing the frozen-provenance source, the card's population of observed recurrences is empty. The mechanism gap is real; its named driver is not.
- **Prior settled from repo sources — no user ruling needed on shape.** `BUG-061` (`ab6c4be`) is the same root cause in the missing-on-mature lane, and its fix is the precedent: that lane was not given a new receipt key or an off-`covered` entry — it was made to **emit a proper sync-report row in the existing verdict enum with the existing resolution vocabulary** (`⊘ missing` / `declined ({reason})`, `SKILL.md:509`), so `covered` + `declined` stay mechanically derived and the `declined` ⊆ `covered` invariant (`SKILL.md:101`) holds. A rot row takes receipt memory the same way. The card's worry that a section-keyed `declined` cannot hold it is answered: `section` is already a free-form row-identity string (`{file} § {Section}`, whole-file artifacts by path), so a third identity form is a vocabulary extension, not a shape change — and adding no new key leaves `hooks-ensure-infra.md:145` / `drain/assets/ensure-infra.md:56` ("leaving `version` / `covered` / `declined` as found") untouched.
- **residual the Prior did not reach — identity granularity.** The card proposes `{file, old literal}`; the surfaced row is `{file}:{line}`. Line numbers shift between runs, so a line-bearing key cannot match across runs — the card is right to drop it. But § Scan guidance contemplates multi-hit files ("One repo can carry hits across multiple `old` forms in the same file… Surface each independently"), and one `old` literal can also hit several lines in one file. A `{file, old}` key therefore collapses those hits: declining one line's hit suppresses the memory line for every other hit of the same literal in that file. Not settled by precedent; it rides whichever option below is picked.

### Decision needed

- **Is a rot row a first-class sync-report row, or a transient per-run proposal?** It is currently the only row class outside the produce-then-judge contract, and that one answer sets both whether GAP-083 is built and its entire shape.
- Options:
  - **A — first-class (full).** Rot rows join the contract, the `BUG-061` move applied to the second off-contract lane: the prompt takes `n — {reason}` (bare `n` re-prompts), the report row records `migrated` / `declined ({reason})`, the § 2c gate's resolution enumeration gains the rot class, § 2c derives the row into `covered` + `declined` under a rot row identity, and the rot-scan surface block gains the `previously declined:` line on the same render rule. No new receipt key; the subset invariant is preserved. Settles the granularity residual as part of the identity spelling.
  - **B — transient (no diff).** Rot rows stay a per-run proposal outside the receipt. Close GAP-083 with a [`docs/decisions.md`](../decisions.md) row recording that rot-decline memory is out of scope — § Scan guidance's referent filter is the intended answer to the card's named recurrence, and `fd9623e` removed the other source, so the remaining population is unobserved.
  - **C — narrow (consistency only).** Capture the decline reason in the report row and extend the § 2c gate to halt on an unresolved rot row; write nothing to the receipt. Closes the forcing-function hole at the lowest cost and touches no cross-run contract — but leaves the card's actual ask (memory across runs) unbuilt, so GAP-083 does not resolve on it.
- recommendation: **A** — the identity question is settled by precedent, the cost is four prose clauses, and it removes the last enumerated-by-exception row class, making the produce-then-judge architecture uniform rather than list-maintained. The refuted exemplar weakens the urgency, not the correctness. ## Design — 2026-09-21

**Ruling: option A — rot rows become first-class sync-report rows.** The owner ruled the leverage fork the verdict surfaced; the correctness half was already settled by the `BUG-061` precedent, so this block records the pick and the shape it locks.

- **Acceptance** (`SKILL.md` § 2b rot scan) — the rot prompt takes `n — {reason}` on one line, a bare `n` re-prompts for the reason before the row resolves. Same rule the section lane already carries.
- **Report row** — a rot row gains a resolution: `migrated` or `declined ({reason})`, so it enters the produce-then-judge contract every other row class already obeys.
- **§ 2c gate** — the resolution enumeration gains the rot class, so an unresolved rot row halts the commit the way a drifted section does.
- **§ 2c receipt** — the derivation gains rot rows as a `declined` source. **No new receipt key**: `covered` and `declined` stay mechanically derived and the `declined` ⊆ `covered` invariant (`SKILL.md:101`) holds, which is what leaves `hooks-ensure-infra.md:145` and `drain/assets/ensure-infra.md:56` untouched.
- **Row identity** — `{file} § rot:{old}`. The surfaced row is `{file}:{line}`, but line numbers shift between runs, so a line-bearing key can never match across runs. `section` is already a free-form row-identity string, so this is a vocabulary extension rather than a shape change.
- **Granularity residual, settled here.** A `{file, old}` key collapses several hits of one literal in one file. That is benign because the memory render is advisory only — the section lane's own rule binds it: "the row still takes its full read-and-compare and its own Block 2 answer". A collapsed key widens the context a row displays; it never suppresses a prompt or auto-resolves a row.

**Sequencing note carried from the verdict.** [`docs/test-queue.md`](../test-queue.md)'s `GAP-072` item has an unverified tail — whether a re-run actually renders the `previously declined:` line in the lane that already has it. This build extends that render to a second lane, so the e2e confirmation for both belongs in one scratch-repo run; queue it rather than claiming it.

## Amendment — 2026-09-21 · cold dry-run of the § 2c receipt contract

The Design block's granularity ruling was wrong where it mattered, and the cold dry-run found it: a fresh agent handed the shipped § 2c receipt paragraph plus a sync report carrying two hits of one literal in one file — one declined, one migrated — produced a receipt with the identity `{file} § rot:{old}` appearing twice in `covered` under contradictory outcomes, and an entry in `declined` the sibling row's `migrated` refutes. The ruling's "collapsed hits share one memory line, which is benign" reasoning covers the **render** only; it never covered the **receipt**, where one identity must carry one outcome.

**Corrected, and this supersedes the Design block's granularity clause:** the collapse is removed at its source rather than reasoned around. One rot row covers one `old` literal in one file, lists every line it hits for display, and takes a single answer — so the row and its identity are one to one and no identity can carry two outcomes. Grouping is sound because [`rename-map.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/assets/rename-map.md) § Scan guidance already resolves the referent per line before a row exists: a line meaning another tool is left alone rather than raised, so every line inside a surfaced row was judged migratable. That section's "surface each independently" governs multiple `old` forms in one file, which remain separate rows with separate identities.

The same run fixed one smaller ambiguity: the identity spells the literal as a bare token, since the report renders it in backticks and the spec had not said whether they belong to the key.

The dry-run's remaining findings are pre-existing looseness in the receipt spec, untouched by this card and carded separately as `GAP-084`.
