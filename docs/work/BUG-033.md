# BUG-033 — `/super-bootstrap:help` silently drops every plugin that nests skills in category subfolders

**Logged:** 2026-08-09 · **Source:** live run of `/super-bootstrap:help` in this repo while wiring the mattpocock per-repo setup
**Problem:** `render-menu.py` walks one directory level only — `skills/<name>/SKILL.md`. A plugin that groups its skills into category subfolders (`skills/<category>/<name>/SKILL.md`) yields no readable frontmatter at that depth, so every one of its commands is dropped from the rendered menu. Observed live: `mattpocock-skills@mattpocock` ships 25 manifest-registered skills and the script emits `mattpocock-skills@mattpocock (0 skills)`, rendering none. The failure is silent to the user — the only signal is the `(0 skills)` count inside the `# sources:` comment line, which the render step does not surface. Blast radius is every downstream repo with super-bootstrap installed: discovery dies for any nested-layout plugin, and the user sees a menu that looks complete.
**Area:** `plugins/super-bootstrap/skills/help/assets/render-menu.py` (lines 69-70: `os.listdir(skills_dir)` + `join(skills_dir, skill, "SKILL.md")`); the layout claim in its header comment (line 8) and in `plugins/super-bootstrap/skills/help/SKILL.md`; `tests/render-menu.test.sh`
**Prior:** Recurse for `SKILL.md` under the plugin's `skills/` root instead of assuming depth 1 — a bounded walk, since a skill directory is identified by containing `SKILL.md`, not by its depth. Whether a zero-row plugin should also surface a visible warning is a separate call for triage.
