# BUG-041 — agent-model-pretool.sh pin extraction dies on BSD sed (macOS)

**Logged:** 2026-08-25 · **Source:** family sweep during BUG-040 triage (cold `triage` agent, 2026-08-25)
**Problem:** `extract_pin()` reads an agent file's frontmatter `model:` pin with a sed address carrying `\+`, a GNU BRE extension. POSIX BRE (BSD sed, what macOS ships) reads `\+` as a literal `+`, so the address only matches a `model:` line whose value has a literal `+` one character in — effectively never. On macOS the pin is never found, `extract_pin` returns 1, and the hook's model-routing decision runs as if every agent file were frontmatter-less.
**Area:** `.claude/hooks/agent-model-pretool.sh:49` — dogfood-only; grep confirms the hook is referenced solely by `.claude/settings.json`, never staged into a consumer repo by `harness-bootstrap`, so no shipped surface and no `/release` propagation.
**Prior:** Same one-line class as BUG-040 — rewrite the address's `.\+` in a dialect-neutral form. Kept out of BUG-040's diff deliberately (cold triage's call: different output class, separate concern, atomic-commit boundary).
