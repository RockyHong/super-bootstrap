# DEBT-022 — todo subagent classify+render pass not right-sized to working-set size

**Logged:** 2026-07-25 · **Source:** GitHub issue #25 (downstream adopter claude-config-manager, absorbed via /pull-issue)
**Problem:** `/super-bootstrap:todo` dispatches a subagent that re-classifies every open row from scratch on every invocation, regardless of working-set size. Observed on sb 2.24.1 with 4 open rows / 3-row need-me board (one venue group): ~34.3k subagent tokens / ~226s per bare dispatch. The full classify pass ran over every row; no computation reuse between invokes. The board is intended as a frequent, low-stakes glance; per-glance cost is disproportionate to a small working set.
**Area:** `agents/todo.md`; `plugins/super-bootstrap/skills/todo/**`
**Prior:** Right-size the classify+render work to actual working-set size — skip or shorten classify phases when row count is small.

## Verdict — surface · 2026-08-02

### Findings

- **root cause: phase ordering, not row count.** `shared/classify-actionable.md` self-contradicts on when the expensive phase runs. § Action-verb intent map (line 51) states it is "applied FIRST after the Harness pre-filter" and "Intent is determined by action verb before path/state rules" — locking `intent` for 14 of its 16 verb rows with zero file reads. § Cloud-safe criterion (line 29) states the opposite scope — "Single positive rule applied to **every row** before bucketing" — and sits physically *above* the verb map, so a reading agent runs it first. Inside it, the derivation inputs are numbered worst-first: **#1** grep the card's latest `## Plan` body for device keywords + path arms, **#2** read the `## Design` block's success criteria, **#3** the phase verb — which is the cheap discriminator that already decides `Write plan` / `Approve design` / `Triage` / `Extract` / `Doc-edit` "regardless of paths." An origin-only card (`Triage`, the dominant row shape in a small working set) therefore greps a Plan block that does not exist and reads a Design block that does not exist before reaching input #3, which locks it cloud-safe unconditionally.
- **the same short-circuit is missing for Harness rows.** § Harness pre-filter is headed "applied before everything" and notes consumers gating on `intent == Cloud` "exclude Harness rows for free" — `skills/drain/assets/eligibility.md:12` confirms it (`if item.intent == "Harness": return false` fires ahead of both the venue and Cloud gates). But the spec never says the pre-filter *skips* the cloud-safe derivation, and "every row" is unqualified. `agents/todo.md:119` has the same shape on the Blast axis — it instructs the `Area:` read + Plan-path widening first, then states "Harness rows always take Blast `repo`" as an afterthought. For a repo whose product *is* Claude configuration (the reporting adopter, claude-config-manager — commit `85ad8e8` extended the pre-filter to exactly that layout), the pre-filter catches nearly every card and every downstream derivation is provably dead work: intent locked, lane locked (`intent: Harness` wins over venue), group locked (`harness`), Blast locked (`repo`), Impact locked by the `Deliberate:`/`Apply:` rows of §3. That matches the reported board — 3 need-me rows in **one** venue group.
- **the card's own number falsifies its axis.** 4 rows carry ~1.5k tokens of card text total (`docs/work/` cards measure ~0.9–2.8 KB each). The pass cost 34.3k — ~8.6k per row, ~23× the row's own content. Row count is not the multiplier; **per-row derived-read depth** is. Gating phases on "row count is small" (the Prior) leaves the multiplier untouched — a 2-row board with deep breadcrumbs still pays it.
- **second cost center, untouched by the above:** `agents/todo.md:125` § 4 coupling gate — "Trace each row's breadcrumbs — `Area:` field, `Problem:` text, paths its appended blocks name — **into docs/code**" — unbounded repo reads per row, per invoke. Its own text says the hard-block edge needs "explicit naming … the named target resolves to an open row or it doesn't" (a grep over card text, no repo trace); only the *soft* edge needs artifact tracing, and soft coupling buys one local rank adjacency plus an Impact lift. The expensive half funds the cheap product.
- **third: a fixed instruction floor row-count gating cannot reach.** ~32 KB ≈ 8k tokens land before the first card is read — `agents/todo.md` 16,875 B + `shared/classify-actionable.md` 12,481 B (self-read at classify time) + the needme scaffold + dispatch template. Corroborating direct measurement from the family: `DEBT-030` records the sibling `log` agent at 23.3k tokens for **1** entry vs 35.3k for **9** — fixed ≈ 21.8k, marginal ≈ 1.5k/entry. These Sonnet classify subagents are fixed-floor dominated at small N.
- **"no computation reuse between invokes" is accurate as an observation, closed as a fix direction.** A cross-invoke cache requires a write; `agents/todo.md:4` grants `tools: Read, Grep, Glob` and line 201 + `skills/todo/SKILL.md:97` both state "Read-only. Never modifies files." Reuse is not a right-sizing tweak — it is a write-grant decision plus cache invalidation against append-only cards.
- **scope reach:** `plugins/super-bootstrap/shared/classify-actionable.md` (§ Harness pre-filter, § Cloud-safe criterion, § Action-verb intent map) — a spec shared by `todo` **and** `drain`; `plugins/super-bootstrap/agents/todo.md` §§1, 3, 4; `plugins/super-bootstrap/skills/drain/assets/eligibility.md` (admission predicate). Sibling cards on the same surface: `DEBT-027` (owns the cloud-safe phase), `DEBT-030` (same disproportion in `log`).
- **attempted:** static trace of the full needme path — dispatch template → scaffold consumption → agent protocol §§1–6 → shared spec → drain's gate. Stopped at the verdict rather than the fix: the fix touches a two-consumer contract, `DEBT-027` already holds the open question "does the derivation earn that cost?" with a hard constraint ("any retirement must replace drain's admission predicate in the same change"), and the sizing question is a fork the trace narrows but does not close. No probes — `docs/techstack.md` carries no § Probes table.

### Decision needed

- **Which cost axis does DEBT-022 buy, and does it collapse into DEBT-027?** The trace says the card's stated axis (row count) is the wrong one, so the scope must be re-cut before any edit.
- Options:
  - **A — Reorder the derivation; keep every phase.** In `classify-actionable.md`: promote the phase-verb check to derivation input #1, state explicitly that the Harness pre-filter and the verb map's locked rows exit before any content read, and reconcile "every row before bucketing" against "applied FIRST after the Harness pre-filter." Same classification outcomes, most derived reads gone. No contract change — drain's predicate is untouched, so `DEBT-027`'s hard constraint never binds.
  - **B — Retire the cloud-safe derivation** (`DEBT-027`'s shape: verb-map-only intent, defaults for the two `(derive)` rows). Larger cut, but drain's admission predicate must be replaced in the same change.
  - **C — Attack the fixed floor.** Restructure `agents/todo.md` (16.9 KB) + `classify-actionable.md` (12.5 KB) for load cost. Reaches the term A and B cannot, but it is a harness-architecture rewrite with repo-wide blast.
  - **D — Cross-invoke reuse** (the card's literal "no computation reuse"). Requires granting the read-only `todo` agent a write surface plus cache invalidation. Recorded as closed unless the read-only rule is deliberately reopened.
- recommendation: **A**, with the card re-cut rather than collapsed. A is the largest cut per unit of risk and needs no contract change; `DEBT-027` already owns that phase, so A executes there. DEBT-022 then narrows by amendment to its residue — §4's unbounded breadcrumb tracing and the fixed instruction floor (option C's territory) — which `DEBT-027` does not cover. Sequence A before re-measuring: the 34.3k figure cannot be decomposed from one data point, and A's diff is the cheapest instrument for splitting fixed from derived.

## Design — 2026-08-04 · user-settled (doctrine 批)

**Cards-only classification: the todo agent reads card text (+ test queue), zero repo reads.**

- §4 coupling gate: soft-coupling artifact trace (reads into docs/code) cut — its own text concedes the hard-block edge needs only a card-text grep, and the soft edge buys one rank adjacency. Hard-block edge stays (explicit ID naming in card text).
- §3 Blast: derive from card text alone — `Area:` field string, block path *mentions*; no reading the named files, no Plan-path widening into the repo.
- Dependency ordering moves from inferred to explicit: repos that need ordering name deps in card text (hard-block edge already supports it; scale-module fact fields are the formal home). Greenfield repos pay nothing — user-confirmed: most consumer repos are greenfield, the deep-read ordering served a need they don't have, at 10–20 min wall-clock per board.
- Fixed instruction floor: trim rides the cut (the two removed passages shrink `agents/todo.md`); no structural split — split's burden of proof unmet, `classify-actionable.md` stays whole (todo+drain seam).
- Self-log-loop concern resolved without machinery: capture's admission is completion-state, worth-judgment sits at triage (dismiss is a first-class resolve), board is pull-based — the loop breaks at human pickup. No cull ritual / volume cap; card it if observed in practice. → docs/decisions.md row on resolve.
