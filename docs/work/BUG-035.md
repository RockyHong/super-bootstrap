# BUG-035 — rename-map has no `/log` row, so the rot scan structurally cannot see stale bare `/log` literals

**Logged:** 2026-08-12 · **Source:** GitHub issue [#42](https://github.com/RockyHong/super-bootstrap/issues/42) (RockyHong), pulled via `/pull-issue`
**Problem:** `rename-map.md` § Slash commands lists a bare-form migration row for every bundled skill except `log` — no `/log` row, and no `/sb-log` in the legacy block — while the section's own policy states all bundled skills use the namespaced form. Phase 2b's rot scan is defined as: grep each map entry's `old` literal across pipeline-owned files, so the map is its only input and a literal with no row is not missed but structurally unreachable. A repo carrying a stale bare `/log` gets a clean rot verdict, and per-section diff cannot catch it either — template shape unchanged, only the literal inside stale, the exact case the map exists to cover. Observed live: converging an older repo onto the v2.32.0 skeleton, bare `/log` and bare `/todo` sat in the same sentences describing the capture→pickup spine (roughly a dozen of the former beside fifteen of the latter); the scan surfaced every `/todo` and reported clean on `/log`, the gap found only by a later unrelated grep. Same absence for `triage`, `triage-report`, `drain`, `check-docs-consistency` — if those never shipped a bare form the absence is correct, but the section gives a reader no way to tell "never existed" from "not yet added".
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/rename-map.md` § Slash commands (bare-form + legacy `sb-*` blocks, § Scan guidance); `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` Phase 2b
**Prior:** Add `` `/log` `` → `` `/super-bootstrap:log` `` and `` `/sb-log` `` → `` `/super-bootstrap:log` `` rows, sweep the bundled-skill list for the same omission, and state the section's coverage rule so a missing row reads as a deliberate "never had a bare form".

## Verdict — surface · 2026-08-12

### Findings

- root cause: **confirmed against the in-repo dev copy as it stands** (copy under test: `plugins/super-bootstrap/` at `7269479`, not the reporter's installed v2.32.0). `SKILL.md:414` defines the rot scan as "read `assets/rename-map.md` and grep every pipeline-owned file in scope for each entry's `old` literal" — the map is the scan's only input, so scan coverage is exactly the map's row list. The bare block (`rename-map.md:22-28`) carries 7 rows; the plugin bundles 13 skills, of which `super-bootstrap` is bare by policy — leaving **5 with no row in either block: `log`, `drain`, `triage`, `triage-report`, `check-docs-consistency`**. A bare literal for any of the 5 is structurally unreachable, as claimed.
  - live in-repo instance, cold-verifiable (the card's `/log` observation is external and was not reproducible here): `assets/claude-md-skeleton.md:71` ships `` Coverage backstop: `/check-docs-consistency` `` and the dogfood `CLAUDE.md:71` carries the identical line, while `plugins/super-bootstrap/README.md:36` fixes that skill's invocation form as `/super-bootstrap:<name>`. The pipeline seeds an off-policy bare literal into every consumer's CLAUDE.md; the rot scan cannot see it (no row) and per-section diff cannot either (skeleton carries the same bare form → section matches). Both blindness axes the map exists to close, on a literal the pipeline itself plants.
  - which of the 5 ever shipped a bare form: **none was ever the plugin's canonical bare form** — all 5 postdate the namespacing refactor `9924278` (2026-05-14): `log` `dfe2988` 2026-06-05, `drain` `71a3c2b` 2026-06-21, `triage`/`triage-report` `ef62c87` 2026-07-08, `check-docs-consistency` `2299ce8` 2026-07-08. Pickaxe over `assets/` finds no bare `/log` and no bare `/triage-report` in any shipped skeleton, ever. `check-docs-consistency` is the sole practical exception — its bare form ships *right now* (above).
  - the map is **not** a strict "was once shipped" ledger: only four `sb-*` skills ever existed (`sb-commit`, `sb-todo` `2026-05-04`; `sb-help` `2026-05-08`; `sb-merge` `2026-05-10`; all retired `419266f` 2026-05-12), yet the legacy block carries `/sb-harness-bootstrap`, `/sb-super-bootstrap`, `/sb-resolve-plugins`, `/sb-release-init` — four forms that never shipped. Defensive rows are already the practiced rule. Corollary: a `/sb-log` row would name a form that never existed, defensible only under that same defensive reading.
  - blocker on a straight unconditional sweep: `docs/specs/mattpocock-coexistence.md:41` records a live bare-name collision — the paired mattpocock set ships its own `/triage`, and `docs/agents/triage-labels.md:24` uses the bare form for it. An unconditional `/triage` row would propose renaming a foreign command in every paired repo — the exact class `/help`'s conditional row already handles.
  - coupling: a `/check-docs-consistency` row added without fixing the skeleton makes the two Phase-2b lanes fight — rot scan proposes migrating the consumer's line 71, then per-section diff reads the migrated section as drift from the still-bare skeleton and proposes reverting it. Row and skeleton literal must land in one commit.

Out of scope but same drift family: plugin-internal prose still writing bare `/log` (`plugins/super-bootstrap/README.md:67`, `skills/super-bootstrap/SKILL.md:38`) — not pipeline-owned, so no scan exposure.

### Decision needed

- **What does a `§ Slash commands` row assert** — this decides whether the 4 never-bare skills get rows at all:
  - **A (canonicalization sweep)** — a row exists for any non-canonical bare form of a bundled skill that could plausibly sit in a downstream pipeline file, shipped-by-us or not. All 5 get bare rows; `/super-bootstrap` stays the one documented bare exception; the block states the rule so a future absence reads deliberate.
  - **B (shipped-only ledger)** — rows track only forms this plugin actually shipped. `check-docs-consistency` earns a row (its bare form ships today); `log`, `drain`, `triage`, `triage-report` get an explicit "never shipped bare — no row by design" line instead, and the 4 never-shipped `/sb-*` rows are either deleted or annotated as exceptions.
  - recommendation: **A** — it is already the map's practiced rule (4 never-shipped `/sb-*` rows), and only A covers the reported case, a converged repo carrying a bare `/log` inherited from its own pre-plugin command, which B by construction cannot see.
- **How does a bare row whose name a foreign tool also owns migrate** — § Scan guidance currently makes `/help` the sole conditional row and every other bare hit unconditional:
  - **A1** — extend the conditional class one name at a time: `/triage` joins `/help` as "confirm the referent is the bundled skill before proposing".
  - **A2** — invert the default: every bare-form hit is referent-confirmed before proposal, and `/help`'s special-case paragraph collapses into that general rule.
  - recommendation: **A2** — the collision class is open-ended now that pairing is a supported posture (`b2055b9`), so A1 re-opens the map on every future pin; the scan already reads each hit's line to render its rot row, so the confirm step adds no pass.
- **Does the coupled skeleton literal land inside this card or split to its own?**
  - **Land here** — `claude-md-skeleton.md:71` + `CLAUDE.md:71` bare `/check-docs-consistency` → namespaced, same commit as the map row.
  - **Split** — new card for the skeleton literal, map row ships alone.
  - recommendation: **land here** — splitting is what creates the rot-scan-vs-per-section-diff oscillation above; both edits are two tokens, and CLAUDE.md is harness-owned so the change earns an `audit-harness-edits` pass either way.

## Design — 2026-08-12

Settled with the user against the three forks above: **A · A2 · land here**.

- **A (canonicalization sweep)** — a row exists for every bare form of a bundled skill that could plausibly sit in a downstream pipeline-owned file, shipped-by-us or not; a skill with no row reads as deliberate. All 12 non-entry skills carry a bare row. The legacy block keeps its four never-shipped `/sb-*` rows and gains none: the prefix is retired, so only skills that existed under it can plausibly appear in that form.
- **A2 (referent confirmation as the default)** — every bare-form hit is referent-confirmed against the hit's line before a migration is proposed; `/help`'s special-case row collapses into that general rule, and `sb-` prefixed forms stay unconditional. Grounded on a micro-test rather than the design argument: 3 cold reps ran the current wording over a fixture consumer `CLAUDE.md` carrying a bare `/log`, a bare `/check-docs-consistency`, and a bare `/triage` whose surrounding prose names a paired plugin's command. 2/3 proposed migrating the foreign `/triage`, each citing the unconditional policy while noting the collision in the row's Reason — and the scan's `y / n / per-row` acceptance turns a blanket `y` into a foreign-command rename. 1/3 held it back.
- **Land here** — `claude-md-skeleton.md` and dogfood `CLAUDE.md` both ship the off-policy bare `/check-docs-consistency`; the row and the literal land in one commit, so the rot scan and per-section diff never propose against each other.

Also compressed in the same section: the § Slash commands policy paragraph restated `README.md` § Naming convention's rationale — cut to a one-line canonical-form statement plus a link to that table.

Out of this card's scope, same drift family: bare `/log` and bare `/check-docs-consistency` in plugin-internal prose (`plugins/super-bootstrap/README.md`, `skills/super-bootstrap/SKILL.md`, `agents/doc-sync-scan.md`, `skills/check-docs-consistency/SKILL.md`, `skills/commit/SKILL.md`) — not pipeline-owned, so no scan exposure; carded separately.
