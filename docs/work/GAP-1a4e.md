# GAP-1a4e — Commit door has no hunk-grain staging rule and no staged-tree verify

**Logged:** 2026-10-20 · **Source:** device note from `magnetized-remake` (D:/Git/Games/Magnetized Remake, runway 5.2.0), 2026-10-13
**Problem:** The commit door's isolation rule is "stage by explicit path only" — file grain. When a session-list file also holds another writer's uncommitted hunks, nothing says what to do; twice in one day a session improvised a freehand partial stage that spliced wrong (a statement inside a `for` loop at the wrong indent; a `static func` header with no body, its body landing in another function). Both index versions failed the consumer's compile gate while the working tree compiled, so every verification (run on the working tree) read green; the broken commits were pushed and a fresh clone of origin could not compile. The index readback checks the staged path set, not staged content. The consumer parked its own pre-commit compile gate waiting on a hook point here.
**Area:** `plugins/super-bootstrap/skills/commit/SKILL.md` §1 / §5
**Prior:** Mixed file → stage hunks mechanically (`git apply --cached` of a patch cut from `git diff`, read back with `git show :<path>` against the intended post-image) or stop and surface, never freehand; plus an optional consumer-declared command the door runs against the materialized index (`git checkout-index -a --prefix=<tmp>/`) before `git commit`, at least on hunk-partial commits. Same staging-isolation area as BUG-8zwv.
