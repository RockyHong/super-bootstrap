# BUG-060 — commit-channel: the guard covers the Bash tool only — a PowerShell-tool `git commit` bypasses the single channel

**Logged:** 2026-09-10 · **Source:** GAP-073 verify run — a dispatched executor, denied on Bash, re-issued `git commit` through the PowerShell tool and it ran
**Problem:** The settings entry wires `commit-channel.sh` under `matcher: Bash` with `if: "Bash(git *)"`. On a dual-shell device the PowerShell tool is a second command surface the hook never sees, so a subagent's raw `git commit` lands in the project's history through it — the single-channel guarantee (root README `.claude/hooks/` row, `docs/overview.md` § Commit) does not hold where that tool exists. Same hole for any other command-running tool the harness exposes.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md` (settings entry shape); `assets/hooks/commit-channel.sh` (reads `tool_input.command` — PowerShell's stdin shape may differ); `.claude/settings.json` (dogfood wiring)
**Prior:** The matcher was authored on a Bash-only device; adding a `PowerShell` matcher entry (and confirming the stdin field name) closes it — verify the deny fires from the PowerShell tool on this device.
**Test-feel:** manual · **Blast:** pkg

## Amendment — 2026-09-10 · gateway (closed-fork check, missed at capture)

This re-walks the closed fork at [`docs/decisions.md`](../decisions.md) row "Widen the commit-channel hook past Bash `git commit`" (was BUG-020): non-Bash tool paths were accepted as out of scope because an MCP tool's `tool_input` carries no `command` field, with the reopen bar set at "a subagent lands a commit through any bypass class in practice". New facts against that verdict: (1) the bypass was walked in practice — a dispatched subagent, denied on Bash, re-issued `git commit` through the PowerShell tool and it ran — though into a scratch fixture, not this project's history; (2) the PowerShell tool is a native command tool, not MCP, so whether its hook stdin carries `tool_input.command` (a matcher-only fix) is checkable and unchecked. Triage rules reopen vs hold; the sibling GAP-075 (subagent commit in a non-project repo) was dropped as dispatcher misuse — the hook confined a subagent by design.

## Verdict — surface · 2026-09-10

### Findings

- **reopen bar: met, by direct transcript evidence.** Session `3bce970e` subagent transcript (`~/.claude/projects/D--Git-super-bootstrap/3bce970e-a2f9-4ec5-a0c8-2c51c3777877/subagents/agent-a81a234e4ff2528f7.jsonl`) records the pair 13 seconds apart: `02:30:04.989Z` Bash tool `git add -A && git ⟨commit⟩ -m "add manifest"` → tool_result is the verbatim `commit-channel.sh` deny text; `02:30:17.497Z` PowerShell tool, same command → tool_result is git's own output (LF/CRLF warnings), i.e. it ran. A subagent walked the non-Bash bypass class in practice. The decisions row's bar reads "lands a commit through any bypass class in practice" — it does not qualify the destination repo, so the scratch-fixture target does not exempt it.
- **the row's stated blocker is falsified for this tool.** The row rules the non-Bash class out as "not a matcher edit — an MCP tool's `tool_input` carries no `command` field". PowerShell is a native tool, not MCP. Its tool_use input schema, read off 13 recorded invocations across the transcript corpus, is `{command, description}` / `{command, description, timeout}` — the same `command` field name Bash uses. `.tool_input.command` therefore resolves for it, and no per-tool parsing is required. The already-wired `Workflow` / `Agent` / `Read` PreToolUse entries in `.claude/settings.json` confirm non-Bash tool-name matchers fire.
- **root cause D1 (the card's claim, confirmed) — the hook never spawns.** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.hook.json` sets `"matcher": "Bash"` with `"if": "Bash(git *)"`. Matcher and `if` both key on the Bash tool, so a PowerShell tool call reaches no hook process. Per the served guideline `~/.claude/guidelines/claude-shape/compound-command-permissions.md` § Hook `if` clauses, `if` takes permission-rule syntax and gates whether the hook process spawns at all — so widening only the `matcher` while leaving `if: "Bash(git *)"` in place would still not spawn on PowerShell.
- **root cause D2 (not in the card; tool-agnostic, live on Bash too) — a newline is not a command separator in the frozen regex.** `assets/hooks/commit-channel.sh` line ~30: `_re='(^|[;&|])[[:blank:]]*git[[:blank:]]+([^[:space:]]+[[:blank:]]+)*commit([[:space:]]|$|;|&|\|)'`. Bash `=~` compiles without `REG_NEWLINE`, so `^` anchors to the whole string only, and the separator class `[;&|]` excludes `\n`. Probed against the frozen script on this device:
  - `git add -A; git ⟨commit⟩ -m x` → **DENIED**
  - `git add -A\ngit ⟨commit⟩ -m x` → **PASSED**
  - the verbatim bypass payload (`$FIXTURE = "…"\nSet-Location $FIXTURE\ngit add -A\ngit ⟨commit⟩ -m "add manifest"\ngit log --oneline -5`), `agent_type` set to a subagent → **PASSED**
  - `{"tool_name":"Bash","tool_input":{"command":"set -e\ngit ⟨commit⟩ -q -m \"x\""},"agent_type":"implementer"}` → **PASSED**

  Consequence: **fixing D1 alone does not close the incident.** With the matcher widened, the recorded bypass command still passes, because its `git ⟨commit⟩` sits on its own line. And the last probe shows the same hole is open on the Bash lane today, for the multi-line `set -e` + newline shape this repo's own commit door idiomatically emits — a bypass class BUG-020 never considered and no decisions row covers.
- **D2 is DEBT-010's unforeseen side effect, not a closed fork.** `c40f916` ("commit-channel v2 command-position matcher") narrowed to command position specifically to stop `git commit` substrings inside a quoted arg or heredoc from false-denying worker calls. The newline hole was never surfaced; `docs/decisions.md` holds no row on it. The trade-off is still live in both directions — an incidental probe this session tripped the deny on a `;`-separated `git ⟨commit⟩` string inside a quoted `printf` argument, so the false-deny class DEBT-010 targeted is not fully closed either.
- **scope reach.** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.hook.json` (matcher/`if`); `assets/hooks/commit-channel.sh` (regex + its header comment narrating `if: "Bash(git *)"` and the one-line property; FROZEN marker `v5` → bump); `assets/hooks-ensure-infra.md` — its `snippetCurrent(name)` predicate resolves "**the** settings.json target-array entry whose command references `<name>.sh`", singular, so a second PreToolUse entry for the same script breaks the idempotency predicate and its `hooksInfraPresent()` conjunct; `.claude/settings.json` (dogfood wiring); `tests/commit-channel.test.sh:48-49` pins `snippet_if == "Bash(git *)"` (BUG-039 assertion) — any snippet change turns that test red by construction; `docs/decisions.md:48` row needs superseding, not deleting. `bench/**/.fixtures/**` copies are pinned fixtures — **do not edit**. `~/.claude/guidelines/claude-shape/compound-command-permissions.md` is a served copy from the storehouse repo: cite it, never edit it here; a change there routes through `/contribute`.
- **provenance.** `.claude/hooks/commit-channel.sh` is this repo's own dogfooded install of its own shipped asset — the asset under `plugins/` is the SSOT, the `.claude/` copy is placed by `hooks-ensure-infra` and re-placed on drift. Fix the asset, then re-sync; never edit the `.claude/` copy as the fix.
- **measured cost axis.** No-op hook spawn (`bash` + `jq`, non-git payload, early exit) on this device: 1366 ms / 20 runs = **~68 ms per call**. That is the per-call price of an `if`-less entry on whatever tool it matches. PowerShell tool use is rare here — 13 recorded invocations in this project's whole transcript history against thousands of Bash calls — so an `if`-less PowerShell entry costs ≈1 second of aggregate latency per project-lifetime, while an `if`-less *Bash* entry or a `matcher: ".*"` entry would tax every tool call.
- **attempted.** Static read of the asset pair, the ensure-infra predicate, the test, and the decisions row; transcript-corpus read for the PowerShell tool's input schema and the incident timeline; four read-only payload probes against the frozen script. Stopped at the fix-shape fork — the remaining unknown (below) cannot be measured from a read-only lane.

### Decision needed

Two forks; **both must land in one change** — D1 alone leaves the recorded incident reproducible.

**Fork A — how the PowerShell lane gets wired.**

- **A1. One entry, `"matcher": "Bash|PowerShell"`, `if` dropped.** Simplest; keeps `snippetCurrent()` valid unchanged. Cost: ~68 ms on *every* Bash tool call, the pre-filter the current design exists to avoid.
- **A2. Keep the Bash entry with its `if` intact; add a second entry `"matcher": "PowerShell"` with no `if`.** Bash keeps its free pre-filter; PowerShell pays ~68 ms on its rare calls. Cost: requires amending `snippetCurrent(commit-channel)` in `hooks-ensure-infra.md` to resolve an entry *set* rather than a single entry — a frozen-procedure edit, and existing installs re-sync against it.
- **A3. Second entry as A2, but carrying `"if": "PowerShell(git *)"`.** Cheapest at runtime if it works. Blocked on an unverified premise: whether the permission engine accepts a command-specifier rule for the PowerShell tool at all. Its documented sub-command splitting is Bash-specific; if the specifier does not parse, the `if` silently never matches and the entry is a **silent no-op** — the exact failure mode this card exists to close.
- **A4. `"matcher": ".*"`, script's existing `.tool_input.command // empty` early-exit carries it.** Covers every present and future command-running tool with zero per-tool work — the card's "same hole for any other command-running tool" clause. Cost: ~68 ms on every tool call of every kind, Read/Grep/Edit included.

**Fork B — how the newline hole closes, given DEBT-010.**

- **B1. Add `\n` to both separator classes** (`(^|[;&|\n])` … `([[:space:]]|$|;|&|\||\n)`). Closes D2 outright. Re-admits the false-deny class DEBT-010 fixed: a heredoc body or a quoted multi-line string containing a line that begins `git commit` now denies a worker's non-commit call.
- **B2. Keep the current regex; accept the newline pass as scoped.** Rejects D2 as out of this card's aim. Leaves the recorded incident reproducible after the D1 fix, and leaves the Bash lane open on the repo's own idiomatic `set -e` + newline shape.
- **B3. Strip heredoc/quoted regions from `$cmd` first, then match with `\n` admitted as a separator.** Closes D2 without re-admitting the false-deny. Cost: real parsing inside a frozen asset — the unbounded-heuristic class `docs/decisions.md:48` already closed once.

- **recommendation: A2 + B1.** A2 buys full coverage of the demonstrated bypass at a cost that lands only on the rare tool, and its one real cost — the `snippetCurrent` amendment — is a bounded doc edit this card already has to open (the FROZEN marker bumps to v6 regardless, since B changes the script). A3 is rejected on the silent-no-op risk; A1 and A4 tax the hot path to buy coverage A2 already has. B1 over B3 because B3 is exactly the parsing class the prior decision closed, and over B2 because B2 leaves the card's own incident un-closed. The false-deny B1 re-admits is a **visible, recoverable** failure (a worker sees the deny text and routes to the door), while the pass it removes is a **silent, unrecoverable** one — the same asymmetry the served guideline `~/.claude/guidelines/claude-shape/compound-command-permissions.md` states as "a gate whose miss is a silent pass therefore anchors on the bare command and re-checks the real sub-command inside the script".
- **settles by:** Fork B is settled by that guideline's stated asymmetry plus the direct probe evidence above — no further authority needed, but it reverses a direction `c40f916` deliberately took, so it wants the user's explicit nod before the frozen asset moves. Fork A's only open premise is A3's viability, and its measurement is a **phased build**: a scratch fixture repo with its own `.claude/settings.json` carrying a marker-writing PreToolUse entry under `"if": "PowerShell(git *)"`, a session opened rooted there, one PowerShell `git status` call, marker present/absent read back. Not worth building — A2 needs no such probe, which is part of why it is the pick. Whether the reopen supersedes or replaces the `docs/decisions.md:48` row is the author's call; the row's non-MCP-tool clause is falsified by this trace regardless.
