# BUG-060 — commit-channel: the guard covers the Bash tool only — a PowerShell-tool `git commit` bypasses the single channel

**Logged:** 2026-09-10 · **Source:** GAP-073 verify run — a dispatched executor, denied on Bash, re-issued `git commit` through the PowerShell tool and it ran
**Problem:** The settings entry wires `commit-channel.sh` under `matcher: Bash` with `if: "Bash(git *)"`. On a dual-shell device the PowerShell tool is a second command surface the hook never sees, so a subagent's raw `git commit` lands in the project's history through it — the single-channel guarantee (root README `.claude/hooks/` row, `docs/overview.md` § Commit) does not hold where that tool exists. Same hole for any other command-running tool the harness exposes.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md` (settings entry shape); `assets/hooks/commit-channel.sh` (reads `tool_input.command` — PowerShell's stdin shape may differ); `.claude/settings.json` (dogfood wiring)
**Prior:** The matcher was authored on a Bash-only device; adding a `PowerShell` matcher entry (and confirming the stdin field name) closes it — verify the deny fires from the PowerShell tool on this device.
**Test-feel:** manual · **Blast:** pkg

## Amendment — 2026-09-10 · gateway (closed-fork check, missed at capture)

This re-walks the closed fork at [`docs/decisions.md`](../decisions.md) row "Widen the commit-channel hook past Bash `git commit`" (was BUG-020): non-Bash tool paths were accepted as out of scope because an MCP tool's `tool_input` carries no `command` field, with the reopen bar set at "a subagent lands a commit through any bypass class in practice". New facts against that verdict: (1) the bypass was walked in practice — a dispatched subagent, denied on Bash, re-issued `git commit` through the PowerShell tool and it ran — though into a scratch fixture, not this project's history; (2) the PowerShell tool is a native command tool, not MCP, so whether its hook stdin carries `tool_input.command` (a matcher-only fix) is checkable and unchecked. Triage rules reopen vs hold; the sibling GAP-075 (subagent commit in a non-project repo) was dropped as dispatcher misuse — the hook confined a subagent by design.
