# BUG-062 — commit door terms lane counts a scene/entity basename used as domain vocabulary, pushing single-scene commits past the scope ceiling

**Logged:** 2026-09-18 · **Source:** GitHub issue [#69](https://github.com/RockyHong/super-bootstrap/issues/69) (downstream Godot repo)
**Problem:** Touching one scene file (e.g. `levels/Ending.tscn`) makes `doc-links.sh terms` yield the basename `Ending`; `hits Ending` returns 9 doc-surface files because specs name the scene in backticks as ordinary domain vocabulary ("the original's win loaded `Ending`"), not as a narration of that file's contents. 9 > the scope ceiling of 8, so every commit touching that scene routes to the cold `doc-sync-scan` dispatch — even a one-knob tweak no other doc narrates. Verify: in a repo whose specs mention a scene name in backticks in ≥9 docs, `terms <scene path>` → `hits <term>` → count > 8; after the fix, a commit changing only a numeric knob in that scene stays at or under the ceiling and judges warm-inline.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` (terms / hits lanes, `HUB_STEMS`), `plugins/super-bootstrap/skills/commit/SKILL.md` § scope ceiling
**Prior:** The code-shape filter (backticked whole word / path segment) cannot tell a domain noun from a symbol citation. Directions from the issue, unprescribed: discount bare-basename-only hits for asset-shaped extensions (`.tscn`, `.tres`) and lean on the anchored citer lane; a repo-declared domain-noun list treated like `HUB_STEMS`; count the ceiling per unique asserting line instead of per file.
