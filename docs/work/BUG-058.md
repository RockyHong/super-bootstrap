# BUG-058 — commit: "Push these now?" fires unconditionally, even with no git remote

**Logged:** 2026-09-10 · **Source:** GitHub issue [#65](https://github.com/RockyHong/super-bootstrap/issues/65) via `/pull-issue`
**Problem:** `skills/commit/SKILL.md` §6 ("Push (on confirmation)") and its rule line ("Push on explicit yes only") ask "Push these now? (y / skip)" after every commit, unconditionally. In a repo with no git remote the question can never be answered yes, yet it fires on every commit round — the user declines it again and again, and a repo whose own docs record "local-only, no remote" gets asked anyway. Proposed change: probe before §6 asks — `git remote` prints nothing → skip §6 silently (no question, no "skipped" line), straight to §7's handoff line; a remote but no upstream → say so in one line and ask once whether to set it (`git push -u <remote> <branch>`) or skip; remote + upstream → today's behaviour. The probe is a fact the gateway can check itself, so it belongs before the ask, not inside it — same stance as the skill's own "session file list" / "index readback" steps. Optional: a project CLAUDE.md or `docs/` line declaring the repo local-only short-circuits the probe. Verify: (1) `git init` with no remote, commit via `/super-bootstrap:commit` → no push question, cycle-handoff line is the last output; (2) add a remote without upstream → one upstream question, once; (3) add the upstream → unchanged "Push these now?" behaviour.
**Area:** `plugins/super-bootstrap/skills/commit/SKILL.md` §6 + § Rules "Push on explicit yes only"
**Prior:** §6 assumes a push surface exists; no remote/upstream probe precedes the ask.
**Test-feel:** manual · **Blast:** local
