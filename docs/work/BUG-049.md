# BUG-049 — commit §5 prose orders the index readback after the harness-audit stamp, contradicting the sibling door

**Logged:** 2026-08-27 · **Source:** GitHub issue #54 (https://github.com/RockyHong/super-bootstrap/issues/54), grounded at pull
**Problem:** `plugins/super-bootstrap/skills/commit/SKILL.md:36` states verbatim: "Where a harness-audit stamp call sits between add and commit, the readback runs after the stamp — still immediately before `git commit`." The stamp call fingerprints whatever the shared index holds at that moment (`harness-audit-pretool.sh --stamp "<verdict>" $(git diff --cached --name-only)`), so with two sessions in one checkout a path the other session staged widens the stamped set before the readback runs — the readback catches the commit but not the stamp. The sibling audit door already runs the opposite order (`claude-config-manager` `skills/audit-harness-edits/SKILL.md:126-128`: readback → stamp), so the two doors disagree on the seam and this repo's shipped prose is the side that disagrees.
**Area:** `plugins/super-bootstrap/skills/commit/SKILL.md` §5 (index readback bullet, line 36)
**Prior:** The seam's mechanism lives entirely in claude-config-manager — `harness-audit-pretool` has zero hits in this repo, and CCM's copy is already correct. What sb owns here is one line of prose that instructs the wrong order; the fix is a prose reorder (add → readback → stamp → commit), not a stamp-call move, since sb issues no stamp call. The issue's proposed verify surface (`bench/commit-guard/` arm staging a foreign path before the stamp) does not apply for the same reason — no stamp logic in this repo to guard; a prose-shaping micro-test is the available surface. Note also `commit/SKILL.md:15` calls §5's readback "the gate", which the current ordering only half-honors.
