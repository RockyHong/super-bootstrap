The defect is one sentence, [`SKILL.md:587`](../../plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md):

> If every row is `✓ current` and nothing changed on disk, report and skip the commit.

It is a two-conjunct guard over a one-bit decision (commit or don't), and **both conjuncts are mis-keyed**:

1. **Conjunct 1 is verdict-keyed where the decision is effect-keyed.** A row's verdict column (`✓ current` / `⚠ drifted` / `⊕ new` / `⊘ missing` / `⊘ removed`) states what was *found*; whether the commit has anything to carry is decided by the resolution column — what was *done*. The skill's own gate at `:546` enumerates four resolutions that write nothing: `declined ({reason})` (section drift kept, insert declined, rot row left alone), `kept (fork)` (§ 2a-hooks / § 2a-autorun fork kept at the overwrite prompt), `registration: … | none`, and `✓ pinned` for a settings key already present. Each of those pairs a non-`✓ current` verdict with a zero-effect resolution, and each one alone falsifies conjunct 1 while the commit's stage set stays empty. The card's `Prior` reads this correctly for `declined`; read against `:546` the class is four resolutions wide, not one.
2. **Conjunct 2's "on disk" is unscoped, and is false on *every* re-run.** § 2b writes `.claude/bootstrap-sync-report.md` before Block 1 renders (`:402`, "Overwrite any stale report from a prior run"), and `:615` deletes it only *after* the commit-or-report step. No runway-written `.gitignore` line covers it — the lines § 2a writes are `.claude/.consult-catalog`, `.claude/worktrees/`, `.autorun-status` (`:598`), so the report sits in the working tree as a visible change at the moment the predicate is read. Taken literally, conjunct 2 never reads true on a re-run. The term the sentence means is **§ 2c's own stage list** (`:589`–`:613`), not the working tree.

**Why RUN 4's state is reachable, and recurring.** `AGENTS.md` is pipeline-owned with its whole shipped body drift-checked (`:170`), so a consumer hand-edit is a permanent `⚠ drifted` source. Declining it is a first-class outcome: § 2b's Block 2 renders `previously declined: {reason}` from the receipt and states that "the row still takes its full read-and-compare and its own Block 2 answer" (`:447`–`:449`), so the row re-fires with the same verdict every sync. The receipt (`:583`) is overwritten whole from `{version, covered, declined, placed}`; with the plugin version unchanged and the decline reason unchanged it comes out byte-identical. `declined ⊆ covered` holds, so Phase 1's set-difference finds no coverage gap and `version_stale` stays unset. Net: once a consumer declines one hand-edit, **every** subsequent no-op re-run lands in the state the text does not name — not a one-off fixture artifact.

**The failure is not benign at the downstream door.** The otherwise-branch's instruction is "use `/super-bootstrap:commit` to stage: …". That door (`skills/commit/SKILL.md` §5) runs `git add` of explicit paths, reads the index back, then `git commit` — with an empty index `git commit` errors, and the door names no empty-stage branch either. So the otherwise-branch is a dead end, and RUN 4's completion rests on the executor silently taking the skip side.

The reconciliation is therefore: drop conjunct 1, scope conjunct 2 to § 2c's stage list — one predicate, two named branches, effect-keyed.
