# BUG-083 — § 2c's commit predicate resolves to neither branch when a declined drift row rides a disk-unchanged re-run

**Logged:** 2026-10-07 · **Source:** harness-bootstrap fixture walk, `fixture-section` RUN 4 (cold executor, plugin v5.1.1)
**Problem:** § 2c branches the commit step on "every row `✓ current` and nothing changed on disk → report and skip the commit. Otherwise … stage: …". A re-run after a drift was declined satisfies neither: the skip clause fails because one row reads `⚠ drifted` (resolution `declined`), while the otherwise-branch has nothing to stage because the declined row wrote nothing and the receipt came out byte-identical. Observed: `AGENTS.md` hand-edited, declined with a reason in the prior run, then an unchanged re-run — nothing staged, no commit, predicate unsatisfied either way. The run completes only because the executor chose a branch the text does not name.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § 2c
**Prior:** The skip clause keys on the verdict column (`✓ current`) where it means to key on effect — a `declined` row changed nothing, so it belongs on the skip side alongside `✓ current`.
