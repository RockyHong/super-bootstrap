# GAP-077 — the runway receipt's `declined` list carries no reason, so a re-run cannot read back why a row was declined

**Logged:** 2026-09-11 · **Source:** `session-close` after the DEBT-114 dogfood re-run — the drift walk had to re-derive every `declined` row from git before trusting it
**Problem:** `.claude/super-bootstrap-runway.json` `declined` is a flat array of section names; the reason a row was declined (dogfood-specific pointer, settled taste, mixed row) lives only in the session that declined it. On the DEBT-114 re-run under `version_stale` every declined row was re-walked from git history before it could be trusted, and one (`docs/work/README.md`) turned out to be a missed propagation typed as taste — the miss a one-line reason would have surfaced at a glance. The receipt exists so a re-run compares against settled divergences instead of re-proposing them; without the reason it only says *that* a row was settled, not *what* settled it.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § 2b drift rows + Phase 2c receipt write; `.claude/super-bootstrap-runway.json` shape (`declined`)
**Prior:** `declined` entries carry a reason string — object form or `"section — reason"` — written by Phase 2c from the drift row's resolution note and echoed into the next run's sync-report row; the flat string form stays readable for old receipts.
**Test-feel:** manual · **Blast:** pkg
