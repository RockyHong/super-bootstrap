# GAP-j0sr — commit door: a repo-generic term inflates the doc-sync scope with no per-term visibility

**Logged:** 2026-10-27 · **Source:** device note from ComfyUI `workflows/agent` consumer (same commit as `BUG-g66v`)
**Problem:** `terms` turned `tools/graphs.py` into `graphs`; that repo backticks `graphs.py` / `graphs.<fn>` across its docs, so `hits graphs` alone returned 8 docs, none narrating the change, and pushed the scope over the 8-doc inline ceiling. `hits` prints files only, so the gateway cannot see which term blew the scope; the owner read "13 related docs" as an SSOT-bloat symptom. The real SSOT signal in that commit — one fact restated in 4 places in README — the gate does not surface.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh` (`do_hits`); `plugins/super-bootstrap/skills/commit/SKILL.md` §3 (scope ceiling) and § Rules "Grep-gate is mechanical" (line 67)
**Prior:** consumer suggestions — print per-term hit counts; demote a term hitting > N docs (or a share of the surface) to path-segment matching, as hub stems already are (tension with "term extraction is path-structure only, never a judgment"); a "changed fact restated in K places" gate line as the direct SSOT-drift signal.

## Verdict — surface · 2026-10-27

### Findings

- premise age: clean — no commit touched `plugins/super-bootstrap/skills/commit/` since the 2026-10-27 observation. The consumer repo is not readable from here; the 8-doc count is taken from the card, the mechanism below from current code.
- root cause (visibility half, verified): `do_hits` (`doc-links.sh:663-754`) does a `break` after the first term that matches a file. Its `END` prints only `f` (`:751`). No term-to-file association survives, so no mode or flag can show which term pulled a file in. The §3 ceiling (`commit/SKILL.md:25`) counts the union of all lanes, so the scope count cannot be traced back to one term either. Confirmed as described.
- root cause (inflation half, verified as working as designed, not a defect): a doc that backticks `graphs.py` or `graphs.<fn>` names the changed file `tools/graphs.py`. `wordin(code, …)` matches it, and so does `pathin($0, …)`, because `pathin` takes any `.`+alnum suffix as an extension shape (`:704`). So `graphs.build` hits the same way as `graphs.py`. The gate's contract is to catch docs that name the changed file. Whether those docs narrate *this change* is the §4 judgment, not a gate fact. Going past the ceiling routes the scope to the designed overload valve (`SKILL.md:25`). That costs a cold dispatch. Per the decisions.md warm-vs-cold row, it also costs judgment quality: the cold judge is weaker on the judgment class. Coverage is not lost.
- card corrections: (1) The Prior's demotion option is "demote to path-segment matching, as hub stems already are". That has two errors. Hub stems are demoted to the *bare-token* form (`barein`, `:712-724`), the inverse of path-segment matching. And path-segment matching would still hit both reported shapes, because `pathin` takes `graphs.py` and `graphs.<fn>` as path shapes. So the suggested demotion would not shrink the reported scope. Only full-relative-path matching (`tools/graphs.py`) or dropping the term would. (2) The "13 related docs" includes the `BUG-g66v` shell-split fragments (that card's Source says the gate enumerated 13). This card's own cause is 8 of them.
- scope reach: `doc-links.sh` (`do_hits` + header + usage), `commit/SKILL.md` §3 "Terms → grep hits" + "Scope ceiling" + § Rules "Grep-gate is mechanical", `tests/doc-links.test.sh` (hits block, `:687-728`), `bench/doc-links/` (`run.sh` hits cases, `expected/` goldens byte-compared, README case list). If the default `hits` output stays unchanged, the goldens hold.
- overlap: `BUG-g66v` (open) changes the same `hits` CLI intake (argv → stdin `-`). Not a duplicate: different defect, same surface. Whatever CLI form one card picks (a flag, a mode, stdin), the other must fit into it. Land them together or one right after the other.
- third Prior item ("changed fact restated in K places"): this is not a mechanical lane. Finding a "fact" and its restatements is a semantic judgment, and the "Grep-gate is mechanical" rule (`SKILL.md:67`) excludes that from §3. It is also a different aim (whole-surface SSOT drift) from this card's (gate-scope attribution). Its natural home is `/super-bootstrap:check-docs-consistency` or a card of its own.
- attempted: static read of `do_terms`/`do_hits`/§3/§ Rules, decisions.md rows on the grep-gate error direction and the warm/cold judge, overlapping cards. No `§ Probes` table in `docs/techstack.md`, so no probes ran. Stopped at the fork below: the visibility half alone could be auto-fix, but the card bundles it with a coverage trade-off that needs a risk call.

### Decision needed

- What does this card ship: attribution only, or attribution plus a coverage-narrowing rule for high-fanout terms?
- options:
  - (A) Attribution only. Add an additive per-term output (for example a `hits` flag or a sibling mode that prints `term TAB count`, or `term TAB file`). The default `hits` output stays byte-identical. §3 tells the gateway to print the per-term counts beside the scope count when the ceiling trips. Coverage does not change. Mechanical, unit-testable via `tests/doc-links.test.sh` and a new `bench/doc-links` case.
  - (B) A plus narrowing. A term that hits more than N docs is matched only as its full changed relative path (`tools/graphs.py`), not its stem. Count-based, so still mechanical. But it trades the false-positive direction for false-negatives, against the decisions.md grep-gate error-direction row ("grep errs false-positive … a pure link-gate … silently drops doc-sync coverage"). A doc that cites `graphs.build` in a changed contract would drop out silently. N has no measured basis.
  - (C) A plus a raised or per-repo ceiling. Leaves matching alone and moves the warm/cold switch. This re-prices the warm-default decision without a measurement.
- recommendation: (A). It answers the card's stated gap (no way to see which term caused the inflation) at zero coverage cost. It also produces the per-term counts that a later (B) needs to pick N. Move the "fact restated in K places" item off this card: log it as its own GAP aimed at `check-docs-consistency`, or drop it. Sequence with `BUG-g66v` on one CLI design for `hits` intake and output.
- settles by: whether to give up coverage for scope size is a risk authority call (user). If (B) is wanted later, settle it with per-term hit counts gathered over real consumer commits once (A) ships. Size: `dispatched probe` (a cold subagent runs `terms`/`hits` with attribution over a sample of past diffs in one or more consumer repos and reports the fanout distribution).
