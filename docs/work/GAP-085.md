# GAP-085 — Testing contract asks only for the green half of the evidence

**Logged:** 2026-09-21 · **Source:** GitHub issue #73 (https://github.com/RockyHong/super-bootstrap/issues/73), filed by RockyHong 2026-09-21
**Problem:** The `CODING_STANDARDS.md § Testing` skeleton `harness-bootstrap` writes, and the standing build-dispatch contract ("Verify before claiming — evidence before done / fixed / passing"), can both be satisfied to the letter by an implementer that hands back an assertion that cannot fail. Observed in a real round: an implementer replacing a flaky assertion's hard-coded tolerance with a self-measured bound took a whole-run maximum — an order of magnitude larger than the asserted quantity — so the comparison threshold was negative for the entire run and the assertion could not fire for any input. Five green runs were offered as evidence the defect was fixed; the greens were real and meant nothing. The gap is not "it didn't verify" — it verified exactly what the contract asks for. A passing suite is structurally blind to the difference between "the code is right" and "the check is dead", and an implementer left to its own judgement does not invent the missing step (two rounds running, it did not).
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/` (the `CODING_STANDARDS.md § Testing` skeleton asset) + the standing build-dispatch contract where the "do not commit, report the file list" convention lives (`CLAUDE.md` § Dispatch and its shipped skeleton counterpart)
**Test-feel:** manual · **Blast:** repo
**Prior:** Issue proposes one clause in both places — a new or changed assertion lands with proof it can go red: perturb the input, threshold, or compared value until the assertion fires, confirm the failure message names the quantities a reader needs, revert, and report the red verbatim alongside the green; a green from an assertion never observed failing is not evidence. Verify by bootstrapping a scratch repo, dispatching a build that changes an existing assertion's tolerance, and reading whether the returned report carries a verbatim induced failure.

## Amendment — 2026-09-21 · phase-1 fidelity raise

Supersedes one clause in the Plan above: step 1's "the fixture is a scratch repo whose **only** instruction surface is the two shipped skeletons verbatim and unmodified". That was wrong in two ways, both caught before any run fired.

The `CLAUDE.md` arm cannot be the raw skeleton. [`harness-bootstrap/SKILL.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md):352 fills placeholders on write, :522-529 list the substitutions and the conditional blocks, and :335 fills the Rules bullets — so no bootstrapped repo ever holds `{Project Name}`. Only `AGENTS.md` is copied with no substitutions (:231), and it stays byte-verbatim. The skeleton's braces are three classes, not one: true placeholders, conditional blocks that fire or drop on detection, and literal braces that belong in the shipped prose (`docs/work/{ID}.md`, the `/super-bootstrap:triage {ID}` row) and must survive.

The deeper error: a two-file arm is a **weaker** control than the condition the incident occurred in. The card's incident happened in this repo under the full harness, and a bootstrapped consumer likewise gets the full runway. A minimal fixture can show a gap the full runway would have closed, and authoring an ambient clause off that reproduces the [`BUG-064`](../decisions.md) failure exactly. The fixture now seeds the runway `harness-bootstrap` places for this repo shape — single-package, code present, scale module unarmed — derived from SKILL.md Phase 2 rather than invented. Deliberately withheld: any signal-seeded `.claude/rules/*.md`, since planting a test-glob rule would pre-install candidate arm **C** into the control.

Instrument re-validated after the change — suite green, liveness probe still discriminating in both directions, arm delta still exactly one append per contract surface. Gate thresholds untouched; one superseded gloss is recorded as a dated erratum in `bench/assertion-liveness/FINDINGS.md`.

**Open instrument risk, unmeasured:** the placed `.claude/settings.json` carries the § 2a core plugin pin. Whether a headless run under a credentials-only `CLAUDE_CONFIG_DIR` resolves it, skips it, or **stalls** on the marketplace is unknown until the first run. Disposition fixed in advance: a stall is an instrument failure reported as **no measurement**, never a reason to quietly strip the pin.
