# DEBT-113 — model tiering: the top tier is a fixed alias instead of the session owner's model

**Logged:** 2026-09-10 · **Source:** owner's ruling after DEBT-110's keep-as-is close
**Problem:** The top tier is pinned to a fixed alias wherever it appears — `agents/triage.md` carries `model: opus`, the tiering table's Top row reads `opus`, and the served agent-model guard's deny text offers `haiku|sonnet|opus`. A fixed top alias sits either below the session (a Fable session dispatching Opus for its hardest and its aesthetic work) or above it (an Opus session paying for Fable). Ruling: the top tier is **inherit** — the model the session owner runs the gateway on — and that model is also the **cap**; the gateway assigns mid / small below it by shape. Aesthetic / design work and the hardest-judgment doors ride the top tier uncapped within the session: a Fable session gives them Fable, an Opus session caps at Opus.
**Area:** repo side — `plugins/super-bootstrap/agents/triage.md` (`model:`), `plugins/super-bootstrap/README.md` tier narration (lines naming Opus), `plugins/super-bootstrap/skills/triage/SKILL.md` line 9; storehouse side, via `/contribute` — `work-discipline/model-tiering.md` (Top row, § Tier ownership by surface), `agent-model-pretool.sh` deny text
**Prior:** Typed top-tier agents take `model: inherit` (official frontmatter value); an ad-hoc top-tier call site passes the session's own model, which the guard already accepts; the lore's Top row renames to "inherit — the session owner's model, also the cap". Supersedes DEBT-110's disposition.
