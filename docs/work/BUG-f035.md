# BUG-f035 — `doc-links.sh` fails 11 suite checks under busybox awk: the grep lane's stdin term list arrives empty

**Logged:** 2026-11-13 · **Source:** cross-awk Docker run of `tests/doc-links.test.sh` at v5.10.6 (`alpine:3.20`, BusyBox v1.36.1)
**Problem:** Under busybox awk the suite reports 234 passed, 11 failed. Nine failures are `grep-scope` checks: busybox awk does not read stdin through `getline < "-"` — the probe `printf "a\nb\n" | awk 'BEGIN{ while ((getline x < "-") > 0) n++; print "lines=" n }'` prints `lines=` — so the stdin term list at `doc-links.sh:894` arrives empty and the grep lane scans fewer docs with no error. With that one read changed to `getline xl < "/dev/stdin"` inside the container, the nine pass (243 passed, 2 failed); the change was not tried under gawk, mawk, one-true-awk or Windows Git-Bash. The two remaining failures are `term-uses` checks with a different, unexamined cause: "a doc already linking docs/terminology.md takes no term candidate" and "exactly the four expected candidates (got 5)". The same suite passes 245 of 245 under mawk 1.3.4-20200120, original-awk 2022-09-12 and gawk 5.2.1 on `debian:bookworm-slim`. `.claude/rules/asset-dialects.md` § Portable-awk subset names mawk and one-true-awk as the consumer awks and does not name busybox, so whether busybox is in the supported set is open. Beside it: the rule's named image `debian:bullseye-slim` can no longer install git (its debian-security pool returns 404), so the three-awk run used bookworm.
**Area:** `plugins/super-bootstrap/skills/commit/assets/doc-links.sh:894` and its `term-uses` lane; `.claude/rules/asset-dialects.md` § Portable-awk subset; `tests/doc-links.test.sh`
