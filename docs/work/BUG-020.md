# BUG-020 — commit-channel hook covers Bash path only; commits via other tools bypass the commit door and doc-sync

**Logged:** 2026-07-26 · **Source:** head/tail interface contract design work for super-bootstrap bracket (finding stands independent of that design)
**Problem:** The commit-channel `PreToolUse` matcher is `Bash(git commit *)` in both the shipped hook asset and the dogfood `.claude/settings.json`. Any commit that lands via another path — a bespoke commit skill, `gh`, an MCP git tool — bypasses the hook entirely, so doc-sync never sees the finished diff. The README presents the hook as the mechanism that confines raw `git commit` to the main-session commit door and routes worker subagents back to `/super-bootstrap:commit`, but only one path class is actually enforced.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.hook.json`; `.claude/settings.json` (dogfood hook wiring); root `README` (hook guarantee claim)
**Prior:** Widen the matcher to cover all commit-landing tool paths, or document the enforcement gap and narrow the README guarantee to match what is actually enforced.

## Verdict — surface · 2026-08-02

### Findings

- root cause: **partially confirmed — the card's two premises split.**

  **Confirmed (enforcement scope).** `commit-channel.hook.json` line 3 `"matcher": "Bash"` + line 7 `"if": "Bash(git commit *)"`, mirrored verbatim at `.claude/settings.json` lines 5–10. The `if` field is the primary filter (per the asset's own `_comment` and `commit-channel.sh` lines 3–5); the script's re-check (`_re` line 27) is defense-in-depth downstream of it. Two bypass classes follow:
  - **Same-tool, different verb** — `git revert` / `git cherry-pick` / `git am` / `git commit-tree` + `git update-ref` / `git stash` land commits through the Bash tool without the string `git commit`, so the `if` filter never fires. (`git merge` / `git tag` are already *deliberately* exempt — `commit-channel.sh` lines 11–13, and `merge/SKILL.md` line 86 runs `git merge {branch} --no-ff` as an orchestrator op.)
  - **Non-Bash tool** — a `mcp__*` git tool's name does not match the `Bash` matcher, so the hook never runs; and even with a widened matcher the script would still exit at line 18 (`cmd=$(… .tool_input.command)`; `[ -z "$cmd" ] && exit 0`) because an MCP tool's `tool_input` carries no `command` field. **"Widen the matcher" is therefore not a one-line change for this class** — it needs per-tool input parsing in a frozen asset plus an unknowable tool-name set. No `.mcp.json` exists in this repo today, but `resolve-plugins/SKILL.md` (lines 53, 255) curates MCP picks and can write one into a consumer repo, so the class is live downstream, not hypothetical.

  **Falsified (README overclaim + doc-sync framing).** Two sub-claims in the card's Problem do not survive direct read:
  - The root `README.md` line 57 reads "`commit-channel` (PreToolUse) confines raw `git commit` to the main-session commit door" — scoped verbatim to raw `git commit`, which is exactly the one path class enforced. `plugins/super-bootstrap/README.md` line 81 and `plugin.json` `description` say the same ("raw commits routed to the gateway-inline commit door"). No doc claims universal commit coverage, so **no README narrowing is owed** and Prior branch (b)'s doc half has no target.
  - "so doc-sync never sees the finished diff" assumes the hook is doc-sync's enforcement. It is not, by ratified design: the PreToolUse doc-sync gate (`docsync-gate` + `docsync-scan`) was **retired** (`hooks-ensure-infra.md` lines 32–34, commit `0bafb35`) when doc-sync moved gateway-inline into the commit door. The surviving hook gates on `agent_type` only (`commit-channel.sh` lines 30–33) — the **main session's own raw `git commit` passes with zero doc-sync**, identical exposure to any bypass path. The residual defect is *subagent routing*, not doc-sync coverage.

- scope reach: `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.hook.json` (`if` filter) · `assets/hooks/commit-channel.sh` + installed `.claude/hooks/commit-channel.sh` (frozen, version-markered — a change is a v4 bump propagating to every bootstrapped repo via copy-on-drift, `hooks-ensure-infra.md` §Idempotency) · `.claude/settings.json` (dogfood mirror) · `tests/commit-channel.test.sh` (existing unit harness, stdin-driven — covers any verb widening) · `harness-bootstrap/SKILL.md` line 230 ("Fires on" column). Docs: none owed.

- attempted: static trace of the hook pair + script, both copies; family sweep across commit-landing paths (Bash git verbs · `gh api` · MCP tools · drain worktree lane — `drain/assets/worktree-settings.local.json` already denies `merge`/`rebase`/`tag` to workers by permissions, and worktree workers run as separate processes so `agent_type` is absent and they pass the hook by design); `decisions.md` checked for a closed fork. Stopped at the fork below: closing the gap is a scope call the repo has a ratified bar for, not a mechanical defect.

### Decision needed

- **Does the commit-channel guard widen past `git commit`, and how far?** The repo's ratified bar for hook enforcement is empirical — "Build the hook only if ambient demonstrably fails" (`decisions.md` row 47), with two hooks already retired in favor of ambient `CLAUDE.md` prose after control runs (rows 26, 27). No incident of a subagent landing a commit via an alternate verb is on record. Against that: this guard already exists, so widening is a regex + `if`-field edit inside a live asset, not a new hook.

- Options:
  - **A — widen to the branch-landing verb family, Bash-tool only.** `if` becomes `Bash(git *)` (the script's own regex stays the decider); the script's `_re` extends to `revert` / `cherry-pick` / `am`; `merge` / `rebase` / `tag` stay exempt as orchestrator ops. Frozen-asset v4 bump + `tests/commit-channel.test.sh` rows. Leaves the MCP and `gh api` classes open.
  - **B — cover every commit-landing tool path** (A plus matcher entries for `mcp__*` git tools and per-tool `tool_input` parsing). Unbounded tool-name set, parsing logic inside a frozen self-contained asset, and no consumer instance to test against.
  - **C — accept the scope, no behavior change.** One comment line in the frozen script naming the enforced boundary (Bash `git commit` invocations only; alternate verbs and non-Bash tools ride ambient dispatch-prompt discipline). Docs stay as-is — the overclaim premise is falsified.

- recommendation: **A**, with C's comment line folded in. It closes the class that actually reaches a user's branch through an in-session subagent, costs one regex + one `if` string, and is covered by an existing unit suite — while B re-enters the unbounded-heuristic class `decisions.md` row 41 already closed ("heuristics re-enter the syntax-matching fragility class the v3 redesign exited"), and pure C leaves a same-tool, same-actor bypass open in a guard that is already paid for. If the empirical bar is held strictly (no observed failure → no widen), C alone is the consistent call — that is the judgment this fork asks for.
