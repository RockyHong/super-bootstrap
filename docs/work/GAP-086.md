# GAP-086 — The rot scan's clean is indistinguishable from its literal list coming back empty

**Logged:** 2026-09-22 · **Source:** observed live during a `/super-bootstrap:harness-bootstrap` sync on this repo (runway 2.51.1 → 2.52.0, commit `88ce1df`)
**Problem:** [`harness-bootstrap/SKILL.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md) § 2b tells the executor to "read `assets/rename-map.md` and grep every pipeline-owned file in scope for each entry's `old` literal", and names no check that the extraction actually yielded literals. An executor whose list-building command fails gets an empty list, loops zero times, and reports `rot rows: 0` — the exact output a genuine clean produces. § 2c's gate accepts it, because zero rot rows is the expected shape on a healthy repo, so nothing downstream can tell the two apart. Observed: a `grep -oE … | tr -d '\`- '` pipeline errored (`range-endpoints of '\`- ' are in reverse collating sequence order`), the literal variable was empty, and the scan printed a clean over 13 pipeline-owned files without testing a single literal. Re-run with a working extractor: 21 literals, still 0 hits — the verdict was right and the check was dead, which is precisely the pair that leaves no trace in the output. Caught only because that session had just finished measuring this failure class for `GAP-085`; a session without that priming records the false clean into the receipt.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/SKILL.md` § 2b (rot scan) — and § 2c only if the gate is where the liveness assertion should sit instead
**Test-feel:** manual · **Blast:** repo
**Prior:** The scan reports a row count without ever reporting the size of the set it swept. Candidate shape: state the literal count before the row count, and treat a zero-literal extraction as an instrument failure reported as *no scan* rather than as a clean — the same disposition a bench already gives a runner that cannot fire. Adjacent but non-covering: [`bench/rot-row-contract/`](../../bench/rot-row-contract/README.md) tests the row contract plus the § 2c gate and receipt write that *consume* rot rows, reading-only with no fixture repo, so it never exercises the extraction step that produces them.
