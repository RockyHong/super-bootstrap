# DEBT-057 — `/super-bootstrap:help` still has no way to tell the user a source came back empty

**Logged:** 2026-08-09 · **Source:** scoped out of BUG-033 by its triage verdict — the depth fix closed the observed harm, this is the residual class
**Problem:** BUG-033 fixed one silent-drop cause (a depth-1 walk missing nested layouts). The silence itself is untouched: when a source yields no rows for any other reason — a manifest declaring paths that no longer resolve, a layout neither branch anticipates, an install whose `skills/` tree is absent — the menu renders as if that source had nothing to offer, and the user cannot distinguish "this plugin ships no slash commands" from "discovery failed here". The only trace is the `(N skills)` token on the `# sources:` stderr line, which SKILL.md step 3 never renders.
**Area:** `plugins/super-bootstrap/skills/help/assets/render-menu.py` (the `# sources:` line and what reaches stderr); `plugins/super-bootstrap/skills/help/SKILL.md` step 3 (the rendering contract that would have to surface it)
**Prior:** Two obstacles the fix has to clear, both recorded in BUG-033's verdict before it was resolved. A bare zero is not an anomaly signal — `typescript-lsp-win` and `pyright-lsp` are enabled and truthfully ship no skills — and a naive declared-vs-emitted count mismatch also false-flags, since a manifest allowlist legitimately emits fewer rows than the tree holds (mattpocock: 25 of 35). So the work is a predicate first, a rendering change second. The rendering half touches obeyed prose in SKILL.md step 3, which `.claude/rules/skill-authoring.md` gates behind a RED.
