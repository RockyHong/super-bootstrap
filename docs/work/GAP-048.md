# GAP-048 — resolve-plugins has no coordination protocol for a foreign settings.json writer; collision avoided by hand

**Logged:** 2026-08-02 · **Source:** live `/super-bootstrap` run, tier-2 gate — CCM wired three hook bundles into `.claude/settings.json` (commit `e7ce8f1`), then `resolve-plugins` would have overwritten the same file ~30 min later; skipped by operator decision, not by any guard
**Problem:** Two independent managers claim write authority over `<project>/.claude/settings.json` with no designed coordination. `/super-bootstrap:resolve-plugins` (tier-2 step 1) reads and rewrites the file with stack-matched skill/MCP/hook pins. `/resolve-claude-config` (CCM bridge) writes `enabledPlugins` entries via `_plugin_apply.sh` and merges whole hook bundles into `hooks.{PreToolUse,PostToolUse,UserPromptSubmit,SessionStart}` via `_hook_apply.sh`. Neither knows about the other: `resolve-plugins` has no awareness of the hook bundles CCM wires; CCM has no awareness of the pin set `resolve-plugins` curates. Running in either order risks one clobbering the other's block in the same file. The collision recurs on every `/super-bootstrap` run in a repo that also uses the CCM bridge; the next operator has no signal it exists — the skip this session depended on someone noticing.
**Area:** `/super-bootstrap:resolve-plugins` skill (tier-2 step 1 of the super-bootstrap entry); `.claude/settings.json` write semantics; `/resolve-claude-config` (CCM bridge, external)
**Prior:** Three candidate shapes at pickup: (1) read-merge-write — scope `resolve-plugins` writes to only the keys it curates, leaving foreign blocks untouched; (2) detect-and-surface — detect a foreign manager's marker and surface rather than write; (3) rule out as CCM-specific (noting any external settings.json writer hits the same collision, so the general problem remains regardless).
