# BUG-036 — todo/classify: a surface Verdict stays "Decide" after a later Amendment rules it

**Logged:** 2026-08-20 · **Source:** GitHub issue [#45](https://github.com/RockyHong/super-bootstrap/issues/45) via `/pull-issue`
**Problem:** `/super-bootstrap:todo discuss` serves cards as "awaiting your decision" after the user has already ruled them. In one board, 2 of 9 Discuss rows were cards whose `## Verdict — surface` fork had been fully ruled by a later `## Amendment` (one carrying explicit closure conditions); the board re-asked the Verdict's original questions. Failure direction is one-way — over-reports pending decisions (ruled → shown as open), never under-reports — so it inflates the Discuss board silently. Cost: the board's premise is "no need to open the card to know what's owed"; once a Discuss row may be an echo of a ruled fork, every row must be verified by reading the full card. Verify with three cards, each carrying a `## Verdict — surface` block: (1) followed by an `## Amendment` that answers the Verdict's `### Decision needed` → must **not** render as Discuss; (2) followed by an unrelated `## Amendment` (e.g. stale line-pointer update) → must **still** render as Discuss; (3) no later block → must still render as Discuss. Current: all three render as Discuss — case 1 is the bug, case 2 is the guard against overcorrecting.
**Area:** `plugins/super-bootstrap/shared/classify-actionable.md` thread-state ladder (§ card thread rules, line 84 surface-Verdict rule; line 94 `User-blocker override`) · consumers: `plugins/super-bootstrap/skills/todo/assets/render-board.py`, `plugins/super-bootstrap/agents/todo.md`
**Prior:** The surface-Verdict rule keys on the latest block **of type Verdict** only, while its ladder neighbours (the `## Design` rules, lines 86/88) are forward-aware — they check what was appended after the block they match. Under the thread contract (`docs/work/README.md`) a user ruling lands as `## Amendment`, so the rule cannot see the resolution by construction; `User-blocker override` compounds it by naming a `surface` Verdict as "its most common form". Fix shape: make the rule forward-aware like the Design rules — but the predicate must be "a later block *answers* the Verdict's `### Decision needed`", **not** "any later block exists" (a naive rewrite flips over-report into under-report, the worse direction). Two candidate routes: (a) judge the later block's content against the open fork (costs judgment, matches how cards are written); (b) a mechanical ruling marker the ladder keys on, with every ruling-writing door updated to emit it (deterministic, but existing cards keep old behavior unless every door ships it). `docs/decisions.md` § Closed Forks (block-presence stage detection, satellites rejected) names "a stage misread ships a wrong board row" as its reopen condition — this is that case; the fix stays inside the single-file thread, not a satellite revival.

### Decision needed

- **Where does a user's ruling on a `surface` Verdict land, so the ladder can see it?**
  - **(a) Content-judgment predicate** — the rule reads "a later block *answers* this Verdict's `### Decision needed`". Matches how cards are written today, no contract change; but the script lane has no model, so its encoding can only approximate (nearest proxy: an Amendment post-dating the Verdict that quotes or names one of its options — and fixture case 2 is precisely what such a proxy misfires on).
  - **(b) Mechanical ruling marker** — a new `## Ruling — {date}` block type or a required line inside the Amendment, keyed deterministically by both lanes. Costs a thread-contract change plus a ruling-writing door everywhere a fork gets answered; existing cards keep old behavior until re-marked.
  - **(c) Route rulings to the existing `## Design` block** — the contract already scopes Design to a fork the user ruled, and the script already drops the Decide row for it (probed). Cost: one spec-side reconciliation (line 84 gains the `no Design or Plan after it` forward-check the script already applies) plus a door instruction naming Design as the ruling's home. Limit: a ruling that settles no aim ("drop this card", "ship the recommendation as-is") is a strained fit for a settled-aim section, so (c) owes a stated rule for that shape — Amendment plus a one-line Design, or resolve the card outright.
  - recommendation: **(c) plus the spec/script reconciliation.** Only route that buys the case-1 drop with no new predicate, no new block type, no migration — and the line-84 divergence must be closed under (a) and (b) anyway, so (c) is also their shared first step. Revisit (b) only if a real ruling turns up that Design cannot hold.
- **Does closing the ladder's missing fall-through row ride this card, or its own?**
  - fold into BUG-036 — same rule, same line; the fix cannot ship correct without naming the successor row, and the Amendment-only crash closes as a side effect.
  - split a new BUG — the crash reproduces today independent of any BUG-036 change (an Amendment-only card kills the whole board, exit 1), so it is separately shippable and arguably more urgent.
  - recommendation: **fold**, with the successor row named explicitly and the spec ladder made total (every reachable block-state maps to a row, with a stated default instead of a fall-through). The crash and the false Decide row are the same hole read from two sides.

## Design — 2026-08-20

Fork from the Verdict's `### Decision needed`, ruled by the user (gateway session, 2026-08-20). This block is itself the first ruling landed under the convention it settles.

- **Ruling home: route (c).** A user's ruling on a `## Verdict — surface` lands as a `## Design — {date}` block — the chosen option, settled, plus the approval line — and the ladder's existing Design rules take over from there (`Approve design` / `Start execute`). A ruling that settles no aim does not get a strained Design: **drop** → resolve the card (delete it; the commit message carries the why); **"ship the recommendation as-is"** → that recommendation *is* the settled aim → a one-line Design naming it. No new block type, no Amendment-as-ruling, no migration of existing cards.
- **Spec/script reconciliation.** `shared/classify-actionable.md` line 84 gains the forward-check the script already applies: `Latest Verdict is surface, no Design or Plan block after it`. Line 94 (`User-blocker override`) narrows its example to an *unruled* surface Verdict so the keyword arm cannot re-inflate a cleared row.
- **Fall-through folded in.** The ladder is made total: a card carrying blocks but no Verdict / Design / Plan (Amendment-only) takes the `Triage:` row (Cloud, raw) — the same state as origin-only, since nothing has grounded it yet. The script's first branch keys on that predicate instead of `not card.blocks`, which also closes the `plan is None` crash at the `else` branch.
- **Doors.** The triage skill's surface-absorb step names where the ruling lands (Design, or resolve); `docs/work/README.md` § Thread contract's Design line names the surface-Verdict ruling as one of its two entry shapes; `docs/agents/triage-labels.md` maps `ready-for-human` / `needs-info` to a surface Verdict *with no Design after it*.

**Approved:** (c) + fold — user ruling 2026-08-20.
