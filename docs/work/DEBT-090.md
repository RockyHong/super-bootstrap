# DEBT-090 — `hooks-ensure-infra` copy-on-drift downgrades a consult-check hook another manager owns and has extended

**Logged:** 2026-08-27 · **Source:** consumer sync report (v2.29.7 → v2.39.3 on an already-bootstrapped repo) — the installer declined the proposed re-copy and recorded the decline in the receipt
**Problem:** [`hooks-ensure-infra.md`](../../plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md) § Idempotency treats the plugin's frozen `consult-check-*.sh` pair as the SSOT and re-copies on any content drift. On a device where claude-config-manager planted its own consult-check pair first, the installed scripts scan three roots (`docs/**` plus the project's and the device's `.claude/guidelines/**`) while the frozen asset scans `docs/**` only — the installed copy is a functional superset owned elsewhere. Following the asset's "frozen asset here is the SSOT" line, copy-on-drift silently drops the two guidelines trees. [`docs/decisions.md`](../decisions.md) closed the fork as "super-bootstrap absorbs the CCM-planted hook, CCM retires its copy" — but the shipped asset has not absorbed the wider scan, so every device still mid-transition hits the downgrade on each sync.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks-ensure-infra.md` § Idempotency (copy-on-drift rule, SSOT line) · `assets/hooks/consult-check-*.sh` (scan roots) · `docs/decisions.md` (absorption row — verify the retire side actually happened)
**Prior:** Absorb first: widen the frozen asset to the three-root scan so the copy is a true superset; until then, copy-on-drift on a file whose installed copy is a superset owned by another manager should surface a `⚠ foreign-owned, wider` row and wait for approval instead of defaulting to overwrite.

**Blast:** cross-module
