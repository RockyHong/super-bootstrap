## Design — 2026-10-10

User ruling — **supersedes the Design block above** (that block was landed on a gateway pick before the user ruled; the user rejected it): **no third Verdict kind.** Verdict kind stays the binary attention signal — `auto-fix` = no one needed, `surface` = the user is needed — and a third kind would blur whose attention it calls for. "No verdict at all, gateway decides" is also out: it removes the kind that `needs-me` / `autorun` read, and moves more judgment onto the gateway, where this incident's drift happened.

The fix lives **inside `surface`**, which gains two need shapes:
- `### Decision needed` — a real fork: options + recommendation + `settles by:` (unchanged).
- `### Taste needed` (name provisional) — no fork; the acceptance test is the author's eye. Grounding only: what repo docs already rule (cited), where the card claim is factually wrong, a shared-trait observation (not a predicate to ratify), what a change drags with it. No options, no recommendation.

Gateway absorb (`skills/triage/SKILL.md` step 3): a `Taste needed` surface runs no climb-to-fork, no MCQ, no Design block — the gateway carries the grounding forward and produces the artifact the author judges (e.g. candidate replacement words), then hands it to the author. `SKILL.md:35`'s kind reading becomes "whether the user is needed", not "whether a fork is open". `needs-me` keeps reading an unruled `surface` as needing the user; `autorun` keeps reading it as grounded. Agent-side selector: the condition the agent already derives — no runnable check can judge; the test is the author's eye (`agents/triage.md` criterion 3 vs the `:41` "any failure → surface" contradiction resolves here).
