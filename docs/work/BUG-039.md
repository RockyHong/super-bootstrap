# BUG-039 — commit-channel `.if "Bash(git commit *)"` never spawns the hook for `git -C <dir> commit`

**Logged:** 2026-08-21 · **Source:** GitHub issue [#48](https://github.com/RockyHong/super-bootstrap/issues/48) via `/pull-issue`
**Problem:** `commit-channel.hook.json` pre-filters with `"if": "Bash(git commit *)"`. Claude Code evaluates `if` with permission-rule matching, where a sub-command-anchored pattern matches only when the sub-command is the first token after `git`. A worker subagent running `git -C <dir> commit -m …` — or any global-flag form (`git --no-pager commit`, `git -c user.name=x commit`) — does not match, so the hook process is never spawned and the commit goes through: a silent pass on the one gate the single-channel commit design relies on. The script is already robust — `commit-channel.sh`'s `_re` (`(^|[;&|])[[:blank:]]*git[[:blank:]]+([^[:space:]]+[[:blank:]]+)*commit(...)`) allows intervening tokens, and piping `{"tool_input":{"command":"git -C /tmp/x commit -m hi"},"agent_type":"general-purpose"}` into it returns `deny`. Only the `.if` pre-filter loses the call. Distinct from the closed fork "Widen the commit-channel hook past Bash `git commit`" ([`docs/decisions.md`](../decisions.md#closed-forks), was `BUG-020`): that fork covers other verbs / non-Bash paths; this is a `git commit` invocation the script covers but the pre-filter drops.
**Area:** `plugins/super-bootstrap/skills/harness-bootstrap/assets/hooks/commit-channel.hook.json` (`if` + `_comment`); `assets/hooks/commit-channel.sh` "Primary filter" header line; dogfood copy `.claude/hooks/commit-channel.sh`
**Prior:** Anchor the pre-filter on the bare command — `"if": "Bash(git *)"` — and let the script narrow (it already `exit 0`s on non-commit). Same shape force-push-style guards use. Verify: (a) with `agent_type` set in the stdin payload, `git -C "$PWD" commit -m x` → deny JSON; (b) main-session `git commit -m x` → passes; (c) `git -C "$PWD" status` → hook exits 0 silently.
