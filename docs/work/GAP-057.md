## Verdict — surface · 2026-08-10

### Findings

- coverage is **apparent, not real**. The four principles held against mattpocock's
  model-invocable set at v1.2.3 (`codebase-design`, `tdd`, `writing-for-agents`,
  `code-review` read in full):

  | Principle | Nearest surface | Coverage |
  |---|---|---|
  | 1 · think-before-coding | `tdd` "confirm the seams with the user"; `grilling` | none — his gate is scoped to one seam decision or a grilling session; nothing binds the general don't-assume-silently behavior while editing |
  | 2 · simplicity-first | `code-review` smell **Speculative Generality**; `tdd` "don't anticipate future tests or add speculative features"; `codebase-design` "one adapter means a hypothetical seam" | partial, and displaced in time — his hits land at review or inside the red loop; karpathy's binds at authoring |
  | 3 · surgical-changes | `tdd` "refactoring is not part of the loop" | near-zero — diff-scope discipline has no counterpart, and `code-review`'s smell list actively invites adjacent refactors (extract, move, split) |
  | 4 · goal-driven-execution | `tdd` red→green | real, and deeper than karpathy's — on the test-shaped half only; the plan-step → verify-check half, and every diff with no test surface, stay uncovered |

- trigger surfaces do not line up. Coverage needs content **and** firing moment.
  `karpathy-guidelines` fires on "writing, reviewing, or refactoring code" and is named by
  CLAUDE.md § Coding Principles, so it loads before any code work; every mattpocock
  candidate carries a narrow trigger (design a module's interface / build test-first /
  edit an agent doc / review since X). The partial content hits never fire at the
  authoring moment.
- `code-review` **consumes** a coding standard, it does not supply one — its step 3 reads
  `CODING_STANDARDS.md` / `CONTRIBUTING.md` and adds a fixed Fowler smell baseline. A
  bootstrapped repo ships `CODING_STANDARDS.md` headings-only, deferring to
  `karpathy-guidelines`. Retiring the pin hands his own Standards axis nothing but the
  baseline on every fresh repo — the pairing would weaken his skill, not absorb it.
- pin classes are asymmetric. karpathy is a **core pin** (locked); mattpocock is a
  **paired pin** (droppable). Retiring the locked one in favour of the droppable one makes
  the coding standard optional — a repo that drops him would carry no standard at all.
- `writing-for-agents` is not a candidate: its axis is document authoring for agents, not
  code. It bears on harness edits here, a different slot.

### Decision needed

- Does `andrej-karpathy-skills` retire from the §2a core pins?
- Options: **keep the pin** · retire it and let mattpocock's set carry the lane · retire it
  and author a repo-local standard into `CODING_STANDARDS.md` instead

## Amendment — 2026-08-10 · earn-right reframe, verdict recommendation superseded

### Owner steer — combination bar

Plugins compose chemically, not additively; a combo is 1+1<2 unless each part's shape and
result are pinned and its outcome quality plus cost efficiency measured. Unmeasured
stacking is the ceremonial trap the superpowers de-routing already cost this repo once.
Against that bar karpathy has shape (four principles) but **no measured result**, at
non-zero always-on cost. Trust upstream as shipped; do not hand-combine sources — so
transcribing the four principles into the `CODING_STANDARDS.md` skeleton is ruled out as a
fork, not offered as an option.

### What decides it

representative task canonical-only, observe) and already mandated for behavior-shaping

- probe reads **behavior-changing** → the slot is earned; the remaining question is narrower

Probe obstacle: this repo is markdown-only, so there is no in-repo coding task to measure

## Probe design — 2026-08-10 · built, unrun

Kit at `D:/Git/_probe-karpathy/` — outside this repo by necessity, throwaway once its
report lands here. Its `README.md` is the runbook, `JUDGE-BRIEF.md` the judge dispatch,
`RESULTS-TEMPLATE.md` the capture sheet.

**Output is reference, not verdict** (owner's framing). The kit produces a difference
report and its consumer impact; it issues no keep/retire recommendation and the judge brief
forbids one. Consistent with this repo's existing probe shape — the harness-edit audit
returns insights, never verdicts ([`decisions.md`](../decisions.md) row 25) — and with
`escalation-design.md` § surface evidence, not conclusions.

### Construction

Runs outside super-bootstrap because this repo's own `CLAUDE.md` § Coding Principles
instructs reading the skill, so no in-repo agent can serve as a no-guidance control. No
parent `CLAUDE.md` sits above `D:/Git/`.

`karpathy-skills` is `false` at device scope, so the arms differ by **one project-scope
pin** — the same difference a real consumer repo sees — with no toggling needed.
`mattpocock-skills` is `true` at device scope and therefore live in **both** arms, held
constant. The measured quantity is thus karpathy's *marginal* effect given the paired set,
which is exactly what this card asks.

### Tasks — one per uncovered principle family

| Task | Fixture defect | Discriminator |
|---|---|---|
| T1 | tax computed pre-discount, contradicting the docstring; planted adjacent smells (unused imports, dead function, commented-out block) | scope discipline, minimalism |

### Guards against a rigged read

- **Criteria are task-derived, never karpathy's four principles.** Scoring an overlay
  against its own instructions is the tautological antipattern mattpocock's `tdd` names —
  arm A would win by construction. T1's expected values are hand-worked in comments, an
  independent source of truth.
- **Judge is blind** — arm labels withheld, the skill text withheld, the probe's purpose
  withheld, run outputs shuffled and relabelled.
- **Within-arm variance is measured first.** 3 repeats per cell; a between-arm gap no
  larger than the within-arm spread is reported as noise. This replaces the earlier
  pre-registered decision rule, which produced a disposition and was therefore a verdict.
- **Clarifying questions get one fixed reply** (`Use your judgment.`) in both arms —
  asking is itself the T2 observation, so the response must not vary.

### Shape and cost

18 runs (3 tasks x 2 arms x 3 repeats) at **sonnet** — the tier this harness's § Dispatch
actually sends builds to. Judges at **opus**: bounded read, but gate-grade centrality
(`model-tiering.md` § Centrality amplifier). Rough order 200-300k output tokens.

Weakest joint, stated: a behavioral guardrail's value runs inverse to model capability, so
a single-tier read can produce a false no-op (high tier) or a false earn (low tier). An
optional opus spot-check on T1 (+6 runs) narrows this; not built in.

### Out of scope for this probe

Cross-generation stability, decay over long sessions, and pin-vs-inline — the last is moot
under the owner steer above, which rules transcription out as a fork.

### Runner — headless `claude -p`, one process per run

Not manual sessions, and not the bare Messages API: the treatment under test *is* a Claude
Code harness feature (CLAUDE.md discovery plus plugin/skill resolution), so a raw API call
carries none of it and would measure nothing. Headless is also the cleaner instrument, not
just the cheaper one — every run's ambient is identical by construction rather than by
operator discipline, nothing carries between runs, the tier is pinned per invocation, and
cost and turn count are recorded rather than transcribed. `run.sh` in the kit performs one
run; artifacts are the full event stream plus a baseline-to-final diff.

**Arm gates measured, not assumed** (headless probe under
`--setting-sources user,project,local`): arm-a resolves
`andrej-karpathy-skills:karpathy-guidelines` plus mattpocock's 11 model-invocable skills;
arm-b resolves none of the former and the same 11 of the latter, listed identically. So
project-scope `true` overrides device-scope `false`, and the paired set is genuinely held
constant.

**Silent-failure guard.** `karpathy-guidelines` loads through the permission-gated `Skill`
tool, and under `-p` a denial is quiet — an arm-a run whose overlay never fired is
indistinguishable from the null result this probe exists to detect
(`claude-shape/subprocess-tool-gates.md` names this failure shape). `run.sh` grants `Skill`
and prints a per-run hit count; arm-a runs at zero hits and arm-b runs above zero are void.

**T2's observable shifts** — headless has no operator to ask, so the reading is whether the
ambiguity is named in the output rather than whether a question was asked. This retires the
fixed-reply protocol the interactive version needed, and binds both arms equally.
