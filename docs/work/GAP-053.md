# GAP-053 — resolve-plugins: code-intelligence (LSP) plugins as a fourth curation category

**Logged:** 2026-08-06 · **Source:** GitHub issue #30 (https://github.com/RockyHong/super-bootstrap/issues/30)
**Problem:** `/super-bootstrap:resolve-plugins` curates skill / MCP / hook picks from the detected stack; code-intelligence (LSP) plugins are a natural fourth category it does not consider. With a language server attached, Claude gets semantic `findReferences`/`goToDefinition` (no grep false positives on symbol-wide edits) and per-edit diagnostics (broken import surfaces same turn, not at next build) — exactly the stack-matched capability class resolve-plugins pins. Two constraints ride the pick: (a) the language server **binary** is a separate install (npm / rustup / go / dotnet) — plugin pinned without binary → `LSP` tool returns no-server-configured, capability reads installed while doing nothing; proposal should state the binary install command alongside. (b) coverage is typed symbols only — string literals, comments, CSS selectors, config, markdown stay grep-and-verify; say so wherever the pick is presented.
**Area:** `plugins/super-bootstrap/skills/resolve-plugins/SKILL.md`
**Prior:** verify shape from issue — with plugin + binary, `LSP` `findReferences` returns locations; without binary it errors, and that error is itself the incomplete-setup check.
