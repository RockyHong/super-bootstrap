L001| # tilecache
L002|
L003| Python 3.12 CLI that pre-renders map tiles from a PostGIS database into an S3-compatible bucket, with resumable jobs.
L004| Welcome to tilecache! We're so glad you're here and can't wait to see what you build.
L005| This project was started on a rainy weekend and has grown a lot since then.
L006|
L007| ## Commands
L008|
L009| - `uv sync` — install; `uv.lock` is committed and authoritative.
L010| - `uv run pytest -q` — unit suite; `-m pg` adds the PostGIS tests (needs `docker compose up postgis`).
L011| - `uv run tilecache render --bbox <w,s,e,n> --zoom 0-14 --dry-run` — prints the tile count and ETA without rendering.
L012| - `uv run ruff check . && uv run mypy src` — both gate CI.
L013| - `uv run tilecache resume <job-id>` — restarts a job from its last checkpoint row.
L014| - Running commands is how you interact with the tool.
L015| - Feel free to explore the commands and have fun with them.
L016|
L017| ## Layout
L018|
L019| - `src/tilecache/cli.py` — Typer entry; argument parsing only.
L020| - `src/tilecache/render/` — Mapnik bindings; the only module allowed to import `mapnik`.
L021| - `src/tilecache/store/` — S3 writer; all uploads go through `store.put_tile()`.
L022| - `src/tilecache/jobs.py` — job table + checkpointing.
L023| - The layout is designed to be intuitive and easy to understand.
L024|
L025| ## Rules
L026|
L027| - Tile coordinates are XYZ (Google scheme) everywhere; TMS y-flip happens only in `store/tms.py` for the one legacy bucket.
L028| - Zoom levels above 16 are refused at the CLI; the style sheets are not tuned past 16 and render garbage.
L029| - Every render writes a checkpoint row every 500 tiles; a crash resumes from the last row, so a checkpoint must be committed before its tiles count as done.
L030| - Empty tiles (all-transparent) are not uploaded; `store.put_tile()` checks the 334-byte canonical empty PNG hash.
L031| - Styles live in `styles/*.xml`; a style change bumps `STYLE_VERSION` in `render/version.py` so the cache key changes.
L032| - The S3 key is `{style_version}/{z}/{x}/{y}.png`; never change the shape — the CDN routes on it.
L033| - Rules are important because they help keep everything consistent.
L034| - Please try your best to follow them whenever possible.
L035|
L036| ## Testing
L037|
L038| - Render tests compare against golden PNGs in `tests/golden/` with a per-pixel tolerance of 2; regenerate with `--update-golden` only after eyeballing the diff images in `tests/_diff/`.
L039| - PostGIS tests load `tests/data/sample.sql` (one city extract); never point tests at a real database.
L040| - S3 is `moto` in unit tests; the `-m s3live` marker hits MinIO from compose.
L041| - Tests help catch bugs before they reach users.
L042| - We believe that a well-tested codebase is a happy codebase.
L043|
L044| ## Gotchas
L045|
L046| - Mapnik is not fork-safe; the render pool uses `spawn`, never `fork` — `fork` segfaults at random on Linux.
L047| - PostGIS `ST_AsMVT` is not used; we render raster only — don't add vector output without a card.
L048| - `boto3` clients are not thread-safe across the pool; each worker builds its own in `store.client()`.
L049| - Web Mercator bbox inputs are EPSG:4326 degrees at the CLI and converted once in `cli.py`; internal code is EPSG:3857 metres.
L050| - The legacy bucket `tiles-v1` is TMS and read-only; writes to it raise by design.
L051| - Software can be tricky sometimes, and that's okay.
L052| - Don't worry if you run into problems — everyone does!

L073| - Config is `tilecache.toml` in the cwd, overridable per key by `TILECACHE_*` env vars; env wins.
