**Status: DONE_WITH_CONCERNS.** The verdict for BUG-001 is **auto-fix**, and the block is appended to `docs/work/BUG-001.md`. I found the cause by reading the code; I didn't run a repro or the tests.

**Cause:** in `tally/engine.py`, `run()` finishes the statements before it settles the last pending refund. Lines 89–90 call `_emit_period()` first and `_rollover(None)` second. Each refund waits one step in `_held` before it posts. A refund on the batch's last line is still waiting when the statements are finished and the list of open statements is cleared. It then posts onto a new statement that is never output, so it appears on no statement and the balance is too high by its amount.

That wrong post still marks the refund as applied in the refund ledger. So the ledger then treats `R-88120-b` as a repeat of `R-88120`, which explains the "skipped as replay" log line.

**Fix:** call `_rollover(None)` before `_emit_period()`, which is the order `_rollover`'s own docstring describes. Add a unit test with a refund as the last event. Tags: `mechanical`, `inline`, `Probe-deps: none`, `Test Strategy: unit`.

**Card's theory about the ledger key:** I set it aside as the cause.
