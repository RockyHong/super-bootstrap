**Root cause:** `StatementEngine.run()` (`tally/engine.py:89-90`) finishes the statements before it posts the last held refund:
- Every refund is held back one step and only posts when the next event arrives. Mid-batch that works, which is why the staging replay posted it correctly.
- The last refund in a batch has no next event, so it is supposed to post after the loop. Instead, `_emit_period()` runs first: it ships the statements and clears the open set.
- Only then does `_rollover(None)` post the refund, onto a new empty statement that never ships. It also records the refund in the persistent replay ledger.
- The fix is to swap those two calls. The `_rollover` docstring already says it should run first.
