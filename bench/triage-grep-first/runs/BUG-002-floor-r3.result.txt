**Where it comes from:** the dunning letter's `{amount}` field. At `tally/reports/dunning.py:45`, the call to `fmt_money` passes locale and currency in the wrong order: `(cents, account.locale, account.currency)`. The function expects `(cents, currency, locale)`.
- The currency slot receives `"en_GB"`, which has no symbol in `SYMBOLS`. So the formatter falls back to printing the code: `"en_GB "`.
- The locale slot receives `"GBP"`, which isn't a known locale, so the separators fall back to en_US.
- The result is exactly `en_GB 312.40`.

The line below it (`dunning.py:46`, the fee) has the right order. So a second-notice letter shows the broken amount next to a correct `£35.00`.

**The card's guess about the cause is wrong.** GBP is still in `SYMBOLS` (`money.py:16`), and an existing test checks for `£312.40` (`test_money.py:11`). I tested that guess against the code instead of relying on it.

**Checked for the same mistake elsewhere:** every other customer-facing call to `fmt_money` passes the arguments in the right order. That covers the portal API handlers, email notifications, and the CSV, JSON and PDF exports. The swap exists only at `dunning.py:45`. It breaks letters for every non-USD account, not just UK ones.
