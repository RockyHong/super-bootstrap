**Cause:** in `tally/engine.py:89-90`, `run()` calls `_emit_period()` before `_rollover(None)`, so it closes the period's statements before settling the last refund.
- Refunds wait one step in `_held` and only post when the next event arrives. A refund that is the last event gets posted after `_emit_period()` has already cleared the open statements. It lands on a new statement that is never returned, and the carried balance was already written without it.
- `_apply_refund` still records that refund in the replay ledger. So the re-sent `R-88120-b` is correctly skipped as a replay of a refund that never posted.
- Moving the refund earlier in the batch works because the next event posts it while the statements are still open.

**Fix:** swap the two calls. The `_rollover` docstring already says the trailing refund should be settled this way. Add a unit regression test for a refund that is the last event in a batch. Tags: `systematic` / `inline` / Probe-deps `none` / Test `unit`. No doc impact.
